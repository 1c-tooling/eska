# Адаптер метаданных для ядра BSL

Экспериментальная библиотека `eska-bsl-adapter` преобразует общую модель
метаданных ESKA в типы выбранного ядра BSL. Её зависимости закреплены отдельно;
основная библиотека проектов ESKA сохраняет независимость от ядра анализа.
Библиотека пока не публикуется и не входит в установленный комплект.

Первый преобразователь `common_module` принимает `ParsedObject` с загруженными
properties. UUID, имя, контекст выполнения, повторное использование результатов
и сведения заимствования переходят в `bsl_metadata::CommonModule` напрямую.
Отсутствующий флаг сохраняет отсутствие; `false` остаётся явным значением.
QName свойства проверяется по namespace и local name. Ошибки имеют координаты
в исходном XML/YAML. Недоступные свойства, неверные UUID, дубли и неизвестные
значения значимых флагов вызывают конкретную ошибку.

`defined_type` сохраняет UUID и составной тип, `attribute_type` преобразует
общее свойство `Type` для последующих адаптеров полей. Сохраняются альтернативы
`Type`/`TypeSet`, ссылки, определяемые и характеристические типы, параметры
строк/чисел/дат. Namespace и local name определяют schema/config QName;
платформенный каталог ядра узнаёт остальные типы по local name внутри namespaces
1С из диапазона `/data/`. Для namespace СКД отдельно узнаются `SettingsComposer`
и `Filter`. Префиксы не участвуют в сравнении. Неизвестные типы/поля и неверные явные
квалификаторы отклоняются. Пустой `Type` даёт предусмотренный ядром `Unknown`.
`AllowedLength` и `AllowedSign` проверяются на допустимые значения и дубли,
хотя модель ядра не хранит различие фиксированной/переменной длины и ограничения знака.
Обязательный `Type` объектов, полей регистров и определяемых типов читается одним helper.

[Проверки](../../docs/research/eska-format/defined-type-adapter-results.json)
включают точное равенство всех 50/508/531 определяемых типов C1/C2/C3 с нативным
reader, 12 unit и два файловых теста. Исправный parse YAML и готовность BSL-модели
являются разными состояниями: корректный YAML с неподдержанным типом не должен
становиться успешным входом анализа.

`register` преобразует четыре вида регистров, измерения, ресурсы и реквизиты.
Типы полей используют тот же `attribute_type`, реальные UUID сохраняются.
Стандартные поля берутся из закреплённого каталога платформы. Их nil UUID
обозначает неявное поле в модели ядра; он не назначается объектам исходника.
Неполный descriptor, неверные режимы и отсутствующие обязательные типы не
публикуются как готовая модель.

Локальный [`bsl-kernel`](../bsl-kernel/README.md) расширяет исходный enum
допустимыми `Quarter`/`Year`. Адаптер сохраняет периодичность, поле `Период` и
виртуальные таблицы срезов; подстановка `None` не используется. Пример
`project_registers` считает поддержанные и неподдержанные модели отдельно;
неполное покрытие имеет exit 2.

Конструирование модели не определяет доступность BSL-тела или полноту анализа
проекта. Эти сведения должен сохранять общий host. Заимствование в модели
проверяется для сохранения семантики ядра; профиль импорта расширений ESKA
по-прежнему не принят.

`constant_object` сохраняет отсутствующий/пустой/заполненный тип константы,
`enum_object` — реальные UUID, имена и порядок значений перечисления.
Они требуют полного descriptor без recoverable parse issues. Общие helpers
корня и ownership используются также общими модулями/регистрами.
[Приёмка](../../docs/research/eska-format/primitive-adapter.md) включает все
константы/перечисления C1/C2/C3, 23 unit и пять файловых тестов библиотеки.
Все поддержанные модели совпали с нативным reader; XML не материализуется.

`metadata_object` преобразует справочники, документы, встроенные обработки/отчёты,
бизнес-процессы, задачи, планы обмена, характеристик, счетов и расчёта.
Стандартные поля следуют каталогу платформы; типы, владельцы, регистры движений,
порядок и UUID табличных частей/их полей сохраняются. Ошибочные явные настройки
и неподдержанные типы имеют исходные координаты. Синоним табличной части берётся
из настоящего локализованного текста, поскольку reference ошибочно читает
XML-отступы; сравнение остальных полей выполнено отдельно.
[Приёмка](../../docs/research/eska-format/object-adapter.md): 30 unit/шесть файловых
тестов, 231/2289/2995 поддержанных моделей C1/C2/C3. Один `TypeSet` C1 явно
не поддержан. Предопределённые ресурсы, формы и BSL не входят в эту проекцию.

[Расширение проекции](../../docs/research/eska-format/analyzer-process-objects.md)
добавляет процессы, задачи и планы обмена в существующий `MetadataObject`.
Адресные реквизиты задач сохраняют типы; отличающийся исходный kind/UUID остаётся
в общем descriptor для навигации. Пример `project_objects` теперь сравнивает
семь видов: все 76 новых моделей C1/C2/C3 совпали с native reader. Контроль остальных
видов дал 232/2325/3034 готовых модели с прежним неподдержанным `cfg:AnyRef` C1.
32 unit и шесть файловых тестов прошли. Неявные стандартные поля не получают
выдуманных YAML UUID; некоторые их типы по-прежнему `Unknown`.

[Проекция трёх видов планов](../../docs/research/eska-format/analyzer-chart-objects.md)
добавляет стандартные поля и неявные строки планов счетов/расчёта. Признаки счёта
и субконто сохраняют свои уровни, физические UUID остаются в общем descriptor.
Три режима зависимости расчёта проверяются строго. `project_objects` сравнивает
десять видов; 39 из 40 новых моделей C1/C2/C3 готовы и совпали с native reader.
Один план характеристик C1 содержит неподдержанный `cfg:AnyRef`; вместе с прежним
справочником C1 таких моделей две. 36 unit и шесть файловых тестов прошли.

Исходный API закреплён на bsl-analyzer `9021ba0`, пакет `bsl-metadata` заменён
локальным расширением из `bsl-kernel`; библиотека моделей используется без
IDE/LSP/MCP runtime. Для проверок нужен Rust; автоматические файловые
сценарии используют `ESKA_TEST_ROOT` в соседнем playground.
