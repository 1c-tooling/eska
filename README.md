# eska

Текущий этап разработки и очередь задач: [development tracker](docs/roadmap/README.md).

## Создание проекта

```bash
eska new demo --type configuration --workflow trunk
eska new demo-extension --type extension --workflow github-flow --no-vcs
eska --lang en new demo-report --type report --workflow custom
```

`new` создаёт **новый** каталог с `eska.toml`, `src/` и пустым `src/.gitkeep`.
Это каркас для Designer XML, а не готовая XML-выгрузка 1С. Родительский каталог
должен существовать. Существующие файлы, каталоги (даже пустые) и символические
ссылки не изменяются; пути с `..` отклоняются. Относительный путь вычисляется от
текущего каталога или явно заданного `--project-dir`.

В интерактивном терминале `eska new demo` запрашивает недостающие `--type` и
`--workflow` в TUI-меню:

- `↑`/`↓` или `k`/`j` — переместить выделение, Enter — подтвердить;
- `1`–`4` — сразу выбрать соответствующую строку, без Enter;
- Home/End или `g`/`G` — первая/последняя строка;
- Esc, Ctrl+C или Ctrl+D — отменить создание без записи файлов.

Для стандартной русской раскладки в меню работают соответствия `j → о`,
`k → л`, `g → п`, `G → П` независимо от `--lang`. Это ограниченный запасной
вариант, а не определение физических клавиш: прочие раскладки автоматически
не распознаются. Соответствия действуют только для навигации, без Ctrl/Alt/Super,
и не меняют аргументы CLI или текстовые данные. Стрелки и Home/End остаются
альтернативой без буквенных привязок. Поддержка новых языков интерфейса не
требует добавлять раскладки.

Выбранная строка выделена маркером, полужирным текстом и одним цветовым акцентом.
Меню работает во временном экране терминала; после выбора или отмены возвращаются
предыдущий экран, курсор и обычный режим ввода. Непустая переменная `NO_COLOR`
отключает оформление, сохраняя маркер выбора. Минимальный размер окна — 50×14;
при уменьшении меню просит увеличить окно и не принимает подтверждение невидимых
строк. Вставка текста не выбирает пункты. Текстовый ввод идентификаторов заменён
на клавиатурное меню; идентификаторы по-прежнему принимаются через CLI-флаги.

TUI выводится только в stderr. При перенаправленном stdin или stderr оба
параметра обязательны; команда не зависает в ожидании ответа. Если оба флага
переданы, терминальный режим не включается даже в TTY.

Типы: `configuration`, `extension`, `processing`, `report`. Workflow:
`trunk`, `git-flow`, `github-flow`, `custom`. Выбор сохраняется в config:

```toml
[project]
type = "configuration"

[vcs.workflow]
preset = "trunk"
```

Секция `[vcs.workflow]` необязательна для ранее созданных проектов. Пока это
только выбор preset, без исполняемой policy, создания workflow-веток и проверок
их правил; `custom` также не запускает пользовательскую policy.

По умолчанию встроенная библиотека `gix` инициализирует Git с пустой веткой
`main`, без первого commit и remote. Системный Git не требуется; пользовательские
Git-настройки и перенаправляющие переменные окружения не применяются.
`--no-vcs` отключает инициализацию Git, но сохраняет выбранный workflow в config.

При обычной ошибке записи, Git init или проверки удаляется только вновь
созданный каталог. Если сам откат не удался, ошибка сообщает путь оставшихся
файлов. Аварийное завершение процесса и одновременное изменение каталога другой
программой не покрываются транзакционными гарантиями.

Коды `new`: `0` — каркас создан (сообщение и путь в stdout), `1` — ошибка
создания или отмена ввода, `2` — неверные/недостающие параметры. Ошибки идут в
stderr; сообщения и интерактивный выбор доступны на русском и английском.

## Подключение существующей выгрузки

```bash
eska init
eska init existing-project --workflow trunk
eska init existing-project --source sources/designer --workflow github-flow --no-vcs
```

`init [path]` подключает **существующую** Designer XML-выгрузку: создаёт только
`eska.toml` и, по умолчанию, отсутствующий Git-репозиторий. Путь по умолчанию —
текущий каталог; `--project-dir` задаёт базовый каталог так же, как для `new`.
Исходники не перемещаются и не изменяются; `.gitkeep` и другие шаблонные файлы
не добавляются. Уже существующий `eska.toml` (включая каталог или висячую ссылку
с таким именем) — ошибка, без перезаписи.

Команда ищет корневой XML-дескриптор непосредственно в корне проекта и в `src`,
без рекурсивного обхода. Распознаются `Configuration` (конфигурация или расширение
по свойствам расширения), `ExternalDataProcessor` и `ExternalReport` внутри
`MetaDataObject` с пространством имён Designer XML. Тип определяется по содержимому,
не по имени каталога; `--type` и отдельного меню типов у `init` нет.

Для другого расположения укажите `--source` — непустой относительный путь от
корня проекта, без `..`; `--source .` выбирает сам корень. Ссылки разрешаются,
но исходники и проверяемые XML-файлы должны оставаться внутри проекта.
Если выгрузки есть и в корне, и в `src`, команда просит выбрать каталог через
`--source`. Несколько корневых дескрипторов в одном каталоге отклоняются:
каждую выгрузку следует подключать отдельно.

Неизвестным остаётся workflow: в TTY выбирается в том же клавиатурном меню, что
и у `new`. Если stdin или stderr перенаправлен, обязателен `--workflow`.
При переданном флаге TUI не включается. `--no-vcs` отключает операции с Git,
но выбранный preset всё равно сохраняется; его policy пока не исполняется.

Существующий Git (в том числе через `.git`-файл или у родительского каталога)
не переинициализируется: config, HEAD, index, refs, remotes и пользовательские
файлы не переписываются. Повреждённые Git-метаданные и bare-репозиторий
отклоняются; `--no-vcs` позволяет подключить исходники без проверки Git.
Если репозитория нет, создаётся новый с пустой веткой `main`, без commit и remote.

До подтверждения меню запись не выполняется. После выбора исходники проверяются
повторно; config создаётся эксклюзивно. При обычной ошибке откатываются только
созданные этим запуском `eska.toml` и `.git`, **не каталог проекта**. Неудачный
откат сообщает оставшиеся пути. Принудительное завершение процесса и внешние
конкурентные изменения не покрываются транзакционными гарантиями.

Ограничения T06: проверяются XML-файлы верхнего уровня выбранных каталогов,
кроме `ConfigDumpInfo.xml`; повреждённый XML не пропускается. Поддерживается UTF-8
(включая BOM), без DTD и внешних entities; лимиты — 64 МиБ и 1 000 000 узлов на
файл. Это распознавание корневого дескриптора, а не полная проверка пригодности
выгрузки к загрузке в 1С. Пустой каркас `eska new` без XML не является выгрузкой
для `init`, а готовый проект уже имеет config и не нуждается в повторном `init`.

Коды `init`: `0` — подключено (сообщение и путь в stdout), `1` — ошибка или
отмена, `2` — неверный/недостающий workflow либо ошибка синтаксиса CLI. Help,
сообщения и TUI доступны на RU/EN; ошибки идут в stderr.

## Проверка проекта

`eska` ищет ближайший `eska.toml` вверх от текущего каталога и проверяет настройки
и каталог исходников. Другую начальную директорию можно передать явно:

```bash
eska --project-dir /path/to/project
eska --lang ru --project-dir /path/to/project/src/CommonModules
```

Минимальный `eska.toml`:

```toml
[project]
type = "configuration"
```

`type` обязателен: `configuration`, `extension`, `processing` или `report`.
По умолчанию `source = "src"`, `source_format = "designer-xml"`; другие форматы
пока не поддерживаются. Source — непустой относительный путь без `..`, допустимо
`.`. Неизвестные поля и секции, включая пользовательскую locale, отклоняются.

Корень проекта — каталог найденного config. Source должен существовать и быть
директорией внутри этого корня, в том числе после разрешения символических
ссылок. Начальный каталог и source приводятся к физическим абсолютным путям;
поиск через ссылку идёт по родителям её целевого каталога. Повреждённый или
недоступный ближайший config не пропускается ради родительского проекта.

Коды завершения: `0` — проект корректен (stdout/stderr пусты), `1` — ошибка
поиска, конфигурации или исходников (локализованный текст в stderr), `2` — ошибка
аргументов CLI. `--help` и `--version` не требуют проекта. Diagnostics ошибок
аргументов пока формирует `clap` на английском.

Запуск без подкоманды ничего не меняет и не проверяет XML-содержимое исходников.
VCS-команды и сборка пока не реализованы.

## Навигация по исходному коду

Обработчики команд находятся в `src/cli/commands/`: для изменения `init`
откройте `init.rs`, для `new` — `new.rs`. Операции без CLI находятся в
`src/project/`, конфигурация — в `src/config/`, Git и workflow presets —
в `src/vcs/`. TUI и локализация принадлежат `src/cli/`.

Подробная структура, границы модулей и карта «что изменить → какой файл открыть»:
[навигация по исходному коду](docs/architecture.md).

## Тестирование при разработке

```bash
cargo fmt --check
cargo check
cargo clippy --all-targets --all-features -- -D warnings
ESKA_TEST_ROOT=/home/kas/Projects/eska-playground cargo test
```

На этой машине все ручные запуски CLI выполняются только внутри
`/home/kas/Projects/eska-playground`, в отдельных demo-проектах. Автоматические
CLI-тесты с `ESKA_TEST_ROOT` создают там уникальные временные подкаталоги и
удаляют только их; существующие demo не изменяются. На других машинах и в CI
без этой переменной тесты используют системный временный каталог.
