# Границы модульных инструментов

Рабочая декомпозиция T90 от 2026-10-20. Базовый CLI: `5a65cb1`, Explorer:
`443134c`, оба в `codex/design-xml-analyzer`. Это инвентаризация перехода,
а не перечень уже поставляемых отдельных команд.

## Владельцы существующих операций

| Текущий вход `eska` | Владелец после выделения | Граница составной операции |
|---|---|---|
| Без команды | project | Структурная проверка выбранного проекта |
| `metadata` | project | Существующие операции XML и правила поддержки |
| `ide --stdio` | project `serve` | Metadata API, без LSP-прокси |
| `version` | project | Версия в XML, без Git и запуска платформы |
| `new`, `init` | project; общий CLI согласует VCS и выбор платформы | Самостоятельное создание манифеста не инициализирует Git |
| `new --from`, `import` | build распаковывает, project проверяет, общий CLI согласует VCS | Замена source сохраняет preflight, preview и восстановление |
| `build`, `clean`, `platform` | build | Runner, managed infobase, артефакты и их паспорт |
| `patch` | build с VCS-снимками | Нужны build и VCS; ошибка отсутствующего компонента до записи |
| `config init`, `config edit` | build | Текущий machine config содержит только настройки runner |
| `clone` | VCS | Репозиторий, затем проверка проектного манифеста |
| `status`, `diff`, `history` | VCS | Общая модель XML; без платформы и анализатора |
| `start`, `switch`, `save`, `finish` | VCS | Существующий workflow, preflight и preview |
| `shelve`, `unshelve`, `shelves` | VCS | Сохранение index/worktree и восстановление |
| `doctor` | Общий CLI собирает проверки project/build/VCS | Отсутствующий необязательный компонент отражается в отчёте |
| `update` | Установщик выбранного компонента | До T97 сохраняется текущий механизм обновления монолита |
| `--help`, `--version` | Выбранный исполняемый файл | Локальная идентификация и справка без запуска других движков |

Состав проверен по `src/cli/commands/mod.rs` и `src/cli/mod.rs`.
T96 должен сохранить документированные аргументы, human/JSON, streams,
exit codes и отмену; таблица не разрешает упрощать сохранность составных операций.

## Выделение ядра

Общие потребители — существующий CLI и самостоятельный `eska-project`.
Ядро включает файловые операции new/init, проектные настройки, discovery/selection, Designer XML, дерево,
поиск, поддержку, существующее редактирование и версию проекта.
Настройки build и workflow остаются данными; исполнители платформы и Git
остаются за пределами ядра. Presentation, локализация и `clap` туда не входят.

Общая реализация находится в `crates/eska-project-core`, текущий CLI использует
её через прежние Rust-пути. В normal dependency graph ядра
`gix`, `clap`, Tokio, HTTP-клиент, updater и BSL-ядро отсутствуют.
`bstr`, `gix-path` и `gix-validate` взяты в уже закреплённых версиях:
они сохраняют обратимые пути и существующую проверку Git-имён без repository
runtime. Для сохранения root-manifest при enrollment используется прежний `toml_edit`. `zip` и Unicode-классификатор удалены из прямых runtime-зависимостей
монолитного CLI; `zip` сохранён в его dev-dependencies для существующих
проверок картинок.

Общая локализация, пути и ошибки ядра находятся в `eska-presentation`,
metadata/version/Metadata API — в `eska-project`. Существующий CLI вызывает
ту же реализацию напрямую; платформенный выбор и Git-инициализация остались
в его адаптерах. [Самостоятельные команды](project-cli.md) не запускают
эти адаптеры.

T93 добавила самостоятельный [eska-check](check-cli.md), общий адаптер внешнего
процесса и строгую политику CI; project-сервер как процесс не требуется.
В T94 platform runner, build/clean, распаковка и обратимая замена source,
снимки артефактов и machine config перенесены в `eska-build-runtime`.
В normal dependency graph runtime нет `gix`, анализатора, IDE и `clap`.
Git provenance и проверку changed paths передаёт текущий VCS-владелец через
явную границу; отсутствие или ошибка инспектора не выдаются за чистый source.
Общий CLI сохраняет прежние Git preflight, подтверждения, JSON и восстановление.
Транзакция повторно вызывает тот же инспектор перед заменой. Промежуточные
проверки: workspace strict Clippy и 572 теста runtime/прежнего CLI passed,
6 ignored; ошибка callback отдельно проверена как отказ. Нативная матрица
и полный финальный workspace-набор выполняются со standalone CLI T94.

Standalone [eska-build](build-tool.md) и прежняя команда используют общие
CLI-обработчики build/clean/platform/config. Распаковка standalone публикует
только новый XML-каталог через общий writer с эксклюзивным созданием.
`eska-terminal` содержит переиспользуемый TTY-код двух CLI; project/check
не получают эту зависимость. Формат Configurator path находится в общей
presentation-библиотеке, VCS semantic presentation остаётся у своего владельца.

Экспериментальный Rust API теперь принимает `GitProvenance` при сборке
с паспортом и `SourceChanges` при создании import-плана. Ошибка инспектора
имеет структурную категорию `ChangeInspection`; публичный CLI сохраняет
`repository`. Это внутренние интерфейсы без compatibility layer.

Пока выделены внутренние crates с `publish = false`; раскладка публикуемых
packages и выборочная поставка относятся к T97. Автоматизация релизов,
workflow Actions и версия существующего пакета этим шагом не изменены.

Правила XML, снимки перед изменением и разрешения не копируются в новый
инструмент: оба потребителя используют одну библиотеку. Изменение границы
crate само по себе не меняет публичный CLI или Metadata API.

## Baseline

Стенд использует отдельную reflink-копию `buhmfo`, основную конфигурацию и пять
расширений в соседнем `eska-playground`. В одном модуле копии размещён
детерминированный probe для языковых запросов и несохранённых изменений;
оригинал сохранён отдельно. Рабочий проект пользователя не меняется.

Пара: release-сборка CLI, Explorer 0.0.12, внешний клиент
`ElishevKirill.bsl-analyzer-lsp` 0.1.12 и bsl-analyzer 0.3.2. Каждый запуск
использует отдельные `--user-data-dir` и `--extensions-dir` VSCodium.
Установка и сетевые проверки отключены. Холодная серия удаляет только
`.eska` внутри копии; файловый кеш ОС не сбрасывается. Повторная серия
переиспользует производные кеши. Каждый режим содержит пять запусков,
каждый запуск — 30 hover/completion/definition и 30 циклов изменения/исправления
несохранённого BSL с проверкой diagnostic events.

Предварительный порог сравнения T89: 10% либо измеренный разброс baseline,
если он больше. Временные assert в обычные тесты не добавляются. Полные
raw-значения и ограничения стенда фиксируются вместе с результатом серии.

Серия завершена до изменения приложения. [Полные значения и provenance](measurements/t90-baseline.json):
дерево cold/repeat — медиана 612/599 мс, готовность языковых запросов —
6,705/6,671 с. Эти интервалы начинаются внутри Extension Host test runner,
без времени загрузки редактора и установки компонентов. Совокупный peak RSS
всех дочерних процессов стенда — медиана 2451/2436 MiB; общие страницы
могут учитываться несколько раз, PSS не измерялся. XML refresh и смена
ветки/контекста этой серией не измерены.

Probe и launcher сохранены рядом с исходной копией. Повтор на этом стенде:

```sh
run_dir="$(realpath ../eska-playground/t90-baseline-gzndpr3p)"
python3 "$run_dir/run-baseline.py"
```

Команда использует сохранённый baseline-бинарник, явные локальные сервер
и расширение, отдельные профили и меняет только собственные каталоги стенда.

Исходные `cargo fmt --check`, `cargo check`, строгий Clippy и Rustdoc прошли.
Unit: 266 passed, 1 ignored. Sandbox запрещает HTTP listener трём тестам
обновления; вне sandbox эти три теста проходят. Ещё восемь integration-тестов
исходной версии при ограниченном файловом доступе видят смонтированный средой
пустой read-only `eska-playground/.git`; ожидания отсутствующего родительского
repository в этих тестах не выполняются. Эти первоначальные результаты
сохранены в baseline. Полный прогон после выделения ядра с полноценным доступом:
117 unit CLI, 149 unit ядра и 480 integration passed; 6 ignored, failures нет.
`cargo fmt --check`, workspace check, строгий workspace Clippy и workspace
Rustdoc прошли. Explorer baseline typecheck прошёл; Node вне sandbox:
125 passed, 13 skipped. После выделения ядра Node suite с явным настоящим
backend: 138 passed, skipped нет; Extension Host `properties-host.cjs` прошёл.
Общий `extension-host.cjs` не прошёл: `1 !== 2` на ожидании раскрытого узла
модулей в строке 121. Та же ошибка воспроизведена с сохранённым исходным
бинарником; она не объявлена исправленной или успешной проверкой T90.
