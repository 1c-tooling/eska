# T107 — Визуальный конструктор запросов

**Статус:** `IN-PROGRESS`. **Основание:** запрос пользователя от 2026-10-24
и выбор Конфигуратора как основного образца. Продолжает T104–T105; их
предыдущая приёмка сохраняется.

## Результат

Пять вкладок: «Таблицы и поля», «Связи», «Группировка», «Условия», «Порядок».
На первой вкладке доступны поиск и страницы таблиц базы данных, выбранные
источники с полями и результирующие поля. Таблицу можно добавить кнопкой,
поле — двойным щелчком; «Все поля» добавляет отсутствующие поля атомарно.
Формы позволяют задавать псевдонимы, тип соединения и его операнды,
агрегатные функции, сравнения и направление сортировки.

Каталог относится к приложению сессии запроса и его sources, включая
расширения. Список таблиц читается из inventory; поля разбираются из
descriptor выбранного объекта по запросу. Табличные части доступны как
дочерние таблицы. Неизвестная таблица и ошибка чтения metadata различаются.
Контекст приложения и ревизия конструктора проверяются на каждом запросе.

## Архитектура

ESKA формирует выражения на языке исходного запроса, назначает уникальные
псевдонимы и обновляет доказанные квалифицированные ссылки при переименовании.
Комментарии, строки и неподдерживаемые участки сохраняются. Изменения
проходят через прежний точечный план и атомарную проверку; отклонённое действие
не меняет черновик. Нативный Undo/Redo применяется адаптером IDE.

Metadata API 1.22 добавляет `query/constructorCatalog`, операции `compose`
и `appendFields` и структурированную проекцию элементов модели. Клиенты 1.21
сохраняют прежние возможности. В Explorer нет второго парсера, генератора
запросов или схемы метаданных; он отвечает за формы, выбор и вкладки.
[Контракт API](../ide-protocol.md), [пользовательский сценарий](../user-guide.md).

Конструктор заменяет представление родительского черновика. Принятие
возвращает тот же запрос с одним шагом Undo; отмена и закрытие возвращают
его без изменений. Модуль открывается после завершения отдельного
редактирования запроса согласно принятому модальному контракту.

## Референс «Консоль запросов 9000»

Пользовательская EPF распакована через `eska-build unpack` платформой
8.3.27.2325 в собственный каталог playground. Исходный файл не изменён;
SHA-256: `92250cd632bc4e2fc5b909d723ae71f91f570143516eb0054168b1164e04f011`.

Модуль формы, участок 3871–3955, создаёт `Новый КонструкторЗапроса` и вызывает
его `ОткрытьМодально` либо `Показать` с обработчиком завершения. Принятый текст
возвращается в тот же черновик с восстановлением комментариев. Отдельного
визуального конструктора для переноса в обработке нет. Исходники EPF
не копируются в ESKA или Explorer; референс подтверждает жизненный цикл.

## Границы

Это пять основных страниц, а не полная функциональная эквивалентность
платформенному конструктору. Параметры виртуальных таблиц и их полные схемы,
вложенные источники, `UNION`, `INTO`, `HAVING`, `TOTALS` и расширения языка СКД
остаются вне нового визуального набора. Их текст не переписывается.
Перестановка зависимых соединений по-прежнему ограничена общим core.
Полный набор стандартных и общих реквизитов требует дальнейшего расширения
каталога; неизвестная совместимость обрабатывается консервативно.

Семантическая диагностика использует доступный внешний анализатор;
выполнение запросов в информационной базе не добавлено. Анализатор не форкается
и не встраивается. Поддерживается Designer XML; другие форматы не добавляются.

## Приёмка

Проверяются core и RPC на обоих языках, полный набор Rust-проверок, Node/Bun,
содержимое VSIX и обычные установленные окна Linux/VSCodium в ru/en.
Нативный сценарий проходит пять страниц через реальные DOM-кнопки, выбор
таблиц/полей, «Все поля», отмену, применение, Undo/Redo и возврат к родителям.
Отдельно повторяются модальные сценарии и восстановление после перезапуска;
на копии buhmfo проверяется completion внешнего анализатора в черновике.
Windows, macOS, VS Code и Remote не проверяются.
