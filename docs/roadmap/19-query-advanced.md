# T108 — Виртуальные таблицы и составные запросы

**Статус:** `DONE` (2026-10-24, Linux/VSCodium ru/en). По запросу пользователя продолжает
[T107](18-query-constructor.md). Объём: виртуальные таблицы с позиционными
параметрами, вложенные запросы, `UNION`/`UNION ALL` и описание итогов.

ESKA отвечает за каталог, границы областей запроса, синтаксис, зависимости,
комментарии и точечные планы. IDE отображает модель и передаёт намерения.
Designer XML остаётся единственным форматом; внешний анализатор не форкается.

Логические части: общий каталог и параметры виртуальных таблиц; области
вложенных запросов; ветки объединений; поля/группы итогов; интерфейс и сквозная
приёмка установленного VSIX ru/en. Изменения публикуются отдельными логическими
commits. Неизвестный текст сохраняется, отклонённые операции атомарны.

Параметры и колонки сверяются со справкой установленной платформы 8.3.27.2325,
`shcntx_ru.hbk`, раздел `tables`. Доступность учитывает периодичность, вид
регистра и корреспонденцию. Бухгалтерские numbered subconto относятся только
к соответствующим виртуальным таблицам и ограничены назначенным планом счетов.

Реализован Metadata API 1.23: параметры виртуальных таблиц, выходные проекции
вложенных источников, ветки `UNION`/`UNION ALL`, общие итоги, иерархия и
заполнение периодов. Бухгалтерские поля учитывают корреспонденцию, назначенный
план счетов и балансность ресурсов. Регистры расчёта получают поля графика и
базовых регистров из связанных метаданных.

Explorer показывает семь вкладок. Вложенный запрос редактируется в той же
панели с явным возвратом к родителю. ESKA согласует колонки объединения,
сохраняет общий хвост порядка/итогов и возвращает корректную область после
удаления ветки. При неизвестном числе колонок `*` сохраняется; доказанное
несовпадение числа явных полей блокирует применение изменённого запроса.

Прошли полный набор Rust (1085 тестов, 12 ignored), строгий Clippy и Rustdoc,
Node/Bun (по 278 passed, 3 skipped) и 14 нативных прогонов с 16 результатами
окон. Проверены установленный VSIX ru/en, копия buhmfo с опубликованным
анализатором, Undo/Redo, модальность и восстановление. Тот же VSIX проверен
с предыдущим backend API 1.22. Ручной стенд обновлён с резервной копией компонентов,
без изменения его исходников и открытого окна.

Ограничения: `INTO`, `HAVING`, расширения языка СКД и несколько последовательных
секций итогов остаются непрозрачными. Вложенные области не получают общего
порядка/итогов. Связанные расчётные схемы проверены на metadata fixtures;
наследование связанных схем между workspace members отдельно не принято.
Программная внешняя правка может сохранить dirty-вкладку родителя в фоне;
интерактивный фокус возвращается дочернему редактору без потери буфера.
Запросы в ИБ не выполнялись. Windows, macOS, VS Code и Remote не проверены.
