# eska: 1C Explorer — границы и первая версия

Декомпозиция [T41](10-delivery-and-integrations.md) на T76–T81. Основа подключения
T76, дерево T77 и поиск T78 реализованы; остальные возможности T79–T81 запланированы.
Backend и поиск определены в [T60–T70, T75](13-metadata-and-ide.md); статусы и очередь — в [трекере](README.md).
T41 закрывается после приёмки T81, отдельной повторной реализации T41 нет.

По указанию пользователя от 2026-09-17 перед началом T76 сообщить о готовности
backend. Пользователь создаст отдельный репозиторий расширения и предоставит
его расположение. Пользователь предоставил репозиторий `eska-vscode-explorer`
2026-09-18;
реализация T76 начата в выбранной им ветке `feat/explorer`. Исходники
расширения в репозиторий CLI не добавляются.

## Название и назначение

По уточнению пользователя от 2026-09-18 расширения разделяются по назначению,
чтобы пользователь мог независимо выбирать дерево, инструменты проекта и
поддержку языка. Первое расширение отвечает за навигацию и работу с метаданными 1С.

| Уровень | Название |
| --- | --- |
| Репозиторий | `eska-vscode-explorer` |
| Отображаемое имя | `eska: 1C Explorer` |
| `package.json.name` | `eska-explorer` |
| Префикс команд, настроек, views и context keys | `eska.explorer.*` |

Имя publisher и полный Marketplace ID определяются перед публикацией;
репозиторий уже создан пользователем, публикации пока нет.
Общее имя `eska-vscode-extension` для этого компонента больше не используется.

Первая поставка ограничена T76–T81: дерево, поиск, фильтр, иконки и открытие
существующих XML/BSL. В перспективе сюда могут войти просмотр свойств и
редактирование метаданных через готовый backend API отдельными задачами.
T71–T74 этим решением не запускаются; создание/удаление/переименование по-прежнему
зависят от отложенной T74. Визуальный редактор форм в границы Explorer не входит.

Сборка/выгрузка 1С, поставка, запуск приложения, операции Git и блокировки
объектов относятся к отдельному будущему расширению команд eska. Его репозиторий,
название и задачи сейчас не создаются. Внутренние команды Explorer (поиск,
обновление дерева, фильтр, переход к исходнику) остаются частью Explorer.

## Независимость и совместимость

- Explorer использует `eska ide --stdio` и не требует установки другого расширения.
  Навигация работает без bsl-analyzer; пользователь самостоятельно выбирает
  языковую поддержку, форматирование и отладчик.
- Explorer не объявляет BSL/SDBL languages или grammars, debugger types,
  breakpoint contributions, language server, форматтер и диагностику BSL.
  Открытие модуля использует обычный текстовый редактор VS Code и уже выбранные
  пользователем средства языка.
- Команды, views, настройки и context keys используют `eska.explorer.*`;
  сочетания клавиш ограничиваются контекстом своего представления.
- Расширение не переписывает `launch.json`, настройки сторонних расширений,
  ассоциации BSL и форматтер по умолчанию; не устанавливает и не отключает
  bsl-analyzer либо другое расширение автоматически.
- Ошибки подключения к eska и чтения XML для дерева остаются ответственностью
  Explorer. Они не являются проверкой BSL и не дублируют диагностику языка.
- Проверка совместимости входит в T81: профиль только с Explorer и профиль
  Explorer + bsl-analyzer, с фиксацией версий. Во втором проверяются дерево,
  переход к модулю, подсказки/диагностика/форматирование и имеющаяся отладка
  bsl-analyzer. Добавление Explorer не должно менять их настройки или поведение.
  Совместимость с любыми будущими версиями заранее не считается доказанной.

## Минимальный пользовательский результат

- Дерево проекта повторяет структуру Конфигуратора. Группа модулей является
  первым элементом внутри владельца, перед реквизитами и другими коллекциями.
  Рабочее название — «Модули»; `.bin` без соответствующего BSL-файла скрыты.
- Поиск находит объекты независимо от раскрытия дерева и позволяет перейти
  к результату.
- У конфигурации есть кнопка скрытия пустых групп и настройка исходного режима.
  Например, при отсутствии констант группа «Константы» скрывается.
- Иконки соответствуют Конфигуратору либо максимально близки к нему.
- Выбор элементов и раскрытие работают без блокирования интерфейса; скорость
  проверяется на реальном большом стенде.
- Формат исходников — только Designer XML. `eska.toml` обязателен; тип
  `configuration`, `extension`, `report` или `processing` определяет схему дерева.
  Основная конфигурация и внешний отчёт/обработка не получают одинаковый корень.

Само расширение и metadata API не изменяют исходники. Открытие существующего
файла в обычном редакторе VS Code не является API редактирования метаданных.
Специальные редакторы, создание/удаление/переименование, BSL LSP и визуальный
дизайнер форм остаются за пределами этой поставки. Существующие контракты CLI/JSON
не меняются ради клиента. Git-операции, сборка 1С и публикация в Marketplace
в эти задачи не входят.

## Решения интерфейса

| Вопрос | Предложение | Где фиксируется |
|---|---|---|
| Имя и первое раскрытие группы модулей | Подтверждено: «Модули», раскрыта при первом открытии владельца; затем сохраняется выбор пользователя | T65, T77 |
| Допустимый модуль без файла | Подтверждено: показывать только существующие BSL-файлы | T77 |
| Охват поиска | Подтверждено: объекты и вложенные элементы, имя и синоним | T75 |
| Интерфейс поиска | Quick Pick с раскрытием и выделением результата в дереве | T78 |
| Действие выбора | Для модулей — BSL, для объектов/вложенных элементов — место в XML | T77 |
| Фильтр пустых групп | Подтверждено: только разделы корня, по умолчанию включён; переключение отдельно для проекта | T79 |
| ОС первой поставки | Windows, Linux, macOS; реальные проверки отмечать по каждой ОС | T76, T81 |

Строки с пометкой «Подтверждено» приняты пользователем 2026-09-17. Остальные
строки остаются предложениями; до зависимой реализации фиксируются варианты. Отдельно в T62/T65 уточняется версия
Конфигуратора для сравнения структуры; режим совместимости XML не определяет
точную версию интерфейса платформы. Исходники расширения находятся в соседнем
репозитории `eska-vscode-explorer`;
минимальный API VS Code в T76 — 1.109.0. Отдельным запросом от 2026-09-18
пользователь поручил настроить автоматические версии, changelog и GitHub Release.

## T76 — Основа расширения и подключение к eska

**Статус:** `DONE`
**Зависит от:** T70

Создать `eska: 1C Explorer` в репозитории `eska-vscode-explorer`: минимальный
клиент на TypeScript и стабильном VS Code API. На момент
реализации проверить актуальные поддерживаемые версии инструментов, выбрать
минимальную версию VS Code, зафиксировать зависимости и совместимость протокола.
UI работает через core `eska`, не содержит второго XML parser или каталога типов.

**Готово, когда:**

- manifest и регистрации соответствуют границам Explorer и префиксу
  `eska.explorer.*`; собственная поддержка BSL и отладчик не регистрируются;
- расширение активируется при обращении к своему представлению/командам,
  подключается к установленному `eska`; путь можно настроить, версия API
  проверяется до открытия проекта; автоматической установки executable нет;
- один backend обслуживает выбранные проекты текущего VS Code workspace;
  завершение, ошибка процесса и перезапуск не оставляют дочерние процессы;
- `eska.toml`, включая workspace members, загружается по существующим правилам;
  отсутствие manifest, неверный тип и несовместимый backend имеют RU/EN сообщения;
  предлагается инструкция `eska init`, но команда автоматически не запускается;
- место выполнения backend соответствует месту файлов проекта; выбранная
  поддержка Remote/виртуальных workspace и Workspace Trust явно объявлена;
  неподдержанный режим не маскируется локальным чтением похожего пути;
- лог процесса отделён от сообщений пользователю, protocol stdout не содержит
  human text; предусмотрены понятные состояния подключения и восстановления;
- тесты проверяют handshake, отсутствие/несовместимость бинарника, несколько
  проектов, неправильный manifest, завершение и перезапуск процесса.

**Результат (2026-09-18):** в `eska-vscode-explorer`, ветка `feat/explorer`,
реализованы нативное представление подключения, команды выбора папки/перезапуска/
отключения/журнала и настройка executable. TypeScript 7.0.2, API VS Code 1.109.0,
Bun 1.4.2 закреплены; нет runtime npm-зависимостей. Клиент использует существующий
IDE API 1.0, проверяет handshake до открытия workspace и не разбирает XML.
Один child обслуживает выбранный discovery context и его workspace members;
при переключении старый процесс завершается, запоздалые ответы отбрасываются.
Реализованы bounded framing/очереди, таймауты, сообщения RU/EN и диагностика CLI
без команды `ide`. BSL language/debugger contributions отсутствуют.

Remote использует workspace extension host и установленный там eska;
виртуальные и недоверенные workspace отключены. Проверки на Linux: 17 Node tests,
включая интеграционный с реальным backend (четыре типа, два workspace member, повреждённый/отсутствующий
manifest, несовместимый API, завершение и перезапуск), Bun process tests и strict
TypeScript. Smoke-test в VSCodium 1.109.5 (Node 22.21.1) подтвердил активацию,
один backend, перезапуск и отключение. Windows/macOS/Remote и совместимость
с bsl-analyzer остаются T81.
Сборка 1С и большой конфигурации не запускалась.

Отдельно по запросу пользователя добавлены CI и GitHub Release через Knope 0.23.0
(Rust) и Bun: release PR с версией/changelog, тег и Release после его слияния.
Проверены генерация версии/changelog, workflow и отсутствие пустого релиза;
фактическая публикация до push/слияния не запускалась. Сейчас релиз содержит
исходники; VSIX ожидает выбора publisher и упаковки. GitHub Actions должен иметь
разрешение создавать PR. В workflow нет setup-node/npm; стандартный checkout
использует свой Node runtime. Pipeline CLI `eska` не менялся.

Основание: [Extension Host](https://code.visualstudio.com/api/advanced-topics/extension-host),
[Remote Development](https://code.visualstudio.com/api/advanced-topics/remote-extensions),
[Workspace Trust](https://code.visualstudio.com/api/extension-guides/workspace-trust).

## T77 — Дерево проектов, модули и открытие исходников

**Статус:** `DONE`
**Зависит от:** T65, T70, T76

Показать нативный Tree View по узлам backend. Название «Модули», первое
раскрытие группы и показ только существующих BSL подтверждены. Действие выбора
объекта уточняется по таблице выше.
Группа модулей следует схеме каждого владельца, а не проверкам имён каталогов
в клиенте. Набор и расположение прочих групп соответствуют Конфигуратору.

**Готово, когда:**

- configuration/extension/report/processing имеют проверенные отдельные схемы;
  поддержаны реквизиты, табличные части, измерения, ресурсы, формы, команды,
  макеты и другие узлы матрицы T60;
- группа модулей первая; существующие BSL открываются из дерева напрямую;
  `.bin` без BSL скрыты, но владеющий объект не пропадает; чтение текста BSL
  происходит при открытии редактором, а не для построения дерева;
- открытие XML/BSL и положения inline-элемента использует source mapping;
  отсутствующий файл не создаётся и не подменяется другим кандидатом;
- дочерние элементы загружаются по раскрытию, stable IDs сохраняют выделение
  и раскрытие при обновлении; изменение одной ветки не сбрасывает всё дерево;
- работают клавиатура, масштабирование, светлая/тёмная/контрастная темы,
  доступные подписи и локализация; выбор показанного элемента не вызывает
  полного чтения конфигурации;
- доступны ручное обновление и локальная ошибка повреждённой ветки;
  исправление файла возвращает её в рабочее состояние;
- интеграционные тесты VS Code проверяют раскрытие и открытие файла/позиции,
  сохранение выделения, скрытие бинарных модулей и внешние изменения.

**Результат 2026-09-18:** в `eska-vscode-explorer` добавлены нативный Tree View,
ленивая загрузка детей, первая раскрытая группа «Модули», открытие существующих
BSL и XML/inline-элементов. Схема, порядок и подписи приходят из backend;
в клиенте нет XML-парсера или второго каталога типов. Диапазон свойства `Name`
из `metadata/properties` переводится из UTF-8 байтов в UTF-16 позиции редактора
с учётом BOM/CRLF; несохранённые или изменившиеся исходники не получают устаревшую
позицию. Пути проверяются на существование, представимость и границы проекта.

Стабильные TreeItem IDs и адресное обновление сохраняют выделение и раскрытие.
Пакеты файловых событий ограничены 4096 путями, устаревшие поколения/события
не заменяют дерево. Пропуск событий и переполнение требуют обновления корня;
изменение manifest переподключает контекст. Повреждённая ветка имеет локальную
ошибку и восстанавливается после исправления. Ошибка корня не вызывает цикл
повторных запросов. Имеются общее и адресное ручное обновление, RU/EN и ThemeIcon.

**Проверено:** TypeScript, Node/Bun; реальные stdio-запросы для четырёх схем,
модулей, inline-позиций и независимой инвалидации. Автоматический тест
Extension Host VSCodium 1.109.5 на Linux проверяет reveal, открытие XML/BSL,
сворачивание с клавиатуры, сохранение выделения и раскрытия при внешних изменениях,
ошибку/исправление ветки и корня, переподключение по manifest, встроенные темы
и масштаб. Это не заменяет визуальную и платформенную матрицу T81.
Windows/macOS/Remote не проверены; поиск, управление фильтром, набор иконок и
VSIX остаются T78–T81. Сборка/выгрузка 1С не запускалась.

**Уточнения после пользовательской проверки 2026-09-18:** специальный ThemeIcon
`folder` заменён на обычный значок группы: в Seti он заставлял нативный Tree View
сдвигать листовые значки на место стрелки. Координаты проверены в настоящем
Extension Host для светлой, тёмной и контрастной тем с Seti и без файловых иконок:
дочерний значок теперь правее родительского. Глобальные настройки отступов IDE
не меняются. Это исправление геометрии, а не реализация набора T80.

В пользовательском журнале зафиксированы `watch_error code=timeout` и последующий
SIGTERM от клиента; причина долгого ожидания пока не установлена. Расширена
диагностика клиента: PID/версия, контекст и ID запроса, метод, очередь, длительность,
причина протокольной ошибки, код/сигнал выхода и инициатор остановки. Последние
16 КБ stderr сохраняются после исчерпания лимита первых 16 КБ. Используется
LogOutputChannel с уровнями; успешное отключение не считается аварией.
Содержимое XML/BSL и полные тела RPC не включаются в структурированные события;
stderr сохраняется как ограниченный текст backend. Тайм-ауты не увеличены.

Для групп и ролей модулей добавлена настройка `eska.explorer.treeLanguage`:
«Авто / Русский / English». «Авто» следует языку IDE, изменение применяется
сразу к готовым переводам backend без переподключения или сброса кеша, выделения
и раскрытия. Имена объектов не переводятся; остальные надписи остаются на языке IDE.

Проверки этих доработок: typecheck/compile, 27 Node-тестов с настоящим backend,
25 Bun-тестов (две backend-проверки выполнены отдельно под Node), полный сценарий
Extension Host VSCodium 1.109.5, включая переключение всех трёх значений языка.
Нативный тест явно возвращает фокус дереву после открытия редактора перед
клавиатурным сворачиванием. Сборка и выгрузка большой конфигурации не запускались.

Основание: [Tree View API](https://code.visualstudio.com/api/extension-guides/tree-view),
[Views UX](https://code.visualstudio.com/api/ux-guidelines/views).

## T78 — Поиск в расширении и переход к результату

**Статус:** `DONE`
**Зависит от:** T75, T77

Кнопка и команда поиска используют API T75 и стандартный Quick Pick:
ввод текста, частичная выдача с прогрессом индексации, Enter для перехода в дерево.
Индекс запускается при первом открытии поиска; клиент не сканирует XML.

**Готово, когда:** запрос находит элементы принятого охвата даже в нераскрытых
ветках, показывает имя, вид и путь владельца, различает проекты. Выбор результата
раскрывает нужную ancestry и выделяет узел без обхода всех веток клиентом.
Устаревшие запросы отменяются, их ответы не заменяют новую выдачу. Видны
индексация, неполная/ограниченная выдача, ошибка и отсутствие совпадений.
Ввод не блокирует дерево, полная коллекция результатов не пересылается на
каждый символ. Проверены клавиатура, кириллица, одинаковые имена, переход к
вложенному элементу и удаление объекта между поиском и выбором.

**Результат 2026-09-18:** добавлена команда `eska.explorer.search` и кнопка с лупой.
Объекты и вложенные элементы ищутся по имени и синонимам всех языков; в выдаче
видны локализованный вид, проект и непрозрачный путь владельца из backend. Модули и
виртуальные группы не входят в поиск. Сопоставление остаётся в eska; Quick Pick
может дополнительно сортировать видимые строки нативным механизмом IDE.

По результатам проверки пользователя подписи всех 67 типов в поиске переведены
на RU/EN и следуют `eska.explorer.treeLanguage`, включая «Авто». Например,
`common-module` отображается как «Общий модуль», `scheduled-job` — как
«Регламентное задание». Смена языка обновляет открытую выдачу из кеша; wire IDs,
ранжирование и индекс остаются прежними. Это словарь представления клиента,
не дублирование схемы дерева или парсера; неизвестный будущий тип сохраняет свой ключ.

Клиент объединяет ввод с задержкой 250 мс и события индекса с задержкой 500 мс,
запрашивает до 50 hits на проект, сообщает об усечении, неполном индексе, ошибках
и отсутствии совпадений только после готовности индекса. Один последовательный
цикл не накапливает запросы при быстром вводе. Отмена через `$/cancelRequest`
сохраняет transport slot до ответа, поэтому поздний ответ не ломает подключение;
ревизия ввода не допускает публикацию старой выдачи. Escape отменяет чтение,
а уже начатый индекс достраивается в фоне. Повторное открытие использует индекс.

Выбор заново вызывает `metadata/reveal`, проверяет поколение и загружает только
возвращённую ancestry. Нераскрытые соседние descriptors остаются ленивыми.
Проверены переименование между поиском и выбором, одинаковые имена/ID в разных
проектах, четыре схемы, синонимы, ограничение и неполный индекс. Прошли 33 Node
теста (с реальным backend), 29 Bun-тестов (четыре backend-теста выполнены под
Node; штатная `test:integration` под Bun также прошла все 10 проверок),
typecheck/compile и Extension Host VSCodium 1.109.5 с Enter/Escape,
раскрытием результата, отсутствием совпадений и отключением при открытом поиске.

На `../eska-playground/big_configuration_temp` один запуск клиента Node с дисковым
кешем дал: подключение 654 мс, первые hits через 1326 мс, готовность индекса из
131381 элементов через 28122 мс, ошибок 0. Первые два поисковых времени включают
подключение; это наблюдение одного запуска, не сравнение cold/warm и не SLA.
Проверка/reveal выбранного результата заняла 68 мс без отрисовки IDE. Сборка и
выгрузка 1С не запускались. Windows/macOS/Remote остаются проверками T81.

Основание: [Quick Picks](https://code.visualstudio.com/api/ux-guidelines/quick-picks).

## T79 — Фильтр пустых групп и настройка исходного режима

**Статус:** `NEXT`
**Зависит от:** T65–T67, T77

Добавить у конфигурации переключатель «Скрывать пустые группы» и настройку
исходного режима. Подтверждено: фильтр действует только на разделы корня
и включён по умолчанию. Вложенные группы объектов не фильтруются. Уточнить
сохранение переключения между сеансами и
приоритет user/workspace settings; несколько проектов не должны неявно менять
режим друг друга. Поведение внешних отчётов/обработок описать явно.

**Готово, когда:** скрываются только доказанно пустые группы; незагруженная
или ошибочная ветка не исчезает. «Общие» остаётся, если заполнена хотя бы одна
вложенная группа. Пустая корневая группа модулей определяется с учётом скрытых `.bin`.
Переключение не перестраивает поисковый индекс и не запускает полный parse;
обновление состава объекта корректирует видимость группы. Раскрытие сохраняется,
поведение выделения скрытого узла определено. Поиск непустого объекта не теряет
путь к нему из-за фильтра. Проверены отсутствие констант, пустые вложенные
коллекции (сохраняются видимыми), добавление/удаление последнего элемента
корневого раздела на маленьких fixtures,
несколько проектов и сохранение выбранного режима.

## T80 — Иконки метаданных

**Статус:** `PLANNED`
**Зависит от:** T65, T77

Выбрать набор иконок Конфигуратора либо максимально похожий комплект.
Предпочтение пользователя от 2026-09-18 — похожие значки в стиле Material Icon.
Первый кандидат — [Material Icon Theme](https://github.com/material-extensions/vscode-material-icon-theme)
(MIT); конкретное соответствие видам метаданных ещё не выбрано. Нужные SVG
включаются в пакет Explorer без зависимости от установленной файловой темы.
До включения файлов установить источник и условия использования. Сделать
небольшой визуальный образец для согласования, затем покрыть все типы T60,
виртуальные группы и роли модулей. Наличие произвольного пакета не означает,
что он покрывает метаданные 1С.

**Готово, когда:** есть таблица machine kind → icon, fallback неизвестного типа,
недостающие значки выполнены в согласованном стиле. Проверены светлая, тёмная
и контрастная темы, масштабирование и узнаваемость. SVG/другие ресурсы входят
в VSIX; показ дерева не скачивает изображения. Служебные кнопки используют
привычные обозначения VS Code, иконки не заменяют доступные текстовые подписи.

## T81 — Производительность интерфейса, приёмка и VSIX

**Статус:** `PLANNED`
**Зависит от:** T68, T76–T80

Собрать устанавливаемый VSIX и проверить полный сценарий на поддержанных ОС.
Публикация в Marketplace и изменение GitHub Actions/release pipeline требуют
отдельной задачи. Упаковка расширения не является сборкой конфигурации 1С.

**Готово, когда:**

- проверена независимая работа Explorer и совместимость с bsl-analyzer
  по условиям выше; версии и результаты записаны, чужие настройки сохранены;
- VSIX устанавливается в чистый тестовый профиль VS Code; инструкция объясняет
  установку совместимого `eska`, обязательный manifest и открытие проекта;
- весь сценарий «открыть → раскрыть → найти → перейти к исходнику → сменить
  фильтр → обновить → закрыть» проверен; не возникает фоновых процессов после
  закрытия и накопления памяти при повторных циклах;
- на `big_configuration_temp` измерены cold/warm latency, p95 и peak RSS,
  включая Extension Host: корень, 3 808 общих модулей, 636 макетов одного отчёта,
  поиск, выбор элемента и переключение фильтра. Бюджеты T68 проверены end-to-end;
  начальная индексация измерена отдельно от поиска по готовому индексу;
- XML/BSL большого стенда остаются неизменными; модификации для проверки
  обновлений делаются только в собственных маленьких fixtures;
- **сборка `big_configuration_temp` не запускается**, `ibcmd`/Конфигуратор
  не вызываются, версия платформы для просмотра не требуется;
- выполнены релевантные Rust-проверки по working agreement и проверки
  TypeScript/расширения, unit- и интеграционные тесты VS Code;
- фактическая проверка Windows/Linux/macOS записана отдельно: недоступная ОС
  обозначена как непроверенная, а не как успешно пройденная. Объявленный набор
  поддерживаемых ОС требует завершённой приёмки перед статусом `DONE`;
- ограничения и результаты замеров опубликованы в документации, T41 закрывается
  вместе с T81; T71–T74 автоматически не начинаются.

Основание: [упаковка VSIX](https://code.visualstudio.com/api/working-with-extensions/publishing-extension).
