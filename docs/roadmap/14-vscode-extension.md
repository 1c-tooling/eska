# Первая версия расширения VS Code

Декомпозиция [T41](10-delivery-and-integrations.md) на T76–T81. Это план будущей
реализации, а не описание уже доступного расширения. Backend и поиск определены
в [T60–T70, T75](13-metadata-and-ide.md); статусы и очередь — в [трекере](README.md).
T41 закрывается после приёмки T81, отдельной повторной реализации T41 нет.

## Минимальный пользовательский результат

- Дерево проекта повторяет структуру Конфигуратора. Группа модулей является
  первым элементом внутри владельца, перед реквизитами и другими коллекциями.
  Рабочее название — «Модули»; `.bin` без соответствующего BSL-файла скрыты.
- Поиск находит объекты независимо от раскрытия дерева и позволяет перейти
  к результату.
- У конфигурации есть кнопка скрытия пустых групп и настройка исходного режима.
  Например, при отсутствии констант группа «Константы» скрывается.
- Иконки соответствуют Конфигуратору либо максимально близки к нему.
- Выбор элементов и раскрытие работают без блокирования интерфейса; скорость
  проверяется на реальном большом стенде.
- Формат исходников — только Designer XML. `eska.toml` обязателен; тип
  `configuration`, `extension`, `report` или `processing` определяет схему дерева.
  Основная конфигурация и внешний отчёт/обработка не получают одинаковый корень.

Само расширение и metadata API не изменяют исходники. Открытие существующего
файла в обычном редакторе VS Code не является API редактирования метаданных.
Специальные редакторы, создание/удаление/переименование, BSL LSP и визуальный
дизайнер форм остаются за пределами этой поставки. Существующие контракты CLI/JSON
не меняются ради клиента. Git-операции, сборка 1С и публикация в Marketplace
в эти задачи не входят.

## Решения интерфейса

| Вопрос | Предложение | Где фиксируется |
|---|---|---|
| Имя и первое раскрытие группы модулей | Подтверждено: «Модули», раскрыта при первом открытии владельца; затем сохраняется выбор пользователя | T65, T77 |
| Допустимый модуль без файла | Подтверждено: показывать только существующие BSL-файлы | T77 |
| Охват поиска | Подтверждено: объекты и вложенные элементы, имя и синоним | T75 |
| Интерфейс поиска | Quick Pick с раскрытием и выделением результата в дереве | T78 |
| Действие выбора | Для модулей — BSL, для объектов/вложенных элементов — место в XML | T77 |
| Фильтр пустых групп | Подтверждено: только разделы корня, по умолчанию включён; переключение отдельно для проекта | T79 |
| ОС первой поставки | Windows, Linux, macOS; реальные проверки отмечать по каждой ОС | T76, T81 |

Строки с пометкой «Подтверждено» приняты пользователем 2026-09-17. Остальные
строки остаются предложениями; до зависимой реализации фиксируются варианты. Отдельно в T62/T65 уточняется версия
Конфигуратора для сравнения структуры; режим совместимости XML не определяет
точную версию интерфейса платформы. Место исходников расширения и минимальная
стабильная версия VS Code выбираются в T76 без изменения publication pipeline.

## T76 — Основа расширения и подключение к eska

**Статус:** `PLANNED`
**Зависит от:** T70

Создать минимальный клиент на TypeScript и стабильном VS Code API. На момент
реализации проверить актуальные поддерживаемые версии инструментов, выбрать
минимальную версию VS Code, зафиксировать зависимости и совместимость протокола.
UI работает через core `eska`, не содержит второго XML parser или каталога типов.

**Готово, когда:**

- расширение активируется при обращении к своему представлению/командам,
  подключается к установленному `eska`; путь можно настроить, версия API
  проверяется до открытия проекта; автоматической установки executable нет;
- один backend обслуживает выбранные проекты текущего VS Code workspace;
  завершение, ошибка процесса и перезапуск не оставляют дочерние процессы;
- `eska.toml`, включая workspace members, загружается по существующим правилам;
  отсутствие manifest, неверный тип и несовместимый backend имеют RU/EN сообщения;
  предлагается инструкция `eska init`, но команда автоматически не запускается;
- место выполнения backend соответствует месту файлов проекта; выбранная
  поддержка Remote/виртуальных workspace и Workspace Trust явно объявлена;
  неподдержанный режим не маскируется локальным чтением похожего пути;
- лог процесса отделён от сообщений пользователю, protocol stdout не содержит
  human text; предусмотрены понятные состояния подключения и восстановления;
- тесты проверяют handshake, отсутствие/несовместимость бинарника, несколько
  проектов, неправильный manifest, завершение и перезапуск процесса.

Основание: [Extension Host](https://code.visualstudio.com/api/advanced-topics/extension-host),
[Remote Development](https://code.visualstudio.com/api/advanced-topics/remote-extensions),
[Workspace Trust](https://code.visualstudio.com/api/extension-guides/workspace-trust).

## T77 — Дерево проектов, модули и открытие исходников

**Статус:** `PLANNED`
**Зависит от:** T65, T70, T76

Показать нативный Tree View по узлам backend. Название «Модули», первое
раскрытие группы и показ только существующих BSL подтверждены. Действие выбора
объекта уточняется по таблице выше.
Группа модулей следует схеме каждого владельца, а не проверкам имён каталогов
в клиенте. Набор и расположение прочих групп соответствуют Конфигуратору.

**Готово, когда:**

- configuration/extension/report/processing имеют проверенные отдельные схемы;
  поддержаны реквизиты, табличные части, измерения, ресурсы, формы, команды,
  макеты и другие узлы матрицы T60;
- группа модулей первая; существующие BSL открываются из дерева напрямую;
  `.bin` без BSL скрыты, но владеющий объект не пропадает; чтение текста BSL
  происходит при открытии редактором, а не для построения дерева;
- открытие XML/BSL и положения inline-элемента использует source mapping;
  отсутствующий файл не создаётся и не подменяется другим кандидатом;
- дочерние элементы загружаются по раскрытию, stable IDs сохраняют выделение
  и раскрытие при обновлении; изменение одной ветки не сбрасывает всё дерево;
- работают клавиатура, масштабирование, светлая/тёмная/контрастная темы,
  доступные подписи и локализация; выбор показанного элемента не вызывает
  полного чтения конфигурации;
- доступны ручное обновление и локальная ошибка повреждённой ветки;
  исправление файла возвращает её в рабочее состояние;
- интеграционные тесты VS Code проверяют раскрытие и открытие файла/позиции,
  сохранение выделения, скрытие бинарных модулей и внешние изменения.

Основание: [Tree View API](https://code.visualstudio.com/api/extension-guides/tree-view),
[Views UX](https://code.visualstudio.com/api/ux-guidelines/views).

## T78 — Поиск в расширении и переход к результату

**Статус:** `PLANNED`
**Зависит от:** T75, T77

Добавить кнопку и команду поиска поверх API T75. Предлагаемый UI — стандартный
Quick Pick; итоговый выбор интерфейса фиксируется до реализации.

**Готово, когда:** запрос находит элементы принятого охвата даже в нераскрытых
ветках, показывает имя, вид и путь владельца, различает проекты. Выбор результата
раскрывает нужную ancestry и выделяет узел без обхода всех веток клиентом.
Устаревшие запросы отменяются, их ответы не заменяют новую выдачу. Видны
индексация, неполная/ограниченная выдача, ошибка и отсутствие совпадений.
Ввод не блокирует дерево, полная коллекция результатов не пересылается на
каждый символ. Проверены клавиатура, кириллица, одинаковые имена, переход к
вложенному элементу и удаление объекта между поиском и выбором.

Основание: [Quick Picks](https://code.visualstudio.com/api/ux-guidelines/quick-picks).

## T79 — Фильтр пустых групп и настройка исходного режима

**Статус:** `PLANNED`
**Зависит от:** T65–T67, T77

Добавить у конфигурации переключатель «Скрывать пустые группы» и настройку
исходного режима. Подтверждено: фильтр действует только на разделы корня
и включён по умолчанию. Вложенные группы объектов не фильтруются. Уточнить
сохранение переключения между сеансами и
приоритет user/workspace settings; несколько проектов не должны неявно менять
режим друг друга. Поведение внешних отчётов/обработок описать явно.

**Готово, когда:** скрываются только доказанно пустые группы; незагруженная
или ошибочная ветка не исчезает. «Общие» остаётся, если заполнена хотя бы одна
вложенная группа. Пустая корневая группа модулей определяется с учётом скрытых `.bin`.
Переключение не перестраивает поисковый индекс и не запускает полный parse;
обновление состава объекта корректирует видимость группы. Раскрытие сохраняется,
поведение выделения скрытого узла определено. Поиск непустого объекта не теряет
путь к нему из-за фильтра. Проверены отсутствие констант, пустые вложенные
коллекции (сохраняются видимыми), добавление/удаление последнего элемента
корневого раздела на маленьких fixtures,
несколько проектов и сохранение выбранного режима.

## T80 — Иконки метаданных

**Статус:** `PLANNED`
**Зависит от:** T65, T77

Выбрать набор иконок Конфигуратора либо максимально похожий комплект.
До включения файлов установить источник и условия использования. Сделать
небольшой визуальный образец для согласования, затем покрыть все типы T60,
виртуальные группы и роли модулей. Наличие произвольного пакета не означает,
что он покрывает метаданные 1С.

**Готово, когда:** есть таблица machine kind → icon, fallback неизвестного типа,
недостающие значки выполнены в согласованном стиле. Проверены светлая, тёмная
и контрастная темы, масштабирование и узнаваемость. SVG/другие ресурсы входят
в VSIX; показ дерева не скачивает изображения. Служебные кнопки используют
привычные обозначения VS Code, иконки не заменяют доступные текстовые подписи.

## T81 — Производительность интерфейса, приёмка и VSIX

**Статус:** `PLANNED`
**Зависит от:** T68, T76–T80

Собрать устанавливаемый VSIX и проверить полный сценарий на поддержанных ОС.
Публикация в Marketplace и изменение GitHub Actions/release pipeline требуют
отдельной задачи. Упаковка расширения не является сборкой конфигурации 1С.

**Готово, когда:**

- VSIX устанавливается в чистый тестовый профиль VS Code; инструкция объясняет
  установку совместимого `eska`, обязательный manifest и открытие проекта;
- весь сценарий «открыть → раскрыть → найти → перейти к исходнику → сменить
  фильтр → обновить → закрыть» проверен; не возникает фоновых процессов после
  закрытия и накопления памяти при повторных циклах;
- на `big_configuration_temp` измерены cold/warm latency, p95 и peak RSS,
  включая Extension Host: корень, 3 808 общих модулей, 636 макетов одного отчёта,
  поиск, выбор элемента и переключение фильтра. Бюджеты T68 проверены end-to-end;
  начальная индексация измерена отдельно от поиска по готовому индексу;
- XML/BSL большого стенда остаются неизменными; модификации для проверки
  обновлений делаются только в собственных маленьких fixtures;
- **сборка `big_configuration_temp` не запускается**, `ibcmd`/Конфигуратор
  не вызываются, версия платформы для просмотра не требуется;
- выполнены релевантные Rust-проверки по working agreement и проверки
  TypeScript/расширения, unit- и интеграционные тесты VS Code;
- фактическая проверка Windows/Linux/macOS записана отдельно: недоступная ОС
  обозначена как непроверенная, а не как успешно пройденная. Объявленный набор
  поддерживаемых ОС требует завершённой приёмки перед статусом `DONE`;
- ограничения и результаты замеров опубликованы в документации, T41 закрывается
  вместе с T81; T71–T74 автоматически не начинаются.

Основание: [упаковка VSIX](https://code.visualstudio.com/api/working-with-extensions/publishing-extension).
