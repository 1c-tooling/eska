# T145–T146 — Глобальные библиотеки анализа

Задачи добавлены по запросу пользователя от **2026-10-27**. T145 назначена
следующей задачей; T146 включена в планы без разрешения на реализацию вместе
с T145. Этот документ описывает будущий контракт, а не доступные настройки.
Применяются общие [правила реализации](working-agreement.md).

## Исходное состояние

Для отдельной обработки, отчёта или расширения внешняя основная конфигурация
подключается через `[analysis.configuration].source`. В workspace та же роль
задаётся через `workspace.members.<application>.configuration = { source = ... }`.
Ссылка ведёт к Designer XML, участвует в анализе и не становится рабочим member.
[Действующий контракт контекста](../application-context.md) и
[генерация bsl-analyzer.toml](../analyzer-configuration.md) остаются исходной основой.

Глобальный конфиг сейчас содержит настройки сборки; загрузчик находится в
`eska-build-runtime`. Каталога библиотек и разрешения их имён пока нет.
Генератор анализатора записывает один `source.root`. В проверенном контракте
bsl-analyzer 0.4.0 нет списка самостоятельных библиотек.

## T145 — Одна глобальная библиотека

**Статус:** `NEXT`
**Зависит от:** T83, T84, T90, T92, T93 — выполнены.
**Владелец:** ESKA — глобальный конфиг, разрешение ссылки и контекст;
Explorer — отображение ошибок и обновление языковой сессии по контракту ESKA.

### Результат и формат

Путь к библиотеке задаётся один раз на машине. Проекты и приложения workspace
выбирают библиотеку по имени. В каталоге допускается несколько записей,
например `ssl_3_1` и `ssl_3_2`, но один контекст использует **ровно одну выбранную
запись**. Наличие других записей не подключает их к анализу.

Глобальный `config.toml` — пример расположения исходников:

```toml
[libraries.ssl_3_1]
source = "/data/libraries/ssl_3_1/src/cf"

[libraries.ssl_3_2]
source = "/data/libraries/ssl_3_2/src/cf"
```

Отдельная внешняя обработка, отчёт или расширение:

```toml
[analysis.configuration]
library = "ssl_3_1"
```

Приложение workspace с внешними объектами и расширением:

```toml
[workspace.members.tools]
configuration = { library = "ssl_3_1" }
external_objects = ["src/my-processing", "src/my-report"]
extensions = [{ path = "src/my-extension" }]
```

На другой машине то же имя регистрируется со своим путём. Проектный manifest
остаётся переносимым. Имя является точной ссылкой на запись каталога, а не
диапазоном версий; для конкретного выпуска можно использовать имя вроде
`ssl_3_1_11_466`. Автоматический выбор «последней» версии не входит в задачу.

### Границы реализации

- Сохранить прямую ссылку `configuration = { source = ... }` для явного пути.
  `source` и `library` взаимоисключающие; пустое имя, оба поля или отсутствие
  обоих полей в объявленной ссылке — структурированная ошибка.
- Загружать каталог из существующего глобального конфига с учётом
  `ESKA_CONFIG_DIR`. Относительный глобальный `source` разрешать относительно
  каталога этого конфига; прямой проектный `source` — относительно manifest.
  Существующие команды инициализации и редактирования глобального конфига
  принимают новый раздел и сохраняют настройки `[build]`.
- Разрешение имени принадлежит общему слою ESKA. `eska-project` и `eska-check`
  не получают зависимость от runtime сборки ради чтения конфига; размещение
  общего загрузчика определить по текущим потребителям без обязательного
  создания нового crate. TypeScript не читает каталог и manifest самостоятельно.
- Проверять выбранную запись, доступность Designer XML и допустимость внешней
  ссылки по действующим правилам. Неизвестное имя, отсутствующий конфиг/каталог
  или неподходящая выгрузка дают ошибку с именем библиотеки и местом настройки;
  частичный контекст не выдаётся за успешный. Отсутствие глобального файла не
  мешает проектам без ссылки `library`.
- Подключённая библиотека остаётся контекстом только для чтения. Её исходники
  не становятся workspace member, объектом сборки, VCS-операций или массового fmt.
  В `bsl-analyzer.toml` записывается разрешённый путь в существующий `source.root`;
  новый контракт или выпуск bsl-analyzer для T145 не требуются.
- Выбранное имя, разрешённый путь и относящиеся к ним глобальные настройки
  участвуют в проверке актуальности контекста и производного конфига. Изменение
  выбранной записи обнаруживается CLI и работающим проектным сервером; обновление
  анализатора соблюдает действующие правила владения конфигом и языковой сессией,
  сохраняет пользовательские настройки диагностик и несохранённые документы.
  Изменение посторонней библиотеки не переключает активный контекст.
- Проверить round-trip manifest и существующие `new`/`init` при добавлении
  расширения или внешнего объекта: ссылка приложения остаётся в одном месте,
  абсолютный машинный путь не дублируется в дочерних проектах.

В T145 не входят массив библиотек, объединение нескольких конфигураций,
транзитивные зависимости, скачивание исходников, менеджер версий или новые
команды управления пакетами. Эти границы не препятствуют последующей T146.

### Приёмка

1. На собственных fixtures проверить отдельные EPF, ERF и расширение, а также
   workspace с общей библиотекой. Ссылка по имени и эквивалентный прямой путь
   дают одинаковые исходники и семантический контекст анализатора.
2. Две независимые глобальные настройки отображают одно имя в разные локальные
   пути без изменения проектного manifest; невыбранные записи не добавляют исходники.
3. Проверить неизвестное имя, пустую/двойную ссылку, отсутствующий файл и каталог,
   неверный XML, относительные пути, пробелы/Unicode, пересечение с рабочим member.
   Ошибки имеют ru/en-представление и стабильные machine-readable коды.
4. Изменить выбранный глобальный путь: CLI обнаруживает устаревший конфиг,
   Explorer обновляет контекст и языковую сессию без ручного изменения
   `bsl-analyzer.toml`. Настройки вроде `LineLength = false` сохраняются;
   проверяются dirty-буферы и действующее владение конфигом несколькими окнами.
5. Установленный совместимый bsl-analyzer принимает сгенерированный конфиг;
   реальная диагностика и переход в модуль выбранной библиотеки подтверждены.
   Проверить, что build/VCS/fmt не захватывают её исходники.
6. Выполнить обязательные проверки изменённого кода и обновить пользовательское
   руководство, схему конфигурации и контракт компонентов, если он изменится.

## T146 — Несколько библиотек в одном контексте

**Статус:** `PLANNED`
**Зависит от:** T145; согласованной модели библиотек и совместимого релиза
upstream bsl-analyzer.
**Владелец:** ESKA — декларации, разрешение источников и контекст;
bsl-analyzer — видимость символов, метаданные, типы и диагностики;
Explorer — представление результата и конфликтов.

Цель — совместно использовать несколько разных библиотек в одном приложении.
Предварительная форма для обсуждения контракта:

```toml
[analysis]
libraries = ["ssl_3_1", "exchange_2_0", "company_common"]
```

В workspace список относится к `workspace.members.<application>` рядом
с `configuration`, `extensions` и `external_objects`. Общий каталог хранит
машинные пути; схема состава задаётся один раз для выбранного контекста.
Окончательный формат определить при согласовании с анализатором, сохраняя
явное различие основной конфигурации, библиотек, расширений и внешних объектов.

До реализации определить identity и версию библиотеки, её собственный состав
и зависимости, устранение повторного подключения общего источника и поведение
при циклах. Две версии одной библиотеки проверяются в разных контекстах.
Конфликтующие одноимённые модули и объекты должны сообщать оба источника;
порядок списка не выбирает определение молча. Отдельно разобрать полные XML-выгрузки,
которые уже содержат одну и ту же БСП, и пересечение с основной конфигурацией.

Поддержка требует общего контракта анализа библиотек, а не повторной записи
`source.root` или объявления библиотек расширениями. Ядро bsl-analyzer не
форкается и не встраивается; наличие upstream PR не заменяет совместимый релиз.

Приёмка: две независимые библиотеки, общая зависимость, повтор одного источника,
конфликт определений, две версии одной библиотеки и цикл; одинаковый результат
CLI/IDE, реальные диагностики/переходы/типы, обновление одного источника без потери
происхождения символов. Текущая основная конфигурация и расширения сохраняют
свои правила видимости. Начало T146 требует отдельного выбора приоритета.
