# T134–T142 — Компактный конструктор запросов

По запросу от 2026-10-26 подготовлены задачи на развитие интерфейса ESKA.
Пользователь разрешил выполнение T134–T142 от 2026-10-26; сначала выполняются
все части, не требующие доработки bsl-analyzer. Анализатор пользователь
дорабатывает параллельно. T134 — `DONE`, T135 — `NEXT`; остальные задачи сохраняют
свои критерии, а семантическая зависимость не заменяется локальным resolver.
Типы и языковые сервисы продолжают [T115–T119](21-query-analysis.md);
[предложение для мейнтейнера bsl-analyzer](../query-analysis-upstream.md)
отделяет необходимые изменения анализатора от работы ESKA и Explorer.

## Что уже есть и что меняется

Исходная точка — завершённые T107–T114 и Metadata API 1.30.

| Сейчас, по коду | Планируемое изменение |
| --- | --- |
| Три панели таблиц/источников/полей, вкладки разделов; строки с текстом и отдельными кнопками | Плотные таблицы, редактирование ячеек, общая панель действий и изменяемая ширина областей |
| Добавление таблиц/полей, «Все поля», операции над отдельными строками | Множественный выбор, перенос и перестановка выбранного набора одной операцией |
| Имена полей без типов в `QueryFieldChoice` | Единое дерево полей и типов T118 с ленивым раскрытием ссылок |
| Отдельная форма выражения и HTML datalist | Контекстный редактор выражения, функции, параметры и языковые подсказки |
| JOIN, GROUP BY, WHERE/HAVING, ORDER BY, итоги уже редактируются | Компактные специализированные таблицы; структурированные сложные условия |
| Пакеты, временные таблицы, вложенные области и UNION уже поддерживаются | Дерево пакета, понятный путь к вложенной области и матрица соответствия колонок |
| DISTINCT/ALLOWED/числовой TOP сохраняются; FOR UPDATE ограничивает визуальное редактирование | Явные структурированные операции настройки модификаторов |
| Сворачиваемый просмотр полного текста | Изменяемая высота, выделение связанного фрагмента, переходы, diff и контролируемая правка текста |
| Анализ BSL-черновика приостанавливается на время конструктора | Анализ собственной ревизии конструктора через T116/T117 |

Проверенные точки входа: [модель и действия ESKA](../../crates/eska-project-core/src/project/query/constructor/mod.rs),
[сохранение модификаторов](../../crates/eska-project-core/src/project/query/constructor/model.rs),

Это ревью исходников; новый интерфейс в установленном редакторе не проверялся.

## Предлагаемый интерфейс

- Одна компактная строка команд: путь к запросу/ветви, состояние проверки,
  просмотр изменений, «Применить», «Отмена». Пакет раскрывается слева по требованию.
- «Таблицы и поля»: каталог, источники текущей области, результирующие колонки.
  Разделители меняют ширину; выбранное поле имеет тип, псевдоним и выражение.
- Основные разделы: таблицы/поля, связи, условия, группировка, порядок.
  UNION, итоги, индексы и СКД появляются по возможностям и контексту; неиспользуемый
  раздел доступен через «Добавить раздел». Модификаторы — в панели параметров запроса.
- Выражение открывается рядом с выбранной ячейкой или в расширяемом диалоге.
  Дерево доступных полей и список функций имеют поиск; вставка идёт в позицию курсора.
- Внизу — сворачиваемый текст запроса с сохранением высоты. Список ошибок
  открывается из индикатора и переводит к соответствующей строке/выражению.

Стиль: переменные темы VS Code, существующие и самостоятельно созданные ресурсы
ESKA, спокойные разделители, минимум повторяющихся подписей. Начальные цели
плотности: строка 24–28 px, панель команд 28–32 px при масштабе 100%; размеры
растут с пользовательским шрифтом. Проверить на 1280×800 и 900×650: команды
доступны без прокрутки всей страницы, длинные выражения не растягивают каждую
строку. На узком окне каталог сворачивается, содержимое остаётся доступным.

## Границы ответственности

ESKA владеет сессией, ревизиями, структурными операциями, диапазонами и точечным
планом правок. Explorer рисует элементы и передаёт намерение. bsl-analyzer
предоставляет типы, разрешение имён, диагностики и языковые подсказки.
Существующий конструктор ESKA сохраняется; семантический ответ анализатора
не становится генератором всего текста. Операции сохраняют комментарии,
неизвестный синтаксис, BOM/EOL; отказ не меняет текст и ревизию.

Общий [модальный контракт](working-agreement.md) сохраняется: конструктор
владеет собственным черновиком, применение возвращает родителю одну отменяемую
правку, отмена сохраняет родительский текст. Для групповых действий нужна
атомарная операция ESKA; серия независимых запросов из webview её не заменяет.
Обновлённые capabilities управляют доступностью каждого нового действия.

## T134 — Компактная оболочка и адаптивная компоновка

**Статус:** `DONE`. Выполнено 2026-10-26; [приёмка](../measurements/t134-compact-layout.json).
**Зависит от:** T114
**Владелец:** Explorer.

Заменить крупные блоки общей компоновкой с изменяемыми областями, одной панелью
команд и контекстными разделами. Сохранять ширину, высоту, активный раздел,
раскрытие и прокрутку; обновление модели не сбрасывает фокус и ввод.
Предусмотреть загрузку, отсутствие метаданных, конфликт и отключённое действие
с причиной. Использовать ru/en, светлую, тёмную и контрастную темы, управление
клавиатурой и доступные названия кнопок. Работа не требует нового анализатора.

Приёмка: сравнимые снимки старой/новой компоновки, размеры из раздела выше,
масштаб 100/150%, длинные русские/английские имена, восстановление состояния
после перехода между разделами и возврата из вложенного запроса.

Принято на Linux/VSCodium ru/en: 24 сочетания темы, размера и масштаба,
изменение размеров мышью и клавиатурой, сохранение ввода/курсора/прокрутки
и возврат из вложенной области. На собственном примере 48 длинных имён
при 1280×800 и 100% видна 21 полная строка вместо 3. До/после используют
одну версию расширения и один backend. Дополнительно прошли 16 native
регрессионных сценариев, TypeScript, Node/Bun (по 331 passed, 3 skipped).
Грамматика, операции запросов и API 1.30 не менялись. Статистические бюджеты
производительности и семантическая приёмка остаются в T142.

## T135 — Табличное редактирование и групповые действия

**Статус:** `NEXT`
**Зависит от:** T134
**Владелец:** Explorer; ESKA — недостающие атомарные действия.

Таблицы источников, полей, группировок, агрегатов, сортировки и итогов получают
редактирование ячеек и общую панель действий. Добавить множественный выбор,
перетаскивание и его клавиатурный эквивалент, перемещение, удаление и копирование
выбранного набора. Новые псевдонимы и обновление ссылок вычисляет ESKA.
Существующие ограничения перемещения зависимых элементов сохраняются.

Начальный вариант использует текущий каталог имён; T118 затем добавляет типы
в тот же компонент. Перенос поля из каталога с отсутствующим источником требует
явного действия «Добавить источник и поле» с одной проверяемой правкой.
Приёмка: 1/несколько/все строки, дубли имён, комментарии, устаревшая ревизия,
запрет поддержки, отклонённое действие без частичного изменения и Undo/Redo.

## T136 — Контекстный редактор выражений

**Статус:** `PLANNED`
**Зависит от:** T134, T116, T117
**Владелец:** Explorer и ESKA; языковые возможности — bsl-analyzer.

Единый редактор обслуживает SELECT, JOIN, WHERE/HAVING, группировки, порядок,
итоги и значения параметров виртуальных таблиц. Нужны подсветка, вставка поля,
поиск функций, подсказки аргументов, completion, hover, definition и диагностики
в текущей области запроса. Для каждого сервиса проверять capability; собственные
таблицы типов и функций в webview не создавать. Параметры с ожидаемыми типами
подключаются из T119, базовый список имён может появиться раньше.

Анализировать выражение внутри полного снимка запроса, а для BSL учитывать
контекст владельца. Правки completion переводятся обратно только в разрешённый
диапазон. Приёмка: незавершённый ввод, ВЫБОР, ЕСТЬNULL, ВЫРАЗИТЬ, подзапрос,
виртуальная таблица, составная ссылка, отмена и запоздавший ответ сервера.

## T137 — Связи и сложные условия

**Статус:** `PLANNED`
**Зависит от:** T135, T136
**Владелец:** ESKA — модель/операции; Explorer — представление.

Показывать JOIN как пары источников с типом соединения и набором условий ON.
WHERE и HAVING имеют отдельные группы с И/ИЛИ/НЕ, вложенными скобками,
МЕЖДУ, В/подзапросом и проверками NULL. Добавить недостающие структурированные
операции в core; сейчас часть этих конструкций консервативно блокирует правку.
Сложное неподдерживаемое выражение остаётся доступным как исходный текст.

Предлагать связи только по подтверждённым ссылочным типам T116, показывать
основание и требовать выбора пользователя. Название поля не определяет тип,
агрегат или связь. Перенос условия между WHERE/HAVING — явное действие;
агрегат внутри подзапроса не считается агрегатом внешней области.
Приёмка: несколько независимых JOIN, LEFT/RIGHT/FULL, И/ИЛИ со скобками,
строки с ключевыми словами, МЕЖДУ с датами и сохранение семантики на платформе.

## T138 — Матрица объединений

**Статус:** `PLANNED`
**Зависит от:** T135
**Владелец:** ESKA и Explorer; типы — дополнительное покрытие T116.

Показывать результирующие колонки по строкам и ветви UNION по столбцам:
выражение, общий псевдоним, тип при доступном анализе. Поддержать переключение
UNION/UNION ALL, переход в ветвь и явное выравнивание колонок. Использовать
существующие операции ESKA; новые групповые операции дополняют их контракт.
Просмотр матрицы не добавляет NULL и не меняет запрос. Заполнение пропусков
и перенос колонки между позициями имеют preview и атомарное применение.

Приёмка: 2/несколько ветвей, разные количества и типы колонок, вложенный UNION,
переименование выходной колонки, отличие UNION/UNION ALL на данных с дублями.

## T139 — Дерево пакета, временные и виртуальные таблицы

**Статус:** `PLANNED`
**Зависит от:** T134, T135
**Владелец:** ESKA и Explorer.

Добавить дерево «пакет → оператор → вложенная область/ветвь», короткий путь
возврата и переход от временной таблицы к её определению. Создание, копирование,
удаление, перестановка и переименование операторов учитывают зависимости;
использовать существующую модель пакета. Индексы редактируются таблицей полей.
Параметры виртуальной таблицы — компактной формой по существующей сигнатуре,
с сохранением пустых позиционных аргументов. Общий редактор сложного выражения
подключается после T136; до этого сохраняется существующее текстовое поле.

Приёмка: определение/использование/удаление временной таблицы, недопустимая
перестановка, цепочка пакета, несколько уровней вложения, сохранение выбора.
Английское удаление остаётся `DROP`; типы колонок подключаются через T116.

## T140 — Настройки и модификаторы запроса

**Статус:** `PLANNED`
**Зависит от:** T134
**Владелец:** ESKA — синтаксис и точечные правки; Explorer — форма.

Добавить структурированные настройки РАЗЛИЧНЫЕ/DISTINCT,
РАЗРЕШЕННЫЕ/ALLOWED, ПЕРВЫЕ/TOP, АВТОУПОРЯДОЧИВАНИЕ/AUTOORDER
и ДЛЯ ИЗМЕНЕНИЯ/FOR UPDATE с выбранными источниками. Значения и доступность
задаются core с учётом типа оператора, области и поддержанного синтаксиса.
Тип SELECT/ПОМЕСТИТЬ/УНИЧТОЖИТЬ связан с существующим управлением пакетом.
Изменение типа не удаляет молча итоги, индексы или другие несовместимые секции:
нужен конкретный план изменений либо отказ с сохранением текста.

Приёмка: импорт и повторное применение без правок сохраняют байты; включение,
отключение, сочетания модификаторов и пограничные значения TOP проверены
на изолированной платформенной ИБ. Неподдержанное сочетание не выдаётся за допустимое.

## T141 — Связанный текст, комментарии и просмотр изменений

**Статус:** `PLANNED`
**Зависит от:** T134, T135
**Владелец:** ESKA — диапазоны и планы; Explorer — навигация и diff.

Добавить подсветку диапазона выбранной строки в тексте и обратный переход
к области/элементу. Диапазоны и привязки комментариев брать из core.
Показать изменения относительно открытия конструктора; комментарии доступны
у связанного элемента и в общем списке. Сохранить высоту/сворачивание текста.

Прямая правка текста имеет отдельный временный буфер и явное применение
к модели: успешная проверка обновляет модель атомарно, ошибка сохраняет ввод
для исправления. Неподдержанные участки не исчезают. Форматирование подключается
по T122 и не является условием этой задачи. Приёмка: комментарии между секциями,
строки с кавычками, UTF-8/UTF-16, CRLF, смена области, invalid/unsupported ввод,
отмена и отсутствие изменений при открытии/закрытии без редактирования.

## T142 — Приёмка компактного конструктора

**Статус:** `PLANNED`
**Зависит от:** T118, T119, T134, T135, T136, T137, T138, T139, T140, T141
**Владелец:** ESKA и Explorer.

Зафиксировать сопоставимые измерения текущего/нового интерфейса: время открытия,
добавления поля и ответа на ввод, число запросов к backend, видимые строки,
память и сохранность фокуса. Бюджеты согласовать по baseline до оптимизаций.
Пройти установленный VSIX в ru/en, темы, масштаб, клавиатуру, мышь, split,
dirty-буферы, cancel/apply/Undo/Redo, перезапуск и устаревшие ответы.

Повторить релевантные платформенные сценарии T114 и новые условия/модификаторы
на собственных данных; сохранить ограничение одной секции итогов. Проверить
большую конфигурацию с расширениями, пример регистра из T115, недоступный
анализатор и частичный индекс. UI проверяется и с прежними capabilities.
Отчёт различает core/RPC, DOM, установленный редактор и выполнение 1С;
непроверенные ОС/IDE явно перечисляются. Полное закрытие требует семантической
части; промежуточная приёмка оболочки не закрывает T142.

## Рекомендуемая последовательность

Сначала T134 → T135: компактный интерфейс на действующем API. Затем T138,
T139, T140 и T141 с учётом их зависимостей. Согласование T115–T117 с мейнтейнером
можно вести независимо; после совместимого релиза — T118, T119, T136 → T137,
затем общая приёмка T142. По последующему разрешению пользователя выполняются
все независимые от анализатора части; семантические функции ожидают его
доработки. Форматтер остаётся в T120–T123, генерация BSL — в T129.
