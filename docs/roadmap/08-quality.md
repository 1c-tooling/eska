# Formatting и проверки

## T23 — Спецификация test backend

**Статус:** `DEFERRED`
**Зависит от:** T19, T20

До реализации `eska test`, `test --affected` и CI определить проверяемый
контракт: поддерживаемые test frameworks/runners 1С, discovery и стабильный ID
теста, выбор environment, фильтрацию по affected objects, human/JSON result,
exit codes, credentials и одинаковое локальное/CI поведение.

Результат T23 — отдельная принятая спецификация и декомпозиция implementation
tasks. Код команды, собственный test runner и новая dependency в T23 не входят.

Задача отложена до проверки практического CLI MVP (`switch`, `finish`, `build`)
в реальной разработке. Это меняет приоритет, но не удаляет задачу и её контракт.

В обсуждении от 2026-10-26 тестовый клиент 1С назван кандидатом для runner.
Оценить его вместе с остальными backend в этой спецификации, не создавая
параллельную задачу и не меняя статус T23.

## T26 — `eska fmt`

**Статус:** `PLANNED`
**Зависит от:** T03, T19, T144

Режимы `fmt`, `fmt <scope>`, `fmt --check`; project/object-aware scope,
детерминированность, скорость и одинаковый результат в CI. Не возвращать старый
экспериментальный formatter и не редактировать структурный XML regex-ами.
По запросу от 2026-10-27 это следующее направление после T143.

По требованию от 2026-10-26 о гибкости настроек как у clang-format T26 стала
сводной для [T120–T123, T144](22-configurable-formatting.md): политика и схема
стиля, форматтер BSL, форматтер SDBL/встроенных запросов, интеграция CLI/IDE/CI
и поставка отдельного компонента. Уточнение от 2026-10-27: самостоятельный
`eska-fmt`, делегирование `eska fmt`, профиль 1С по умолчанию и первичный
`eska.toml`. Алгоритм форматирования принадлежит ESKA и не требует bsl-analyzer.
T120–T122 — `DONE`, T123 — `IN-PROGRESS`; T26 завершается после приёмки T144.

## T27 — `eska check`

**Статус:** `PLANNED`  
**Зависит от:** T19, T26; расширяется после T28

Агрегатор project, Designer XML, formatting, BSL diagnostics и VCS policy checks.
Интегрировать зрелые анализаторы (например BSL Language Server), не переписывая их.
Обязательны human и JSON output, предсказуемые exit codes и независимое выполнение
checks.
