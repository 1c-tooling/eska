# T143 — Скорость компактного конструктора

**Статус:** `PLANNED`. По решению пользователя замеры T142 фиксируются,
оптимизация выполняется отдельной задачей. В текущий target до T142 её
реализация не входит. Доработка bsl-analyzer не требуется.

**Владелец:** Explorer — устранение затрат представления; ESKA сохраняет
операции, ревизии, диапазоны и проверки. Бюджет согласовать перед оптимизацией.

На одинаковом примере 48 полей при Linux/VSCodium, 1280×800 и 100% получены
следующие медианы шести повторных открытий после первого запуска:

| Сборка | Открытие | Добавление поля | Полных видимых строк |
| --- | ---: | ---: | ---: |
| Исходный интерфейс и API 1.30 | 176,65 мс | 35,30 мс | 5 |
| Компактный интерфейс и прежний API 1.30 | 264,15 мс | 124,04 мс | 21 |
| Компактные таблицы и API 1.32 | 1150,00 мс | 988,06 мс | 18 |

Это локальные серии из семи операций в одном новом профиле на вариант,
а не оценка всех машин. Число RPC одинаковое; медианы constructorOpen и
constructorAction в отдельной трассировке — 3,19 и 3,54 мс. Большая часть
задержки находится в представлении. В `resources/query/layout.mjs` функция
`mount` вычисляет `keyFor(node)` внутри `this.inputs.find` для каждого контрола.
В таблице это повторяет обход DOM-предков многократно. Это кандидат для
профилирования, а не доказанная доля общего времени.

Порядок работы:

1. Повторить сохранённый сценарий `query-compact-performance-host.cjs`, снять
   CPU-профиль webview и отделить JS, layout/paint и транспорт. Согласовать
   допуск по исходным измерениям; предложенные в обсуждении 0,4/0,15 с не приняты.
2. Устранить подтверждённые повторные вычисления без второй модели запроса,
   таблиц типов, новой зависимости или постоянного cache без необходимости.
3. Сравнить те же операции, RPC, RSS/heap и видимые строки до/после. Проверить
   восстановление ввода, курсора, фокуса, прокрутки, выбора и вложенной области.
4. Повторить установленный VSIX ru/en, старые capabilities, групповые операции,
   preview/cancel/apply, защиту родителя, устаревшую ревизию и Undo/Redo.

Сырые серии и точные SHA256 сборок сохраняются в отчёте T142. Изменение скорости
не разрешает переносить синтаксис или доменную логику из ESKA в расширение.
