# Приёмка компактного конструктора T134–T142

Все независимые от bsl-analyzer части реализованы и проверены. T134, T135 и T138–T141 закрыты. T136/T137 готовы структурно; полная T142 остаётся открытой до семантических контрактов анализатора. По решению пользователя оптимизация задержек вынесена в [T143](../roadmap/25-compact-constructor-performance.md).

Доменные операции, ревизии, диапазоны, комментарии, diff, планы и защита записи принадлежат ESKA. Explorer предоставляет интерфейс и штатный Undo/Redo. Второй resolver и таблицы типов/функций в расширении не добавлены. Контракт новых возможностей — Metadata API 1.32; старый API 1.30 проверен отдельно.

## Что принято

Компактная компоновка и сохранение состояния; таблицы и атомарные групповые действия; вставка поля в позицию курсора; группы И/ИЛИ/НЕ, МЕЖДУ, NULL и независимые ON; матрица UNION с явным выравниванием и preview; дерево пакета, текущие определения временных таблиц и копирование операторов; настройки SELECT; связанный текст, комментарии, diff и отдельный буфер полного текста. Неверный ввод и устаревшая команда не заменяют принятую модель.

## Измерения

Один новый профиль на вариант, семь операций: первое открытие отдельно, медиана шести повторов. Одинаковые 48 полей, 1280×800, 100%, en, без анализатора. Это локальные серии, не универсальные гарантии времени.

| Вариант | Открытие, медиана | Добавление поля, медиана | Видимых строк | Фокус/курсор после обновления |
| --- | ---: | ---: | ---: | --- |
| baseline | 176.65 мс | 35.30 мс | 5 | 0/7 |
| current-api30 | 264.15 мс | 124.04 мс | 21 | 7/7 |
| current-api32 | 1150.00 мс | 988.06 мс | 18 | 7/7 |

Число запросов одинаковое: 8 при открытии и 5 при добавлении поля, включая checkpoint и каталоги. В отдельной трассировке медианы constructorOpen/constructorAction — 3,19/3,54 мс. Основная задержка находится в представлении; повторный `keyFor` в поиске input — кандидат для CPU-профилирования. Оптимизация сейчас не выполнялась, бюджет не принят. RSS backend после серии: примерно 16,0 → 16,6 MiB; heap цели webview: 1,9 → 3,2 MiB. Полные замеры памяти, первых операций и диапазонов времени сохранены в JSON.

При одинаковом полном окне 1280×800 и 100% видны 18 строк вместо 5; API 1.30 в новой оболочке показывает 21 строку. При 900×650/150% новая сборка показывает 3 строки en и 2 ru, baseline — 0. Панель строк прокручивается горизонтально; заголовок переносит команды на узком окне.

## Ограничения

Tребуют анализатора: completion/hover/definition/signature help/диагностики, типы и раскрытие ссылок, ожидаемые типы параметров и подтверждённый подбор связей. Частичный семантический индекс и полная семантическая приёмка T142 пока не проверены. Windows, macOS, VS Code и Remote не проверялись.

Проверка полного текста в ESKA структурная. Например, платформа отклонила DISTINCT + AUTOORDER без полей автоматического порядка в проекции; конструктор не угадывает эти поля. Сохранены предел одной секции итогов и DROP. Buhmfo проверена на metadata-only ИБ: отсутствие строк ожидаемо и не доказывает поведение на рабочих данных.

Ранние неуспешные прогоны сохранены в стенде. XML fixture перенесена в подготовку до workspace/open: native dirty-close и настоящий watcher не должны случайно менять исходные условия проверки. До явного Save XML-запроса конструктор не пишет владельца; последующее Save и размещение исходного комментария проверены отдельно, с учётом BOM native-редактора.
