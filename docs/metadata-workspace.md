# Read-only API рабочего пространства метаданных

T66 реализована в `project::metadata_workspace`. Это библиотечная граница
для будущего IDE-процесса; новых CLI-команд и wire-протокола пока нет.

`MetadataWorkspace::open(start, names, entire_workspace)` использует существующие
discovery и selection. Обязателен `eska.toml`. Открываются только выбранные
проекты; manifests участников проверяются существующим discovery, но XML
невыбранных участников не читается. Тип и схема определяются manifest.
`projects()` перечисляет выбранные `ProjectSession`; `project(scope)` и
`project_mut(scope)` выбирают одну сессию. Одинаковые IDs разных участников
не смешиваются: внешний клиент хранит `ProjectScope` вместе с `NodeId`.

## Операции сессии

| Операция | Результат и чтение файлов |
| --- | --- |
| `root()` | ID корня выбранного проекта, без IO |
| `node(id)` | Уже показанный узел: ID, виртуальный parent, подпись, IDs детей, состояние, diagnostics, начальное раскрытие; без IO |
| `object(id)` | Известные имя, тип, логический parent, UUID и синонимы; без IO |
| `children(id, options)` | Дети в порядке Конфигуратора; при первом раскрытии объекта читает только его descriptor |
| `ancestry(id)` | Путь от корня до узла включительно, с виртуальными группами; без IO |
| `properties(id)` | Существующие свойства объекта и диапазоны в исходном XML; читает только owning descriptor |
| `source(id)` | Все существующие применимые источники с ролями, без чтения BSL/payload |
| `project()`, `scope()` | Проверенные пути/настройки проекта и namespace выбранного участника |

`NodeId` различает объекты, коллекции и модули. `TreeNode::can_expand()`
отличает известный лист от раскрываемой, ещё не загруженной или ошибочной ветви.
`ObjectSummary::uuid = None` у непрочитанной ссылки: UUID не выдумывается.
Синонимы ссылки доступны после раскрытия владельца этого XML; до этого
`synonyms` пуст. Выбор ссылки через `object` не вызывает скрытый parse.
Логический parent объекта отличается от виртуального parent узла.

Фильтр `TreeOptions` скрывает только доказанно пустые корневые разделы,
по умолчанию включён. Скрытый узел остаётся доступен по ID; ancestry сохраняется.
Подписи остаются именами или ключами `TreeLabel`: core не зависит от Fluent,
TTY и языка интерфейса. RU/EN ключи предоставляет существующий слой локализации.

Источники возвращаются относительно `session.project().source()`:
XML descriptor, существующие BSL с `ModuleRole`, payload формы/макета.
У inline-объекта возвращается descriptor владельца с логическим путём `inline`.
У виртуальной коллекции источников нет — это успешный пустой результат.
Выбор объекта не теряет его дополнительные модули и payload; выбор узла
модуля возвращает только соответствующий BSL. Неприменимые роли отфильтрованы
схемой, в том числе менеджер внешней обработки.

## Ошибки и границы загрузки

`WorkspaceError` сохраняет структурированные причины:
`UnknownProject`, `UnknownNode`, `UnknownObject`, `MissingSource`,
`Load` (в том числе parse с путём файла), `Source`, `Tree`.
Произвольный ID не инициирует обход диска: принимаются IDs, уже открытые
в корневой структуре или раскрытой ветви. Для результата будущего поиска
T75 сначала должны быть открыты необходимые владельцы.

Открытие читает корневую структуру и проверяет применимые пути модулей
прочитанных владельцев, но не читает дочерние XML, BSL и payload.
Построение ветви завершается до публикации узлов; virtual parent корня ветви
сохраняется при замене ссылки прочитанным объектом. Повреждённый descriptor
не мешает соседним ветвям. После ошибки узел получает `Error`, остаётся
выбираемым; повторное раскрытие может прочитать исправленный файл.

## Срок жизни и оставшаяся T67

В памяти сохраняются показанные узлы, краткие сведения об объектах и множество
раскрытых владельцев. Повторный выбор и раскрытие не требуют parse.
DOM, XML-буферы и свойства после ответа не сохраняются. Объём памяти растёт
с открытыми ветвями; ограничение и eviction относятся к T67.

Это снимок навигации на время сессии. Изменения успешно прочитанных ветвей
пока требуют закрытия и повторного открытия. `properties` каждый раз читает
актуальный descriptor, `source` проверяет актуальное наличие файлов; они
не перестраивают сохранённое дерево. Гарантии общего поколения, refresh,
инвалидация и cache свойств будут добавлены в T67. ID не зависят от подписи,
но переименование логического имени меняет ID согласно общей модели.

`close(self)` потребляет workspace; обычный drop эквивалентен. Файлы исходников,
manifest, Git и служебные cache-файлы не создаются и не изменяются.
Тестовый библиотечный клиент проходит четыре типа проектов и сравнивает
состав/байты всех файлов до открытия и после закрытия. Отдельные тесты
проверяют ленивую загрузку, повторный выбор после порчи XML, восстановление
ошибочной ветви, inline properties, все sources формы/модулей, фильтр,
ancestry и изоляцию workspace members.

Ограничения схем T65 (внешние источники, ещё не сверенные типы) сохраняются;
API не выдаёт неподдержанные XML-фрагменты за полностью разобранные объекты.
