# Read-only API рабочего пространства метаданных

T66–T67 реализованы в `project::metadata_workspace`. Это библиотечная граница
для будущего IDE-процесса; новых CLI-команд и wire-протокола пока нет.

`MetadataWorkspace::open(start, names, entire_workspace)` использует существующие
discovery и selection. Обязателен `eska.toml`. Открываются только выбранные
проекты; manifests участников проверяются существующим discovery, но XML
невыбранных участников не читается. Тип и схема определяются manifest.
`projects()` перечисляет выбранные `ProjectSession`; `project(scope)` и
`project_mut(scope)` выбирают одну сессию. Одинаковые IDs разных участников
не смешиваются: внешний клиент хранит `ProjectScope` вместе с `NodeId`.

## Операции сессии

| Операция | Результат и чтение файлов |
| --- | --- |
| `root()` | ID корня выбранного проекта, без IO |
| `node(id)` | Уже показанный узел: ID, виртуальный parent, подпись, IDs детей, состояние, diagnostics, начальное раскрытие; без IO |
| `object(id)` | Известные имя, тип, логический parent, UUID и синонимы; без IO |
| `children(id, options)` | Дети в порядке Конфигуратора; при первом раскрытии объекта читает только его descriptor |
| `ancestry(id)` | Путь от корня до узла включительно, с виртуальными группами; без IO |
| `properties(id)` | Свойства и диапазоны XML; первый запрос дополняет summary до полного descriptor, повторный использует cache |
| `source(id)` | Все существующие применимые источники с ролями, без чтения BSL/payload |
| `project()`, `scope()` | Проверенные пути/настройки проекта и namespace выбранного участника |

`NodeId` различает объекты, коллекции и модули. `TreeNode::can_expand()`
отличает известный лист от раскрываемой, ещё не загруженной или ошибочной ветви.
`ObjectSummary::uuid = None` у непрочитанной ссылки: UUID не выдумывается.
Синонимы ссылки доступны после раскрытия владельца этого XML; до этого
`synonyms` пуст. Выбор ссылки через `object` не вызывает скрытый parse.
Логический parent объекта отличается от виртуального parent узла.

Фильтр `TreeOptions` скрывает только доказанно пустые корневые разделы,
по умолчанию включён. Скрытый узел остаётся доступен по ID; ancestry сохраняется.
Подписи остаются именами или ключами `TreeLabel`: core не зависит от Fluent,
TTY и языка интерфейса. RU/EN ключи предоставляет существующий слой локализации.

Источники возвращаются относительно `session.project().source()`:
XML descriptor, существующие BSL с `ModuleRole`, payload формы/макета.
У inline-объекта возвращается descriptor владельца с логическим путём `inline`.
У виртуальной коллекции источников нет — это успешный пустой результат.
Выбор объекта не теряет его дополнительные модули и payload; выбор узла
модуля возвращает только соответствующий BSL. Неприменимые роли отфильтрованы
схемой, в том числе менеджер внешней обработки.

## Ошибки и границы загрузки

`WorkspaceError` сохраняет структурированные причины:
`UnknownProject`, `UnknownNode`, `UnknownObject`, `MissingSource`,
`Load` (в том числе parse с путём файла), `Source`, `Tree`.
Произвольный ID не инициирует обход диска: принимаются IDs, уже открытые
в корневой структуре или раскрытой ветви. Для результата будущего поиска
T75 сначала должны быть открыты необходимые владельцы.

Открытие читает корневую структуру и проверяет применимые пути модулей
прочитанных владельцев, но не читает дочерние XML, BSL и payload.
Построение ветви завершается до публикации узлов; virtual parent корня ветви
сохраняется при замене ссылки прочитанным объектом. Повреждённый descriptor
не мешает соседним ветвям. После ошибки узел получает `Error`, остаётся
выбираемым; повторное раскрытие может прочитать исправленный файл.

## Поколения, изменения и refresh (T67)

Источник изменений — события клиента, без фонового watcher в core.
`changed_paths(paths)` принимает нормализованные пути относительно source.
При переименовании клиент передаёт старый и новый пути; при изменении списка
объектов — также descriptor владельца (например, Configuration.xml).
Абсолютные пути, `..` и пустые пути отклоняются до изменения сессии.

Лексический индекс T61 связывает descriptor с владельцем без открытия XML;
он работает и после удаления файла. Артефакты BSL/форм/макетов относятся
к ближайшему известному descriptor. Повторный ownership parse через T50 здесь
не нужен: сессия уже знает объявления объектов. Неизвестный/неоднозначный путь
консервативно инвалидирует известные ветви и перечитывает корень.

Изменённый владелец и его потомки теряют cache и показываются как `Unloaded`;
данные читаются при следующем запросе. Независимые ветви не разбираются заново.
Изменение только корневого списка перечитывает корень, удаляет исчезнувшие IDs,
добавляет новые ссылки и сохраняет неизменившиеся раскрытые ветви.
XML/BSL события обновляют группу модулей, включая добавление и удаление BSL.
`source` проверяет фактическое наличие источников, но не читает BSL.

`refresh(node)` восстанавливает ветвь после пропущенных событий.
Для корня он сбрасывает все известные ветви, перечитывает корень и оставляет
потомков ленивыми. Изменение manifest или логического имени корня требует
повторного открытия workspace: это другая конфигурация/идентичность сессии.

`generation()` монотонно возрастает при непустой инвалидизации.
`RefreshReport` содержит новое поколение и затронутые IDs (в том числе удалённые).
Поисковый клиент T75 должен помечать результаты парой session/generation,
вызывать `check_generation` перед применением ответа и отклонять устаревший.
Генерация относится к одной открытой сессии, не переносится между открытиями.
Ошибка root refresh тоже повышает поколение: клиент читает `generation()`,
отбрасывает прежние результаты и показывает ошибку корня.

Операции обновления и чтения сериализованы через `&mut ProjectSession`.
XML сверяется повторным чтением после parse, SHA-256 сверяется перед публикацией
ветви; наличие модулей проверяется повторно. Изменение между этими проверками
даёт `SourceChanged`, не публикуя новую ветвь. На cache miss хеш также
сравнивается с сохранённым поколением: пропущенное событие не смешивает новые
properties со старым деревом. Cache hit не читает диск — доставку событий
обеспечивает клиент. Абсолютная атомарность внешней записи нескольких файлов
не обещается: клиент группирует события после сохранения и делает refresh
при пропусках. Исправленный XML после события снова доступен.

## Cache и память

`properties` теперь требует `&mut self` для LRU — изменение экспериментального
библиотечного API T66. Новых CLI/JSON contracts нет.
Кешируются owned descriptors через Arc, без DOM и исходных XML-буферов.
Summary дополняется полными свойствами только по первому запросу.
Inline-объекты разделяют owning descriptor. Повторные запросы не делают parse.

По умолчанию: 32 descriptors и бюджет 8 MiB по суммарному размеру исходного XML.
`set_cache_limits` меняет оба предела, ноль отключает удержание.
Превышение вытесняет наименее недавно использованный descriptor.
Большой descriptor может быть прочитан, но не удерживается сверх бюджета.
Это вес cache, **не точный предел RSS**: Rust-объекты имеют собственные allocations.
`cache_stats` показывает число parse/hit/eviction, текущий вес и последний
разобранный путь. При вытеснении навигационные IDs сохраняются; запрос свойств
может повторно разобрать только нужный файл. Лёгкие узлы, summaries,
лексический индекс и fingerprints живут до закрытия/инвалидизации ветвей;
их объём зависит от размера показанного дерева. Их стоимость измеряет T68.

## ConfigDumpInfo

[Read-only замер](measurements/t67-dump-info.json) большого стенда:
Configuration.xml — 1 773 646 байт, ConfigDumpInfo.xml — 39 484 937 байт
и 181 735 Metadata-записей. Один запуск Python ElementTree дал около 14 и
361 мс parse соответственно. Это сравнение входных данных, не benchmark Rust.
Для известного изменённого пути дополнительный обход dump info не нужен,
а ручное изменение XML/BSL не обязано обновлять его configVersion.
Поэтому dump info не используется как источник актуальности.
Его отсутствие, повреждение и события изменения не блокируют чтение XML/BSL.
Тесты отдельно проверяют, что устаревший dump info не скрывает реальные события.

`close(self)` потребляет workspace; обычный drop эквивалентен. Файлы исходников,
manifest, Git и служебные cache-файлы не создаются и не изменяются.
Тестовый библиотечный клиент проходит четыре типа проектов и сравнивает
состав/байты всех файлов до открытия и после закрытия. Отдельные тесты
проверяют ленивую загрузку, повторный выбор после порчи XML, восстановление
ошибочной ветви, inline properties, все sources формы/модулей, фильтр,
ancestry и изоляцию workspace members.

Ограничения схем T65 (внешние источники, ещё не сверенные типы) сохраняются;
API не выдаёт неподдержанные XML-фрагменты за полностью разобранные объекты.
