# Форматирование ESKA

## Статус контракта

T120 реализует политику в общем Rust core: профиль, схема, resolver, migration
preview/apply и протокол текста. T121 добавляет библиотеку `eska-fmt` с алгоритмом
BSL, T122 — SDBL и точечную запись встроенных запросов. В T123 готовы
`eska-fmt` / `eska fmt`; RPC/IDE и поставка по-прежнему в работе.
Анализатор не требуется для разрешения настроек или форматирования.

Первичный конфиг — `eska.toml`, секция `[format]`.
[JSON Schema версии 1](../schemas/format-v1.schema.json) описывает эту секцию,
а не целый манифест. Численные ограничения и область применения проверяет также
строгий загрузчик проекта/workspace. Смена версии профиля требует явного выбора;
новая версия приложения сама не меняет defaults профиля `1c` версии 1.

## Конфигурация

```toml
[format]
profile = "team"
profile_version = 1
exclude = ["**/generated/**"]

[format.profiles.team]
based_on = "1c"

[format.profiles.team.common]
column_limit = 100

[format.bsl]
indent_style = "space"
indent_width = 4

[[format.overrides]]
include = ["src/CommonModules/Legacy/**"]

[format.overrides.bsl]
column_limit = 0
```

Без секции используется `1c` версии 1. Существующие явные параметры
`tools.bsl-analyzer.formatting` учитываются для BSL. При несовместимости со
значением новой секции операция отклоняется до записи. `use_tabs=true` и
`indent_size=1` означают один таб шириной 4 колонки; другой размер в режиме
табуляции неоднозначен и требует явной миграции. В режиме пробелов сохраняется
число пробелов. `indent_size` не становится шириной табуляции автоматически.

Порядок: разрешённый профиль → workspace common/язык → member common/язык →
overrides workspace, затем member → параметры операции. В одном списке overrides
последнее совпадение побеждает. `include` обязательно, `exclude` внутри правила
отменяет только это правило. Пути относительно объявившего правила `eska.toml`;
поддерживаются `*`, `?`, `**` и `/`. `**/` совпадает также с нулём каталогов.
Абсолютные пути, `..`, обратные слеши и классы `[]` в glob не принимаются.

Таблицы наследуют отдельные ключи; скаляры и списки заменяются целиком.
`exclude=[]` очищает наследованные исключения, `column_limit=0` отключает
ограничение, `false` сохраняет свой смысл. Исключения не снимают защиту исходников.
Пользовательские профили объявляются в `format.profiles.<name>` и наследуют
`based_on`; встроенный `1c` переопределить нельзя. Неизвестные профили и циклы
отклоняются. Параметры отступов редактора не переопределяют стиль проекта.

## Каталог опций версии 1

Общие параметры допустимы в `common`, `bsl`, `sdbl` и соответствующих таблицах
профилей/overrides. `keyword_case` профиля SDBL по умолчанию `upper`, BSL —
`canonical`. Типы, диапазоны, enum и остальные defaults входят в JSON Schema.

| Ключ | Default | Смысл / English |
| --- | --- | --- |
| `indent_style` | `tab` | `tab` или `space`; indentation character |
| `indent_width` | `4` | Колонок на уровень; columns per block |
| `tab_width` | `4` | Визуальная ширина таба; tab stop width |
| `continuation_indent_width` | `4` | Добавочный отступ продолжения; continuation columns |
| `column_limit` | `120` | Ориентир длины, `0` без лимита; soft column limit |
| `keyword_case` | По языку | `canonical`, `upper`, `lower`, `preserve`; token spelling |
| `space_after_comma` | `true` | Пробел после запятой; comma spacing |
| `space_around_operators` | `true` | Пробелы вокруг бинарных операторов; binary spacing |
| `space_inside_parentheses` | `false` | Внутренние пробелы скобок; inner parentheses spacing |
| `space_before_call_parenthesis` | `false` | Пробел перед скобкой вызова; call parentheses spacing |
| `wrap_arguments` | `fit` | `fit`, `one_per_line`, `preserve`; call argument layout |
| `wrap_binary` | `fit` | `fit`, `one_per_line`, `preserve`; binary expression layout |
| `break_before_binary_operators` | `true` | Оператор начинает продолжение; leading operator |
| `max_empty_lines` | `1` | Максимум пустых строк; consecutive empty lines |
| `trim_trailing_whitespace` | `true` | Удаление хвостовых пробелов вне литералов/комментариев; trailing trivia |
| `insert_final_newline` | `true` | Финальный перевод строки; final newline |
| `comments` | `indent_only` | `indent_only` или `preserve`; comment indentation |
| `align_assignments` | `false` | Только BSL: выравнивание соседних присваиваний; assignment columns |
| `blank_lines_between_methods` | `1` | Только BSL: пустые строки между методами; method separation |
| `select_items` | `one_per_line` | Только SDBL: `fit`, `one_per_line`, `preserve`; SELECT item layout |
| `condition_items` | `one_per_line` | Только SDBL: переносы условий; condition layout |
| `group_items` | `one_per_line` | Только SDBL: группировки/итоги/индекс; grouping layout |
| `order_items` | `one_per_line` | Только SDBL: порядок; sort list layout |
| `blank_lines_between_queries` | `1` | Только SDBL: пустые строки между запросами/UNION; query separation |
| `clause_newlines` | `true` | Только SDBL: секции с новой строки; clause separation |
| `align_aliases` | `false` | Только SDBL: выравнивание КАК/AS; alias columns |

Например, ширина 2 и `space` дают два пробела вместо таба; `space_after_comma`
переключает `Метод(А,Б)` ↔ `Метод(А, Б)`; `space_around_operators` — `А=Б+В` ↔
`А = Б + В`; `keyword_case` — `если` ↔ `Если`/`ЕСЛИ`; `wrap_arguments` —
`Метод(А, Б)` ↔ вызов с каждым аргументом на своей строке; `select_items` —
`ВЫБРАТЬ А, Б` ↔ список полей по строкам; `align_aliases`/`align_assignments`
добавляют пробелы до общей колонки. Golden-примеры проверяют оба алгоритма через публичный протокол.

## Миграция и машинный контракт

Миграция выполняется явно: preview содержит точный исходный текст и результат.
Apply повторно проверяет план, текущие байты, тип файла и права. До замены создаёт
исключительно новый `.eska-fmt-backup-<sha256>.toml` рядом с манифестом; совпавший
backup допускается только при точном совпадении байтов. Чужой backup не заменяется.
Повтор apply к уже применённому плану возвращает тот же backup. BOM/CRLF, прочие
настройки и комментарии вне переносимой секции сохраняются. Подменённый план,
изменившийся манифест или защищённый файл не применяются. Обычное форматирование
миграцию манифеста не выполняет.

Протокол форматтера имеет `schema_version=1`: `language` (`bsl`/`sdbl`), полный
`options`, снимок `text`, nullable `range`. Координаты — полуоткрытые UTF-8 byte
offsets, границы проверяются до разбора. Лимит снимка — 4 MiB. Ответ содержит
`source_sha256`, список `edits` и фактический `formatted_range`. Адаптер IDE
преобразует координаты в нативные и проверяет версию своего документа; форматтер
не получает команды сохранить владельца. Полная эффективная политика содержит
происхождение каждой настройки, версию профиля, язык и признак исключения.

## BSL: алгоритм и проверенные границы

Форматтер разбирает заголовки/параметры методов, выражения, вызовы, обращения
через точку и индекс, переменные, условия, циклы, исключения, переходы и
асинхронный синтаксис. Обе языковые формы сохраняются. Препроцессорные ветви
проверяются раздельно и объединяются только при согласованной структуре блоков.
Аннотации и препроцессор остаются у левого края. В режиме изменения и контроля
текст `#Удаление`/`#Delete` сохраняется побайтно; активная вставка участвует
в разборе. Неизвестный синтаксис возвращает ошибку без правок.

Строки и комментарии остаются исходными токенами: форматирование BSL не меняет
значение многострочной строки и не форматирует находящийся в ней запрос.
Отдельные комментарии сохраняют собственную строку; комментарии после запятой
и перед закрывающей скобкой не теряются при переносе аргументов.
`comments=preserve` оставляет целиком содержащую комментарий конструкцию.
`trim_trailing_whitespace=false` сохраняет пробелы на оставленных физических
строках; `max_empty_lines` ограничивает их количество. Отдельно заданный
`blank_lines_between_methods` имеет приоритет для интервала между методами.

Выделение расширяется до полных синтаксических конструкций, что отражается в
`formatted_range`; остальные байты сохраняются. Ошибки могут содержать nullable
`offset` — UTF-8 byte offset начала проблемного токена/конструкции. Общие отказы
политики не обязаны иметь позицию исходника. После печати выполняются повторный
разбор и сравнение всех значимых токенов, включая точные литералы и комментарии.

Ограничения: снимок 4 MiB, 262144 токена, 128 уровней выражений/скобок/блоков,
64 уровня препроцессора; результат ограничен 16 MiB. Несогласуемые ветви и
неподдержанные конструкции отклоняются. Это не проверка типов, доступности API
или полноты бизнес-логики.

[Проверки T121](measurements/t121-bsl-formatting.json): 13 сценариев выполнены
платформой 8.3.27.2325 в отдельной ИБ, исходный и форматированный код дали
ожидаемые значения. Выборка 40 модулей buhmfo и пяти расширений прошла сравнение
токенов и повторный проход; исходники пользователя не записывались. Это не сборка
всей buhmfo. Дополнительные диагностики 27 fixtures завершены CLI анализатора;
замечания о стиле/контекстах не объявляются отсутствующими.

## SDBL и встроенные запросы

Один алгоритм обрабатывает отдельный запрос и SDBL-черновик. Форматтер использует
read-only проекцию секций из core: SELECT, JOIN/ON, WHERE, GROUP BY/HAVING, ORDER BY,
вложенные SELECT, UNION, INTO/INDEX BY/DROP, пакеты и итоги. CASE и известные
позиции СКД сохраняются исходными токенами; это не расширяет разрешения визуального
конструктора. Неизвестная структура отклоняет весь запрос без частичной правки.
Проверка грамматических границ не заменяет проверку типов и выполнение платформой.

`select_items`, `condition_items`, `group_items`, `order_items` принимают `fit`,
`one_per_line`, `preserve`. Например, `WHERE A=1 AND B=2` превращается в строки
`WHERE`, `    A = 1`, `    AND B = 2`; режим `fit` оставляет помещающийся список
вместе. `clause_newlines=false` допускает `SELECT A, B FROM T`. При
`align_aliases=true` пробелы ставятся перед общей колонкой AS/КАК; AS внутри CAST
выравниванию не подлежит. Ключевые слова/вызовы меняют регистр только в своих
ролях: путь `T.Where`, псевдоним и `&where` остаются исходными.

Выделение расширяется до полного запроса пакета со всеми ветвями UNION; вложенный
запрос форматируется вместе с содержащим его запросом. `// eska-fmt off/on`
сохраняет целиком затронутый запрос пакета. `comments=preserve` сохраняет запрос
целиком при наличии комментариев. Непереносимые литералы/комментарии могут
превышать `column_limit`. Ограничения core: 65536 токенов и 256 секций/запросов,
не более 32 уровней вложенных SELECT. Отдельный снимок по-прежнему ограничен 4 MiB.

`format_query` использует извлечение и `query::format_plan` core для выбранного
статического BSL-литерала или запроса XML. Общий BSL fmt не трогает строковые
значения. Динамические выражения не собираются в предполагаемый запрос.
Обратная запись проверяет снимок, кодирует кавычки/entities и меняет только
выбранное значение. Комментарии владельца переносятся по неизменным токенам;
неоднозначный якорь отклоняет операцию. Для BSL может сохраниться начальный
перевод строки запроса, необходимый для физической строки исходного комментария.
CDATA может стать экранированным текстом внутри того же query-элемента;
соседние XML-узлы/другие запросы остаются побайтно прежними.

[Приёмка T122](measurements/t122-query-formatting.json): 7 запросов и повторные
13 BSL-сценариев выполнены платформой 8.3.27.2325. Ещё 16 сценариев T114 выполнены
в обеих версиях на отдельной ИБ с тестовыми метаданными: 32/32, включая регистр,
параметры виртуальных таблиц и СКД. Это не выполнение запросов в рабочей buhmfo.

## CLI: файл, объект, member и проект

`eska-fmt [scope]` и `eska fmt [scope]` имеют одинаковые аргументы. Scope — путь
к файлу или каталогу относительно `--project-dir` (по умолчанию текущий каталог).
В проекте без scope выбираются BSL/SDBL из Designer source; каталог объекта
задаётся обычным путём, например `src/Catalogs/Items`. `--member NAME` и
`--workspace` используют общий resolver выбора ESKA. Отдельный BSL/SDBL-файл
работает без манифеста с профилем 1С. Существующий ошибочный манифест не игнорируется.

`--check`, `--diff`, `--dump-config` взаимоисключающие и ничего не записывают.
Без них применяется проверенный план. `--style JSON` задаёт sparse override
операции; все ключи и происхождение видны в `--dump-config`. Встроенный запрос
выбирается явно: `--query-at BYTE` для BSL или `--query-index INDEX` для XML,
индексы и координаты с нуля. Это режим одного файла. `--migrate-config` показывает
миграцию корневого манифеста workspace/проекта, `--apply-migration` применяет её с backup.

`--format json`: `{schema_version:1,formatter_version,mode,files,migration,error}`. Каждая запись files
содержит path, language, source_sha256, changed, status, edits, effective, diff.
`source_sha256` — null у исключённого файла и при `--dump-config`: текст не читается.
Status: `unchanged`, `excluded`, `planned`, `applied`, `failed`, `not_applied`.
Error — nullable структурированная ошибка `{code,field,offset?}`; схема и значения
не зависят от locale. В режиме diff правки также содержатся в edits; human вывод
показывает исходную и новую версии. Код 0 — успех/предпросмотр, 1 — только
`--check` с необходимыми изменениями, 2 — ошибка; отмена — 130. До записи всего
плана проверяются снимки, права, поддержка и межпроцессные блокировки источников.

Чистый вход компонента `eska-fmt __format-text` принимает один JSON Request
версии 1 на stdin, возвращает Response на stdout. Ошибка: `{schema_version:1,error}`
с кодом 2. Вход не читает конфигурацию, файлы или индекс; полная политика передана
вызывающим. Это тот же алгоритм, который используется CLI.

Примеры (scope относительно `--project-dir`):

```sh
eska-fmt Module.bsl --check --format json
eska fmt src/Catalogs/Items --diff
eska fmt --member MyExtension
eska fmt --workspace --check
eska-fmt Query.sdbl --dump-config
eska-fmt Module.bsl --query-at 123 --diff
eska-fmt Schema.xml --query-index 0
eska-fmt --migrate-config
eska-fmt --apply-migration
```

Межпроцессная защита использует пустые lock-файлы в `.eska/source-locks` проекта;
для отдельного файла — в его родительском каталоге. Это служебное состояние.
Lock inode не удаляется при закрытии: владение снимает ОС при закрытии последнего
handle, в том числе при завершении процесса. Снимок и политика поддержки всё равно
проверяются до записи. Молчаливое снятие чужой блокировки не предусмотрено.
План ограничен 128 MiB исходного/нового текста; обход — 100000 узлов и 128 уровней.
Предпросмотр не создаёт lock-файлы. Применение сначала проверяет все файлы,
получает leases и готовит все временные замены; только потом публикует исходники.
Операция не обещает видеть dirty-буфер посторонней IDE. Внешние изменения диска
проверяются по точным байтам; отказ preflight сохраняет весь план неприменённым.
