# Разрешение исходников Designer XML

Библиотечный модуль `project::designer_source` реализует T61. Команда IDE и
клиент VS Code пока не реализованы.

`open_projects(start, names, entire_workspace)` использует существующие
discovery и selection. `eska.toml` обязателен; source и тип берутся из него.
Для workspace XML читается только у выбранных участников. Платформа 1С,
Git-репозиторий и настроенная версия сборки для открытия не требуются.

Конфигурация и расширение открывают `Configuration.xml`. Для внешнего отчёта
или обработки проверяются XML непосредственно в source; `ConfigDumpInfo.xml`
пропускается. Имя корневого XML произвольное. Его тип сверяется с manifest;
нет подходящего корня, несколько корней, неверный namespace, повреждённый XML
и несовпадение типов — разные структурированные ошибки.

Читается не более 64 MiB на корневой descriptor, лимит XML — миллион узлов.
Корневой XML разбирается один раз. Дочерние каталоги при открытии не обходятся.

## Прямое разрешение

`DesignerSource::sources(ObjectId)` возвращает существующие исходники с ролями
`Descriptor`, `Module(role)` и `Payload`. `module(owner, role)` разрешает только
запрошенный BSL-модуль. Он не читает текст модуля; `.bin` без BSL не считается
доступным модулем. Соответствие роли типу владельца задаётся схемой T65, а здесь
проверяются пути существующих файлов.

| Логический элемент | Исходники |
|---|---|
| Объект верхнего уровня | `<коллекция>/<имя>.xml`; коллекция из единого справочника типов |
| Реквизит, табличная часть, измерение и другой inline-элемент | XML ближайшего владельца и логическая последовательность вложенных элементов |
| Форма | `<владелец>/Forms/<имя>.xml`, `Ext/Form.xml` или `Ext/Form.bin`, `Ext/Form/Module.bsl` внутри каталога формы |
| Команда | `<владелец>/Commands/<имя>.xml` и `Ext/CommandModule.bsl` внутри каталога команды |
| Макет | `<владелец>/Templates/<имя>.xml` и существующие `Ext/Template.*` внутри каталога макета |
| Подсистема внутри подсистемы | `<владелец>/Subsystems/<имя>.xml` |
| Модули конфигурации | `Ext/<роль>Module.bsl` относительно source |
| Внешний отчёт/обработка | `Ext`, `Forms`, `Commands`, `Templates` прямо в source либо под именем корневого XML без расширения |

Для макетов и форм просматривается только собственный каталог `Ext`;
дополнительные каталоги ресурсов рекурсивно не читаются. Несколько подходящих
вариантов одного descriptor или модуля дают `AmbiguousLocation`, а не выбор
первого найденного. Отсутствующий файл возвращает пустой результат.

Логическая inline-location пока не является проверенной координатой в тексте:
её существование и диапазон определяет parser T64. Resolver не проверяет
содержимое каждого найденного descriptor и не выдаёт выдуманные позиции.
Все пути в результате относительны source. Проверяются обычные компоненты
пути и canonical containment; выход через `..` или symlink отклоняется.

## Обратное разрешение

`changed_owners(paths)` использует существующий `discover_affected` из T19/T50:
читает только descriptors затронутых владельцев, сохраняет локальные ошибки
и число прочитанных descriptors. Полный `discover` для этой операции не нужен.
Пути Windows приводятся к разделителям логической Designer-схемы перед
распознаванием; возвращаемые пути остаются обычными `PathBuf` текущей ОС.

Тесты охватывают все зарегистрированные корневые коллекции, четыре типа
проектов, все роли модулей, обе раскладки внешних объектов, вложенные формы,
команды, макеты, подсистемы, inline-location, пустые кандидаты и symlink-выход.
Проверка на Windows/macOS ещё не выполнялась; переносимость на этих ОС
не объявляется результатом локального прогона Linux.
