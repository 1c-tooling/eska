# Дисковый кеш метаданных

`MetadataWorkspace::open_cached` открывает проект с кешем в
`<корень проекта>/.eska/cache/metadata`. У каждого участника workspace свой
каталог. Обязательный `eska.toml` проверяется при каждом открытии; source,
тип проекта и корневой XML определяются обычным discovery.
`MetadataWorkspace::open` сохраняет прежний режим без записей на диск.

Кеш сохраняет разобранные descriptors (summary и полные properties), а также
проверенные сведения о корне. Дерево и поисковые записи восстанавливаются из
этих данных. Он не содержит BSL, payload макетов или снимок раскрытия дерева.
Индексация поиска по-прежнему запускается отдельно от показа корня.

## Актуальность

При первом обращении к descriptor в новой сессии читается XML и вычисляется
SHA-256. При совпадении восстанавливается разобранная структура без XML parse.
Размер и дата файла не считаются доказательством отсутствия изменений:
редактор, копирование или переключение ветки могут сохранить их.
Поэтому дисковый кеш убирает повторный разбор, но не все чтения исходников.
Повторные обращения в текущей сессии используют память и события T67.

Корневой список объявлений проверяется первым, без рекурсивного обхода source.
Новые/удалённые объекты определяются по актуальным объявлениям владельцев;
удалённый descriptor не восстанавливается как существующий из кеша.
Наличие BSL-модулей проверяется заново при раскрытии: группа «Модули» не берётся
из старого снимка. Содержимое BSL для этого не читается.

## Формат и восстановление

Это внутренний версионированный JSON, **не публичный IDE-протокол**.
Ключ учитывает версию формата/программы, source, descriptor, владельца и режим
properties. Изменение правил сериализации/парсинга требует повышения версии
формата кеша. Содержимое защищено отдельной контрольной суммой.
Чтение одной записи ограничено 64 MiB, более крупные записи не сохраняются.

Запись выполняется через уникальный временный файл и переименование после
полной записи. Конкурирующие сессии могут заменять одну запись; хеш исходника
не позволяет принять данные другой версии XML. Ошибки кеша, несовместимый
формат, повреждение и отсутствие прав означают чтение/разбор XML обычным
способом. Исходники и manifest при этом не меняются.

Каталог создаёт собственный `.gitignore` со строкой `*`; шаблон новых проектов
также исключает `/.eska/cache/`. Существующий пользовательский `.gitignore`
в корне проекта не редактируется. Символьные ссылки в служебных каталогах
и вместо файлов кеша не используются. При конфликте с пользовательским
файлом кеш отключается для соответствующей операции.

Каталог можно удалить целиком при закрытой IDE. Удалённые из исходников
записи автоматически не обходятся и не удаляются: размер на диске зависит
от истории набора descriptors и версий формата. LRU сессии ограничивает
память разобранных descriptors отдельно; поисковый индекс имеет полный охват.

## Диагностика

`disk_cache_stats()` сообщает hits/misses/writes/failures и прочитанные/
записанные байты. Для режима `open` он возвращает `None`.
`source_io_stats()` отдельно показывает чтения XML и байты, время чтения,
проверки путей, обращения к metadata файлов и открытия каталогов, число разборов корня при discovery.
`cache_stats()` содержит разборы descriptors, LRU и время вычисления хешей.
Проверки путей включают canonicalize/existence/containment; это операции
resolver, не точное число системных вызовов `stat` внутри ОС.
