# Поиск по метаданным

T75 реализован в `project::metadata_workspace::search` как библиотечный API
`ProjectSession`. Поиск охватывает объекты и вложенные элементы Designer XML
по имени и синонимам, включая нераскрытые ветви. IDE-клиент использует его через [постоянный протокол](ide-protocol.md);
поиск в Explorer реализован в [T78](roadmap/14-vscode-extension.md#t78--поиск-в-расширении-и-переход-к-результату).
Виртуальные группы и модули не являются результатами поиска.

## Индексация

Открытие workspace не запускает индекс. Клиент явно вызывает
`start_search_index()`, затем `index_search_step(descriptors)` между запросами
интерфейса. Один шаг обрабатывает не более 64 описаний объектов из очереди, ноль не
выполняет работу. Файл предопределённых данных читается вместе с владельцем. Это синхронные кооперативные шаги: один крупный XML не прерывается
посередине; будущий IDE-клиент должен выполнять их вне UI-потока.
`cancel_search_index()` приостанавливает работу между шагами,
`resume_search_index()` продолжает очередь. Повторный start сбрасывает индекс.

Индекс использует summary descriptors и отдельную проекцию ancestry, не
раскрывает видимое дерево, не читает BSL или содержимое макетов. Полный охват
требует чтения всех объявленных descriptors. Неизвестные схеме XML-фрагменты
остаются диагностикой, а не объявляются успешно проиндексированными.

`search_progress()` и каждый ответ содержат поколение сессии, число доступных
объектов, ожидающих descriptors и ошибок. Состояния:
`NotStarted`, `Building`, `Cancelled`, `Ready`, `Incomplete`.
`search_failures()` возвращает ошибки чтения и диагностики по владельцам.
Пустой список совпадений при неполном индексе не означает отсутствие объекта.

## Запрос и результаты

`search(text, &SearchOptions)` не читает XML и не начинает индексацию.
Пробелы по краям запроса удаляются, пустой запрос возвращает пустой список.
Сопоставление — буквальная подстрока после Unicode lowercase, без fuzzy search,
разбиения на слова, морфологии и объединения «ё» с «е».

Ранги: точное имя, точный синоним, начало имени, начало синонима,
подстрока имени, подстрока синонима. При равном ранге порядок задают имя
в нижнем регистре и ObjectId. Разные объекты с одинаковыми именами сохраняются.
По умолчанию проверяются синонимы всех языков. `synonym_language` ограничивает
только синонимы точным ключом языка XML, например `ru` или `en`.

Лимит по умолчанию — 50, допустимый фактический диапазон — 1–500.
`truncated` означает усечение: клиент предлагает уточнить запрос.
Результат содержит project/object/node IDs, тип, имя, синонимы, ранг,
поколение и полный путь к узлу, включая виртуальные группы.
Для нескольких проектов клиент вызывает API выбранных сессий и сохраняет
ProjectScope: одинаковые ObjectId разных проектов не взаимозаменяемы.

`reveal_search_hit(hit)` проверяет проект и поколение, раскрывает только
объекты-предки результата и возвращает доступный путь в дереве.
Результаты предыдущей сессии нельзя переносить в заново открытую сессию.

## Обновления и время жизни

`changed_paths` и `refresh` из T67 инвалидируют также поисковые записи, даже
если ветвь не раскрывалась. Затронутые поддеревья скрыты из выдачи до повторной
индексации. Клиент продолжает шаги очереди; при отмене сначала вызывает resume.
Изменение списка владельца удаляет исчезнувшие поддеревья и сохраняет индекс
неизменившихся дочерних descriptors. Пропущенные события требуют refresh,
как и для дерева: сам поисковый запрос свежесть файлов не проверяет.

Индекс хранится в памяти до закрытия сессии отдельно от ограниченного LRU
кеша descriptors; его размер зависит от полного охвата метаданных.
При `open_cached` descriptors восстанавливаются из [дискового кеша T68](metadata-cache.md)
после проверки хеша XML; поисковые записи строятся заново без повторного XML
parse неизменённых descriptors. При обычном `open` записей на диск нет.

Предопределённые данные четырёх поддержанных видов объектов включаются в индекс
из Ext/Predefined.xml без раскрытия дерева. Индексируются Name и Description
(язык `und`, поскольку поле не локализовано). При явно заданном synonym_language
действует обычное точное сравнение, включая `und`. Изменение payload инвалидирует
записи его владельца, reveal раскрывает группу и фактических родителей элемента.
Один шаг владельца может дополнительно читать его файл предопределённых данных.
