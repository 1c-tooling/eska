# Отмена запросов общего анализатора

`module_diagnostics` и `module_completions` теперь принимают
`QueryCancellation` вместо простого флага контроллера ввода. Это отдельное
изменение неопубликованного API `eska-analysis`; стабильные CLI и установленный
комплект не менялись. `InputRequest.cancellation` сохраняет прежний контракт
ограниченного чтения YAML/BSL.

Каждый query создаёт короткоживущий handle той же базы. Внутри одного внешнего
attach scope регистрируется его Salsa cancellation token. `cancel()` доступен
другому потоку: выполняющийся запрос прерывается на ближайшем checkpoint ядра.
Один токен управляет одним активным запросом; повторное одновременное
использование отклоняется через `CancellationTokenInUse`. Отмена постоянна,
включая все клоны токена. Повторный запрос требует нового токена.

Guard удаляет регистрацию при обычном возврате, отмене или panic; clone базы
не выходит из метода и не блокирует следующую запись. Входные байты, fingerprint
и `SessionRevision` отменой query не меняются. Перехватывается только Salsa
cancellation unwind; непредвиденный panic передаётся вызывающему коду.

Это кооперативная отмена: произвольный код без checkpoint не останавливается
немедленно. Для проверок до/после query остаются явные checkpoints и проверка
токена перед выдачей результата. Deadlines, планировщик запросов, бюджет RSS
и transport пока не реализованы; EF-18 остаётся `IN_PROGRESS`.

Три новых синхронизированных теста не зависят от задержек: отмена приходит
внутри выполняющегося tracked body, реальный parse checkpoint не пропускает
вычисление дальше. Проверены неизменные входы, последующий query/update,
изолированность соседнего handle, отказ при занятом токене, поздняя отмена
после удаления регистрации и cleanup после немаскируемого panic.
Общая библиотека прошла fmt/check/strict Clippy, 16 тестов без ignored, Rustdoc
и release-сборку read-only примера. Повторная проверка C1 сохраняет одинаковую
syntax-only диагностику saved/editor/close/batch и явную неполноту проекта.
Результаты записаны в [машинном отчёте](query-cancellation-results.json).
Проверка платформы 1С не требуется для этого изменения read-only запроса;
клиентская приёмка здесь не проводилась.
