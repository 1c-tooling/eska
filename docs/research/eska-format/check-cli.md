# Самостоятельный syntax checker ESKA

Первый `eska-check` — отдельный бинарник общей библиотеки `eska-analysis`,
собираемый feature `check-cli`. Он проверяет сохранённые исходники обычной
конфигурации ESKA. Сервер IDE, LSP runtime, Git, отладчик, платформа 1С и XML-экспорт
не участвуют. Команда экспериментальная, не опубликована, не включена в установщик
и пока не вызывается оболочкой `eska`. Сборка описана в
[README библиотеки](../../../tools/analysis-core/README.md).

## Команда и границы профиля

```bash
eska-check --profile syntax --format json
eska-check --profile syntax --project-dir . --project main --lang ru-RU
eska-check --profile syntax --timeout-seconds 300 --max-document-bytes 67108864
eska-check --profile syntax --max-retained-source-bytes 268435456
```

`--profile` обязателен; сейчас поддержан только `syntax`, использующий
`ParseError` общего ядра. Выбирается один проект тем же selector, что проектным
и сборочным инструментом: из workspace root нужен `--project`, внутри member
он определяется по контексту. Workspace sweep и Designer XML не поддержаны.
`--config` задаёт настройки относительно выбранного проекта; иначе читается
`bsl-analyzer.toml` с прежним JSON fallback pinned config loader. Ошибка файла
не подменяется настройками по умолчанию. Отключение `ParseError` даёт
`profile_enabled=false` и неполную проверку, без обхода BSL.

Настройки исключений исходников, дополнительных конфигураций, extensions,
externals, Git diff/authors и diagnostic baseline пока отклоняются через
`analysis_scope_unsupported`. Checker не игнорирует заданный неподдержанный scope.
Полная семантика, formatter, платформенные проверки и VCS-политика не включаются
в этот профиль. Их нельзя считать пройденными на основании exit 0.

| Exit | Результат |
|---|---|
| 0 | Профиль проверен, находок нет, требуемое покрытие дескрипторов полное |
| 1 | При полном покрытии найдены ошибки синтаксиса |
| 2 | Неполные модели метаданных, unread/binary input, отключённый профиль или остановка |
| 3 | Ошибка аргументов, выбора проекта, настроек или запуска анализа |

Неполнота имеет приоритет над findings; уже найденные ошибки остаются в отчёте.
Help/version возвращают 0. Human output и help доступны на RU/EN; JSON не содержит
локализованных сообщений или времени выполнения.

## Общие входы и bounded batch

Проверенная проектная композиция передаётся в сессию через `into_reader`/
`from_reader`; повторного открытия manifest нет. Идентичности YAML и модулей
берутся из того же manifest, что в IDE. Модули inline-команд связываются
с дескриптором владельца: отдельного command XML в этом layout нет. Сохранённые
файлы необъявленных объектов остаются ресурсами и не становятся активными
модулями при файловом обходе.

YAML проходит прежний saved input/adapter. BSL читается verbatim, с BOM/CRLF,
получает source hash и проверяется тем же `module_diagnostics`. Тело освобождается
после независимой syntax-проверки; тяжёлые memo периодически очищаются между
группами из 32 модулей. Счётчик проверенных файлов принадлежит результату batch,
а не текущей резидентной полноте уже освобождённых тел. Это правило нельзя
переносить на семантический профиль, которому нужны соседние модули.

`--max-retained-source-bytes` задаёт [общую квоту текущих YAML/BSL-входов](source-budget.md),
по умолчанию 256 MiB. `--max-document-bytes` уменьшает общий жёсткий предел документа 64 MiB.
Текущие BSL-тексты также ограничены 64 MiB; модели YAML, результаты, parse trees
и memo в эту квоту не входят. Это не общий предел heap или RSS.

`--timeout-seconds` по умолчанию 300. Один timer отменяет bounded reads
и активный query через `QueryCancellation`. Лимит начинается после выбора
проекта, загрузки настроек и открытия композиции; охватывает создание сессии,
чтение YAML/BSL, queries и построение coverage. Перед возвратом результата
deadline проверяется ещё раз. Завершённый batch сразу останавливает timer.
Отмена кооперативная: блокирующий I/O и код без checkpoint могут выйти
за указанное время. Начальная композиция и вывод отчёта не имеют общего
wall-time лимита. Остановка сохраняет явные `stop` и число непроверенных модулей,
никогда не превращаясь в успешный пустой отчёт.

## Машинный контракт

Schema 1 содержит `tool=eska-check`, `command=check`, `status` и `data`.
В `data` находятся `project_root`, `scope`, `settings_path`, `settings_sha256`,
`position_encoding=unicode-scalar` и `report`. Settings hash относится
к нормализованным правилам профиля, а не к сырым байтам файла настроек.
Ошибки запуска используют общий error envelope проектных инструментов.

`report` содержит profile/enabled/status, manifest hash, coverage, resources, stop,
metadata issues и результаты файлов. Coverage раздельно показывает полноту
чтения YAML, поддержанных моделей прочитанных дескрипторов и syntax-проверки.
`metadata_models_complete` имеет ограниченный смысл
[`descriptor_models_complete`](shared-session.md): полнота ресурсов, всех
семантических свойств, типов и BSL-анализа этим полем не подтверждается.
`resources` показывает точный текущий резерв исходных байтов и его общий предел,
считая owning YAML текущих готовых моделей и загруженные BSL-тексты.
Файлы имеют state `checked`, `binary` или `unavailable`, source hash и ревизию
проверенных байтов. Findings содержат code/severity, UTF-8 byte ranges и
zero-based строки/колонки в Unicode scalars. Человекочитаемые позиции начинаются
с 1; это не LSP UTF-16 coordinates.

## Проверки

Первый компонент проверен 20 unit/файловыми тестами общего host и восемью
process-тестами. Проверены saved IDE/batch parity, inline-команды, release
текущего текста, readonly BOM/CRLF, оба языка, JSON, exit codes, настройки,
selection, binary/unread/limits и deadline.
Fmt/check/strict Clippy/test/Rustdoc и release-сборка прошли. Приложение прошло
полный обязательный набор и minimal/project-cli/build-cli matrix: 884 успешных
теста основного набора, 14 прежних ignored. Минимальный core сохранил
160 успешных тестов и три ignored.

Реальная конфигурация C1 содержит 1 975 активных текстовых модулей, включая
99 inline-команд. Все проверены, синтаксических findings нет; байты BSL совпадают
с нативными, исходники не изменены, JSON RU/EN одинаков. Неполнота текущих
проекций YAML сохранила exit 2. Установленный `bsl-analyzer 0.2.86` проверил
1 979 BSL-файлов при файловом обходе; четыре дополнительных файла принадлежат
объектам, отсутствующим в декларациях конфигурации и сохранённым как ресурсы.
На том же активном наборе диагностика совпала. Reference здесь проверяет
только `ParseError`: он не умеет загружать канонические метаданные ESKA.
Workspace MCP в сессии недоступен; использован установленный CLI.

C1 прошла за 13,5/14,2 секунды на EN/RU с peak RSS около 529 MiB; размер
release-бинарника — около 44 MiB. На C2/C3 analysis timeout в одну секунду
дал `deadline_exceeded`, exit 2 и 19 170/22 710 явно непроверенных модулей.
Полный wall time составил 1,73/1,84 секунды, что подтверждает границы
кооперативного лимита, а не жёсткий предел всего процесса. Полный syntax sweep
этих двух конфигураций здесь не проводился.

Исторические замеры первого компонента и граф зависимостей записаны в
[машинном отчёте](check-cli-results.json). Полная семантическая приёмка,
сервер, глобальный бюджет памяти и платформенная клиентская проверка этим
компонентом не выполнены. EF-18 остаётся `IN_PROGRESS`.
Общая квота и её последующие проверки описаны в [следующем компоненте](source-budget.md).
