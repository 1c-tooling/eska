# Проверенная распаковка CF/CFE

`eska new --from` и `eska import` распаковывают файл в собственной временной
области `.eska/import`. Пробная `ibcmd config export --file` даёт root identity:
тип, native UUID и имя. CF/CFE затем загружаются в отдельную файловую ИБ;
CFE получает `--extension` с именем из XML. Для загрузки суффикс меняется
только у собственной временной копии, по проверенному типу.

Повторная полная выгрузка обязана сохранить identity и содержать ConfigDumpInfo.
Частичные файлы пробного export удаляются и не попадают в проект. EPF/ERF
сохраняют успешную прямую выгрузку; фактическое имя дескриптора читается из
результата, включая Unicode и точки в имени входного файла.

1С может прочитать пустую конфигурацию под неверным суффиксом, сообщив успех.
Несовпадение identity разрешает ограниченный повтор с другими native суффиксами,
каждый в новой ИБ. Всего не более четырёх вариантов. Отмена, ошибка запуска,
обычная ошибка платформы или отсутствие проверенного корня не запускают повтор.
Конечное несовпадение, неполная выгрузка и другая identity завершаются отказом
без изменения проекта или входного файла. Успешные JSON схемы не изменены.

На установленной 1С 8.3.27.2325 через Distrobox проверено реальное расширение:
прямой export дал 106 файлов и ошибку хранилища, полная загрузка/выгрузка — 107.
Переименованные CFE `.cf` и CF `.cfe` восстановили правильные type/UUID/Name;
входные SHA-256 сохранились. Для CFE сравнились все пути и байты метаданных,
модулей и ресурсов; отдельно отличается служебный ConfigDumpInfo.

Процессная fixture воспроизводит ложный пустой root, ошибки загрузки/выгрузки,
неверную identity и отсутствие ConfigDumpInfo. Проверены обе локали, новый
проект и сохранность существующего source/config, временная очистка и отсутствие
частичных файлов в результате. Windows/macOS здесь не проверялись.
