# Карта состава при повторном импорте

EF-25 добавляет проверяемое переименование отдельных объявленных объектов по
UUID. Рабочая карта, подтверждённый предок и incoming сравниваются независимо
от исходных native fingerprints. Если карта изменилась только на одной стороне,
план выбирает её; разные карты обеих сторон дают `mapping_unsupported`.

Следующая часть добавляет [удаление owner](import-deletion.md); ниже описана
исходная граница rename представления и его приёмка.

Descriptor merge переносит новый native path и `Name`, сохраняя независимые
рабочие значения и YAML comments. Модули, ресурсы и plain queries сопоставляются
по UUID владельца и относительному native slot. Локальный модуль переезжает вместе
с объектом; bytes, BOM и CRLF сохраняются. Manifest публикуется последним в уже
существующем guarded journal. Поддержка, freeze, settings и accepted pin не меняются.

## Проверка прав

Перед выбором значений создаётся временное представление привязок. Оно требует
того же профиля, корня, набора UUID, классов, родительства и порядка UUID ссылок.
Разрешено переименование unrestricted владельца при разрешённом Resource доступе.
Нативный запрет, ESKA freeze и editable-with-support не разрешают переименование
в этом профиле. Замороженный родитель продолжает ограничивать потомков.

Представление берёт прежние native stencils и защищённые значения из independently
pinned base. Из новой карты оно выбирает только проверенные имена/пути и ссылки
на те же UUID. Single/list references и preserved text links принимаются только
как точная подстановка нового qualified label того же UUID; у общего модуля
сохраняется прежний метод обработчика. Владелец ссылки должен разрешать её правку.
Представление не становится новой принятой базой: повторная проверка storage
по-прежнему сравнивает исходный approved snapshot, а не производную карту.

Защищённая подготовка сборки выполняет ту же проверку после публикации. При
неизменной карте действует прежний selector, включая восстановление повреждённого
working manifest в non-strict режиме. Непринятые структурные изменения не получают
прав через новую декларацию.

Сохранившиеся ссылки на прежнее квалифицированное имя блокируют результат.
Для общего модуля также проверяются отдельные BSL identifiers его прежнего имени.
Проверка консервативная: отдельные BSL identifiers, opaque XML и текстовые
упоминания не переписываются автоматически. Переданная ссылка должна совпасть
с проверенным переходом; произвольная правка preserved XML остаётся отказом.
Пересекающиеся BSL, SDBL и binary edits остаются конфликтами файлов.

## Обратные координаты

Source map schema 6 допускает разные accepted/working пути одного UUID. `accepted`
содержит настоящий исходный path/fingerprint из принятого store; `working` —
новый путь и текущие bytes. Сериализованный stencil не объявляется принятым input.
`locate` находит исходный descriptor по UUID и переводит изменённый `Name`/property
в рабочий YAML. Legacy maps 1–5 сохраняют прежние ограничения и сериализацию;
prepared artifact envelope остаётся прежним. Descriptor schemas 1/2 поддержаны.

## Проверки и границы

Unit проверки покрывают перенос локального модуля и свойства, сохранение YAML
comments, UUID/policy pin, координату нового имени, frozen rename, подмену UUID,
неизменный повтор и surviving dependency. Обработчик проверен для разрешённого
перехода, нового метода и frozen link owner. Форма проверена вместе с типизированной
default-form ссылкой, новой привязкой plain query и координатой локального `.sdbl`.
Полный Rust набор и независимые native
циклы записываются в [результатах](import-composition-results.json).

Следующие части добавили [удаление](import-deletion.md) и
[полные новые собственные поддеревья](import-addition.md). Ниже — граница этой
исходной части rename: добавление/удаление отдельного объекта, новый/заимствованный UUID, перестановка
ссылок одновременно с rename и изменение inline состава вместе с новой картой
ещё не поддержаны этим представлением. Неинтерпретируемый XML payload
(включая binary bytes в файле с `.xml`) блокирует проверку зависимостей rename.
Existing inline операции при неизменной
карте сохраняют прежнее поведение. Native CLI lifecycle, IDE refresh и приёмка
EF-25 остаются отдельными незавершёнными частями той же задачи.

Четыре отдельные контролируемые native пары прошли import/build/dump на 1С
8.3.27.2325: 13/107/8/6 файлов. ERF содержит дополнительный собственный СКД макет,
созданный для этого опыта. После нормализации физических EPF/ERF root filenames
и игнорирования служебных CDF configVersion совпали весь состав, metadata XML
semantics и opaque bytes. BSL отличается только ожидаемым локальным комментарием;
repeat, settings и прежний pin проверены. Выполнение форм/отчётов клиентом и
производственные конфигурации в этой части не проверялись.

Workspace MCP недоступен; четыре изменённых BSL файла проверены установленным
`bsl-analyzer-app` через CLI. Baseline complete, failed files 0, SyntaxError 0;
прочие style/context diagnostics: 0/4/50/2. Это проверка выбранных модулей, не
полная семантическая приёмка конфигурации. Конфигурация анализа использовала
defaults: `bsl-analyzer.toml` в собственных проектах этого опыта отсутствует.
