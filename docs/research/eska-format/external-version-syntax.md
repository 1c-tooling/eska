# Синтаксический адаптер версии внешнего объекта — T84

Первый адаптер T84 реализован в общем `project_core::object_module_version`.
Он принимает текст BSL, возвращает общий `ProjectVersion`, диапазон функции и
точный диапазон числового содержимого литерала в исходных UTF-8 bytes.
Файловые операции, CLI, связь с регистрацией БСП, миграция и реальная EPF/ERF
приёмка ещё не подключены. T84 остаётся `IN_PROGRESS`.

## Контракт

Требуется ровно одна экспортная функция `Версия()` без параметров, async и
компиляторных аннотаций. Она имеет одно выражение `Возврат` со строковым
литералом корректной схемы T83. Русские/английские keywords и регистр имени
поддерживаются. Комментарии и области разрешены; условные определения и
контекст вставки/удаления отказаны. Произвольные тела, склейка, скобки,
вычисление и несколько возвратов не считаются управляемым источником версии.

Parser разбирает весь модуль перед проверкой функции. Синтаксическая ошибка
соседнего кода отказывает; семантика соседнего кода не проверяется.
Комментарии, строки и обращения к одноимённым членам не объявляют функцию.
Ошибки содержат стабильный code и исходный byte range, без локализованных
сообщений parser. Отсутствующая функция указывает на EOF. Размер текста
ограничен 16 МиБ; BOM учитывается в координатах.

## Выбор parser

Для этого узкого consumer используются опубликованные `tree-sitter` 0.27.1
с единственным feature `std` и `tree-sitter-bsl` 0.1.7, MIT по их manifests.
AST и поля берутся из [опубликованной BSL grammar](https://github.com/alkoleft/tree-sitter-bsl).
Regex не используется для обнаружения функции или замены литерала.

Прямое подключение закреплённого parser bsl-analyzer проверено локально:
`cargo package` отказал из-за отсутствующей registry version dependency.
Это не пригодный dependency path публикуемого ESKA crate. Выбор языкового host
[EF-17](analysis-kernel.md) сохраняется для анализатора; новый parser обслуживает
только узкий контракт версии. Его результаты не подменяют diagnostics host.
Лицензия проекта, версия crate и publication pipeline не менялись.

## Проверки

Пять групп unit-тестов проверяют обе схемы, mixed-case имя, английские keywords,
BOM/CRLF и точечную замену с повторным разбором. Отказы покрывают отсутствие,
процедуру вместо функции, дубли, неэкспортную сигнатуру, параметры, async,
аннотацию, условный scope, произвольные тела, неправильный номер и ошибочный
соседний синтаксис. При замене сохраняются другие литералы, комментарии и код.
Проверки здесь синтаксические; выполнение в 1С ещё не подтверждено.
