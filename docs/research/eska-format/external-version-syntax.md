# Синтаксический адаптер версии внешнего объекта — T84

Первый адаптер T84 реализован в общем `project_core::object_module_version`.
Он принимает текст BSL, возвращает общий `ProjectVersion`, диапазон функции и
точный диапазон числового содержимого литерала в исходных UTF-8 bytes.
Синтаксический план миграции и проверка связи с регистрацией БСП реализованы
в том же core. Файловые операции, CLI и реальная EPF/ERF приёмка ещё не подключены.
T84 остаётся `IN_PROGRESS`.

## Контракт

Требуется ровно одна экспортная функция `Версия()` без параметров, async и
компиляторных аннотаций. Она имеет одно выражение `Возврат` со строковым
литералом корректной схемы T83. Русские/английские keywords и регистр имени
поддерживаются. Комментарии и области разрешены; условные определения и
контекст вставки/удаления отказаны. Произвольные тела, склейка, скобки,
вычисление и несколько возвратов не считаются управляемым источником версии.

Parser разбирает весь модуль перед проверкой функции. Синтаксическая ошибка
соседнего кода отказывает; семантика соседнего кода не проверяется.
Комментарии, строки и обращения к одноимённым членам не объявляют функцию.
Ошибки содержат стабильный code и исходный byte range, без локализованных
сообщений parser. Отсутствующая функция указывает на EOF. Размер текста
ограничен 16 МиБ; BOM учитывается в координатах.

## Явная миграция и регистрация БСП

`plan_migration` принимает исходный текст и необязательную явно выбранную
начальную версию. Отсутствующая функция требует начального номера; пригодная
существующая функция сохраняет свой номер. Конфликт начального и существующего
значения отказан. План может добавить документированную экспортную функцию,
вставить `Экспорт` в пригодную закрытую сигнатуру и заменить один подтверждённый
литерал регистрации на `Версия()`. Другие тела и регистрационная логика не
переписываются. Пустой текст позволяет подготовить новый модуль.

Preview содержит виды правок, исходные byte ranges и точные замены. Применение
плана к изменившемуся тексту отказано; результат повторно проверяется.
Повторная миграция готового модуля возвращает пустой план. Запись файла пока
не реализована; чтение и импорт не выполняют эти правки.

`inspect_contract` проверяет также `СведенияОВнешнейОбработке()`, когда она есть.
Принят узкий профиль: одна экспортная функция без параметров/async/аннотаций,
один заключительный возврат локальной структуры; её создание — пустая
`Новый Структура` либо стандартная фабрика
`ДополнительныеОтчетыИОбработки.СведенияОВнешнейОбработке(...)`.
Версия задаётся ровно один раз прямым присвоением поля `Версия` либо
`Вставить("Версия", Версия())`; английский `Insert` также поддерживается.
Остальные прямые поля и вставки с постоянным ключом сохраняются.
Серверная условная оболочка регистрации допустима: это форма обработок
из playground. Сама `Версия()` остаётся безусловной.

Динамический ключ, переинициализация, второе присвоение версии, условная запись,
alias структуры, её передача аргументом, неизвестный mutator, `Выполнить` и
затенение имени `Версия` отказаны. Произвольные фабрики, вычисления и возвраты
также требуют ручного приведения к профилю. Это проверка конкретного
синтаксического контракта, без утверждения о семантике всего модуля или БСП.

## Выбор parser

Для этого узкого consumer используются опубликованные `tree-sitter` 0.27.1
с единственным feature `std` и `tree-sitter-bsl` 0.1.7, MIT по их manifests.
AST и поля берутся из [опубликованной BSL grammar](https://github.com/alkoleft/tree-sitter-bsl).
Regex не используется для обнаружения функции или замены литерала.

Прямое подключение закреплённого parser bsl-analyzer проверено локально:
`cargo package` отказал из-за отсутствующей registry version dependency.
Это не пригодный dependency path публикуемого ESKA crate. Выбор языкового host
[EF-17](analysis-kernel.md) сохраняется для анализатора; новый parser обслуживает
только узкий контракт версии. Его результаты не подменяют diagnostics host.
Лицензия проекта, версия crate и publication pipeline не менялись.

## Проверки

Тринадцать групп unit-тестов проверяют обе схемы, mixed-case имя, английские keywords,
BOM/CRLF и точечную замену с повторным разбором. Отказы покрывают отсутствие,
процедуру вместо функции, дубли, неэкспортную сигнатуру, параметры, async,
аннотацию, условный scope, произвольные тела, неправильный номер и ошибочный
соседний синтаксис. При замене сохраняются другие литералы, комментарии и код.
Дополнительные проверки покрывают создание и экспорт через явный план,
binding присвоения/Insert, конфликт начального номера, stale snapshot,
идемпотентность и отказы неподтверждённой регистрации. Форма стандартной фабрики
сверена с исходниками обработки в playground; пользовательские файлы не менялись.
Проверки здесь синтаксические; выполнение в 1С ещё не подтверждено.
