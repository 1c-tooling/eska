# Планы видов характеристик, счетов и расчёта

`ChartOfCharacteristicTypes`, `ChartOfAccounts` и `ChartOfCalculationTypes`
подключены к существующему `CanonicalMetadata::Object`. Общий адаптер сохраняет
обычные поля, табличные части, ownership и стандартные настройки. Новых crates,
зависимостей, индекса, XML-fallback или протокольных команд нет. Это продолжение
[объектной проекции процессов/задач](analyzer-process-objects.md) в EF-18.

## Реальные и неявные объявления

Каталог платформы выбирается по настоящему виду объекта. План счетов дополнительно
получает `Вид` / `Type` типа `ВидСчета` и `Забалансовый` / `OffBalance` типа Boolean,
как в закреплённом
[native reader](https://raw.githubusercontent.com/1c-tooling/bsl-analyzer/9021ba07471eee8a2614bed2105a2c8699f60780/crates/bsl-metadata/src/xml_parser/standard_attributes.rs).
Эти имена не добавляются в общий список стандартных имён других объектов.

`AccountingFlag` остаётся полем счёта. `ExtDimensionAccountingFlag` входит в строку
неявной таблицы `ВидыСубконто` / `ExtDimensionTypes`. Тип её `ВидСубконто` задаётся
ссылкой `ExtDimensionTypes` на план видов характеристик; отсутствующее/пустое
свойство сохраняет Unknown, неверная явная ссылка отклоняется.
[Нативная модель таблиц](https://raw.githubusercontent.com/1c-tooling/bsl-analyzer/9021ba07471eee8a2614bed2105a2c8699f60780/crates/bsl-metadata/src/xml_parser/catalog.rs)
использует nil UUID для неявной строки и её колонок. Адаптер сохраняет эту форму
ядра; общая исходная модель отдельно хранит настоящие UUID объявленных признаков.

Definition подтверждает реальные признаки по текущему physical kind и родителю.
У признака субконто физический родитель — план счетов, хотя BSL обращается через
неявную строку. Одноимённые признаки объекта и строки ведут к разным UUID.
Неявная таблица и её стандартные колонки не получают выдуманных YAML-целей.
Совпадение имени настоящей таблицы с неявной, как и неоднозначные реальные
объявления, не разрешается выбором первого UUID.

`DependenceOnCalculationTypes` разбирается в три различных режима: `DontUse`,
`OnActionPeriod`, `OnRegistrationPeriod`. Отсутствие означает независимый план.
Два режима по периоду включают стандартное поле `ПериодДействияБазовый` и три
неявные таблицы вытесняющих/ведущих/базовых видов с self-ref колонкой `ВидРасчета`.
Пустой/неизвестный явный token и дубли отклоняются с текущими координатами.
В реальных C2/C3 все шесть планов независимы; зависимые режимы проверены тестовыми
примерами. Работа этих режимов в клиенте 1С здесь не подтверждалась.

## Проверки

Этот замер относится к `09fe256`. Текущий контракт ошибок и проверки следующего
компонента описаны в [подробных причинах отказа моделей](analyzer-adapter-issues.md).

Пройдены 36 unit и шесть файловых тестов адаптера; 66 unit/file, 68 analyzer
process и девять checker process tests анализа, всего 143. Minimal profile — 54.
Все шесть adapter gates, 19 tool gates четырёх профилей и 15 root gates прошли:
fmt/check, строгие Clippy/Rustdoc, тесты и release builds. Root — 893 passed /
14 прежних ignored; minimal 165/3, project-cli 181/3, build-cli 200/3.
Регрессии отдельно проверяют оба уровня признаков с одинаковым именем,
редакторское переименование, invalid/close и неоднозначное физическое объявление.

Read-only `project_objects` сравнил все готовые модели десяти видов с независимыми
native parsers. Все 39 новых моделей совпали. Один план характеристик C1 содержит
неподдержанный `cfg:AnyRef`: корректный YAML остаётся доступным дереву, BSL-модель
имеет invalid и definition явно отказывает. Вместе с прежним справочником C1
неподдержанных моделей с этим типом теперь две; произвольного преобразования
`cfg:AnyRef` в известный `cfg:AnyIBRef` нет. Сохранилось прежнее исключение сравнения
синонимов табличных частей, где native reader выбирает XML-отступы.
Bytes 10/28/48 выбранных YAML/XML/control files проверены; оригиналы не записывались.

Шесть stdio-сценариев C1/C2/C3 в RU/EN выбрали все 4/13/23 новых владельца
на собственных частичных payload copies с полным составом. Подтверждены
284 definition и 284 независимых locate, 184 отказа, всего 468 definition requests.
Все 12 настоящих признаков счёта и девять признаков субконто проверены на каждой
locale. Текущие ranges/hash, UTF-16/byte positions, BOM/non-BMP/CRLF, editor authority,
invalid/close/refresh и locale parity согласованы. Недоступная BSL-модель C1
сохраняет parsed tree и не получает успешную definition-цель.

Bytes 8/17/27 выбранных оригиналов каждого сценария сохранены; собственные
payloads восстановлены и временные проекты удалены. Native XML не копировался
в проект сервера, PATH был пустым; normal exit не ждал stdin EOF. Остальные payloads
намеренно отсутствовали, semantic complete остаётся false. Peak RSS —
79656–254596 KiB; сценарий занял 0,25–2,26 s. Это ограниченный локальный замер.

CLI `bsl-analyzer-app` 0.3.0 проверил 101 уникальный BSL-фрагмент: ноль ParseError.
Workspace MCP недоступен, использован CLI fallback; platform help degraded,
проверка ограничена синтаксисом. Reference MCP подтвердил три режима зависимости.
Runtime graph прежний — 206 package names / 214 resolved versions; release server —
49111544 bytes. [Машинный отчёт](analyzer-chart-objects-results.json) содержит
gates и обезличенные результаты. Kernel patches не менялись.

## Ограничения

`cfg:AnyRef`, внешние источники данных, form data, predefined values, query text,
полная семантика, все IDE edits, общий heap/RSS budget и Explorer ещё в работе.
Квота source bytes не ограничивает всю память процесса. Настоящий VS Code client,
OS watcher и платформа 1С в этой части не запускались. EF-18 — `IN_PROGRESS`.
