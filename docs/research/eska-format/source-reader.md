# Чтение ESKA без XML-материализации

Внутренний `project_core::source_format::SourceReader` открывает только
`source.json` и `configuration.yaml`. Manifest проверяется целиком; объявленные
в корне владельцы связываются с его native paths и UUID. BSL, ресурсы, принятая
база и YAML остальных владельцев при открытии не читаются.

[Descriptor schema 2](readable-layout.md) использует именованные значения
и отдельные native slots. Declarations и semantic projection используют общие
schema paths с editor/source map, сохраняя native identities, logical parents
и semantic values. Legacy schema 1 продолжает читаться без миграции.

[Раздельное расположение EF-24](descriptor-layout.md) использует обязательные
native contexts карты версии 2. Форма, команда, макет и вложенная подсистема
получают собственные физические владельцы, прежнюю logical ancestry и native
UUID; inline части остаются внутри основного descriptor. Семейная версия 1
сохраняет прежний путь чтения. [Карта версии 3](resource-layout.md) дополнительно
объявляет физические пути модулей и ресурсов, сохраняя native identities.
`DeclaredModule.native_path` описывает путь для контекста ядра, ключ reader —
физический исходник. Измерения ниже относятся к семейному расположению.

`read_owner` читает текущий текст одного объявленного YAML. Проверяются профиль,
схема, UUID, тип/имя основного объекта, полный набор nested descriptors и их
объявления. Вложенные реквизиты, табличные части и отдельные описатели форм дают
типизированные факты с реальными родительскими UUID. Проекция строится из
`MetadataNode`, без генерации XML и повторного чтения его семантическим parser.
Opaque XML проверяется существующими правилами descriptor, без новой схемы.

`parse_owner` принимает несохранённый текст и выполняет те же проверки.
Корневые декларации можно переставить при сохранении прежнего набора,
классов, точных имён и multiplicity. Saved/unsaved metadata сохраняет этот
[порядок](child-order.md); разрешение экспорта проверяется отдельно.
Строгий YAML reader одновременно возвращает проверенную модель и CST;
читатель и точечный редактор используют один обход координат.
Диапазоны объекта и scalar `Name` задаются UTF-8 byte offsets. Они относятся
только к `OwnerSnapshot.path` и `source_sha256`; диапазон имени включает
его quoting или block syntax. Перевод в кодировку позиций LSP выполняет host.
Комментарии, Unicode, CRLF, flow mappings и порядок сериализованных полей
не заменяются поиском совпадающего текста.

Читатель хранит явный снимок manifest/configuration. При изменении этих двух
файлов потребитель открывает новый reader. Снимки содержат SHA-256 исходного
manifest; повторное чтение отдельного владельца всегда получает текущие байты
и новый source hash. Сохранённых CST, индекса дисковых YAML и собственного
file watcher здесь нет. Ошибка текущего YAML возвращается с его source path;
старый YAML и производный XML не являются fallback.

Отсутствие или повреждение другого владельца/ресурса откладывается до обращения
к нему. Успешное открытие дерева поэтому не означает пригодность к сборке.
Права и полную целостность проекта проверяют существующие accepted-base и
protected-export операции, включая межфайловые identity и все payload.
Working reader не читает политику поставщика и не предоставляет разрешений.
Новые inline [значения перечисления](enum-value-creation.md) читаются в saved/overlay
из авторитетного YAML; разрешение создания применяется только при protected export.

В выбранном пути проверяются обычные каталог/файл и каждый относительный
компонент; symlink и специальные файлы отвергаются до чтения. Каждый текст,
включая manifest, ограничен 64 MiB. Это граница обычного чтения, не новая
гарантия атомарного доступа при конкурентной подмене filesystem.

Публичные CLI/config/JSON пока не изменились. API экспериментальное, доступно
и в минимальной библиотеке без `legacy`. Следующие потребители — общая
проекция метаданных и IDE-host; публичный build подключается отдельно через
проверенное поколение.

## Проверки

11 новых обычных тестов проверяют отложенные ошибки, полную семью владельца,
родительские UUID, координаты, несохранённый текст, изменения файла/manifest,
отказ при потере nested descriptor, несовпадении declaration/identity,
дубликатах YAML, неявном добавлении владельца и filesystem aliases.
Ошибочный YAML не активирует лежащий рядом native XML.

Полные fmt/check/strict Clippy/test/Rustdoc и diff check прошли:
294 unit и 525 integration для приложения, 93 unit для минимального ядра.
Обычный прогон пропускает 13 opt-in тестов, минимальный — два.
Из них новый reader measurement выполняется отдельно на C1/C2/C3 в release.

## Реальные замеры

Release, один процесс и последовательное чтение всех владельцев без удержания
их снимков. Каждый запуск ограничен 4 GiB address space; это не лимит RSS.
Файлы берутся из собственных импортов EF-09, входы не изменяются.
OS page cache не сбрасывался; это не замер cold disk и не ускорение сборки.

Все три запуска прошли. Это подтверждает ограниченное открытие и чтение семей
из реального ESKA-состава; не является CF/клиентской приёмкой C2/C3. Проход всех
YAML занимает десятки секунд, поэтому host должен запрашивать владельцев
адресно. Manifest C2/C3 сам занимает около 45/53 MiB: его полное чтение остаётся
стоимостью открытия, без скрытого кеша. Принятая база и многогигабайтные payload
не входят в рабочую память reader.

Самый большой прочитанный owner — 0,61/5,04/4,78 MB соответственно. Подробные
JSON, параметры и вывод opt-in теста сохранены в собственном playground-каталоге
задачи; публичный отчёт не содержит частных имён конфигураций или объектов.
