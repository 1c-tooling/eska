# Объекты и табличные части в каноническом вводе

`metadata_object` в `eska-bsl-adapter` напрямую преобразует основной descriptor
справочника, документа, встроенной обработки или встроенного отчёта. Имена,
родные UUID, заимствование, типы реквизитов, порядок табличных частей и их полей
приходят из общей XML/YAML-проекции. У корня, табличных частей и их полей UUID
сохраняется в модели ядра. Обычный `Attribute` выбранного ядра не имеет слота
UUID; полный исходный идентификатор остаётся в общей модели ESKA.

Стандартные реквизиты берутся из каталога платформы закреплённого ядра, включая
его порядок и имена RU/EN. Условия появления определяются `CodeLength`,
`DescriptionLength`, `NumberLength`, `Hierarchical` и `Owners`. Числовой код/номер
сохраняет принятую ядром ограниченную точность; исходное значение длины остаётся
в YAML. Ссылки владельцев и регистров движений проверяются целиком: неизвестный
элемент, неверный QName или недопустимый target не отбрасывается молча.
Неверные явные длины, флаги и режимы дают отказ с исходными координатами.

Табличная часть сохраняет `Use`, свой UUID и UUID каждого поля. Настоящий синоним
берётся из локализованной общей модели. Ядро имеет один строковый слот: выбирается
`ru`, затем первый имеющийся язык; выбор не зависит от locale CLI. Все языки
остаются в исходном ESKA и доступны проектному API.

Закреплённый нативный reader использует `Synonym.text()` и возвращает пробелы
XML вместо содержимого `v8:content`. Отдельный тест воспроизводит дефект и
проверяет одинаковую каноническую модель при изменении XML-отступов. Поэтому
реальное сравнение явно исключает только этот слот, отдельно считая различия.
Совпадение остальных полей модели проверяется целиком; неизвестное непустое
значение caption у reference вызывает отказ сравнения, а не нормализацию.

Для типов СКД добавлены точные QName `SettingsComposer`/`Filter` из
`http://v8.1c.ru/8.1/data-composition-system/settings`. Переименование XML-префикса
не меняет тип, foreign namespace и неизвестный local name отклоняются.
Это namespace вне прежнего диапазона `/data/`; общая проверка других платформенных
типов не расширялась на произвольные namespaces.

[Результаты](object-adapter-results.json) включают 30 unit/шесть файловых тестов,
обязательные проверки библиотеки и C1/C2/C3. Пример `project_objects` запускается
с пустым `PATH` и читает оба корпуса без записи. Реальные замеры выполнены в
release-сборке; это время сверки обоих источников, не задержка запроса IDE.

| C1 | 231 | 2138 | 135 | 716 | 1 | 2,88 |
| C2 | 2289 | 27151 | 2254 | 16529 | 0 | 63,59 |
| C3 | 2995 | 37703 | 3096 | 22547 | 0 | 87,41 |

Во всех поддержанных моделях совпали все поля, кроме отдельно проверенного
синонима табличной части. Всего 5485 этих синонимов различаются из-за описанной
ошибки reference. У одного объекта C1 `TypeSet=cfg:AnyRef` не моделируется
выбранным ядром: его reader возвращает `UnknownNamed`, адаптер даёт явный
unsupported с исходным QName и координатами. `AnyIBRef` не подставляется вместо
него без подтверждения семантики. C1 завершился с exit 2; C2/C3 — с exit 0.

Сравнение ограничено основными descriptor четырёх видов. Формы, BSL-тела,
предопределённые элементы и остальные семейства не входят в полноту этой
проверки. Неподдержанный `TypeSet` явно учитывается отдельно и даёт exit 2.
Это компонент EF-18, а не готовый production analyzer/check.
