# Именованные наборы типов, десятая часть EF-24

Проверка [целей Type/TypeSet](type-targets.md) дополнена ограничением владельца:
`DefinedType.Type` не может содержать именованный `DefinedType` или
`Characteristic` текущей конфигурации. Отказ даёт `source_type_set_owner_invalid`
с UUID, свойством и индексом alternative до публикации. Wire, версия проекта,
правила поддержки и единственный источник editable values прежние.

## Основание проверки

На установленной 1С 8.3.27.2325 в отдельной копии C1 созданы два новых
определяемых типа, которые не используются реквизитами, формами или BSL.
Исходный числовой контроль собран в CF. Ссылка на себя, взаимные ссылки и
цепочка без цикла получили `Invalid type` на стадии `import_sources`.
Результат одинаков для native элементов `v8:Type` и `v8:TypeSet`.
Ссылка нового определяемого типа на существующую характеристику также
отвергнута с обеими записями; исходный контроль собран отдельно.

Отдельная новая константа подтвердила, что выбирать разрешения только по
native element name нельзя. `Type` с именем определяемого типа и `TypeSet`
с именем конкретной ссылки успешно собраны в CF. Свежая выгрузка платформой
нормализует их в `TypeSet` и `Type` соответственно. ESKA сохраняет исходную
запись без самостоятельной нормализации и разрешает её точечное редактирование.

Поэтому общий граф раскрытия типов этой частью не вводится. Подтверждённый
запрет вложенных именованных наборов строже проверки циклов в `DefinedType`
и не объявляет цепочку без цикла допустимой для платформы.

## Авторитет и границы

Набор определяется категорией native `GeneratedType` в объявленном дереве:
`DefinedType` у одноимённого класса метаданных либо `Characteristic` у
`ChartOfCharacteristicTypes`. Эти известные категории у другого владельца
дают `source_type_definition_invalid`. Prefix или семейство строки QName
не заменяют категорию. Неизвестные/отсутствующие категории сохраняют прежнюю
проверку существования имени; их семантика не заявляется.

Редактор использует самостоятельно проверенную accepted base и её namespace
scopes. Подмена рабочей native category не создаёт разрешений. Protected export
сначала восстанавливает forbidden edits, затем проверяет выбранные значения:
frozen invalid value восстанавливается, разрешённое invalid value отказывает.
Отказ не меняет исходники, base или pin и не создаёт готовую generation.

Импорт Designer XML сохраняет исходники для инспекции; он не является полной
проверкой семантики. Ошибка не позволяет принять такой package как trusted base.
Проверка включена в полное чтение package, принятие/open base, миграции и экспорт.
Адресный source reader и legacy preserved Type по-прежнему не обещают полного
анализа внутренних зависимостей.
Ранее допустимый typed package с вложенным именованным набором теперь отказывает
при полной проверке. Существующие pins и сохранённые значения не переписываются.

Bare sets, другие namespaces, неизвестные категории, раскрытие наборов и
взаимные зависимости характеристик не проверяются этой частью. Совместимость
зависимых форм/предопределённых данных и cross-qualifiers остаётся отдельной
работой. Structural create/delete/rename и публичная orchestration ещё нужны;
EF-24 сохраняет `IN_PROGRESS`, следующие этапы не запускаются.

## Проверки

Прошли 15 root/14 SDK/5 adapter gates: fmt/check/strict Clippy/test/Rustdoc,
minimal core и отдельные CLI. Root — 434 unit + 552 integration, 24 opt-in
пропущены; SDK — 359, adapter — 70 + 12.
Проверены обе descriptor schemas, обе alternative spellings, aliases/URI,
неизвестные категории, неверный native owner, CST preview, raw protected export,
невозможность подменить category, восстановление frozen values и отказ acceptance.
Платформенные probes работают только в собственных каталогах playground.

Свежая C1 сохранила native bytes и All-семантику 3 595 descriptors/8 330 объектов;
3 507 generated declarations и 1 129 Type/114 TypeSet alternatives прошли
проверку. Две прежние правки ссылочного и числового определяемого типа совпали
с независимым native control, прошли no-op и strict export без exclusions.
Оба маршрута собраны в CF и выгружены на 1С 8.3.27.2325: 8 769 файлов/
8 064 каталога равны, кроме 7 011 `ConfigDumpInfo.configVersion`.
Проверены artifact checksums; исходники, accepted base, исходный XML,
настройки и версия сохранены. Все 3 595 YAML прошли прежние JSON schemas.
