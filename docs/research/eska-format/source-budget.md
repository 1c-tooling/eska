# Общая квота текущих входов анализа

[500 циклов текущих YAML/form/BSL/query inputs](current-input-stress.md) прошли
на собственных EPF/ERF: source reserve, hashes, отказ нулевой квоты и точный
replay проверены на RU/EN. Debug RSS измерен отдельно; это не большой проект
и не общий предел памяти процесса.

Сессия IDE и `eska-check` используют одну квоту исходных байтов YAML/rights/BSL/`.sdbl`.
`SessionOptions.max_retained_source_bytes` и
`BatchOptions.max_retained_source_bytes` по умолчанию равны 256 MiB.
Checker задаёт её через `--max-retained-source-bytes`; локальный предел документа
64 MiB и отдельная квота BSL-текстов 64 MiB сохраняются.

Квота учитывает точный размер owning YAML для каждого текущего `Ready`
metadata snapshot, verbatim текст [прав роли](analyzer-roles.md) и размер каждого
текущего BSL-текста. Invalid rights XML остаётся читаемым ресурсом и занимает
свой резерв; unavailable ресурс его освобождает. `MetadataSnapshot.source_bytes`
получается из тех же verbatim UTF-8 bytes, что hash и координаты. Парсер метаданных
не хранит исходный текст целиком, поэтому это учёт размера входов, а не их heap.
Unsupported/invalid BSL-проекция не освобождает успешно разобранный YAML:
дерево и свойства продолжают его использовать, и его размер учитывается.

Перед чтением или разбором вычисляется оставшаяся общая квота. Замена может
повторно использовать место своего прежнего готового входа. Более строгий
резерв вызывающего кода и локальный предел документа сохраняются.
Недостаточная квота даёт `InputFailure::SourceBudgetExceeded`, заменяет текущий
вход на unavailable, очищает slot/текст ядра и освобождает прежнее место.
Accepted failure меняет общую ревизию и версию черновика. Stale request/document
version и обновление диска поверх черновика отклоняются без изменения квоты.
Закрытие перечитывает текущий диск и может снова столкнуться с недостаточной квотой.

`resources()` и поле `report.resources` показывают
`metadata_source_bytes`, `module_text_bytes`, `query_text_bytes`, `total_source_bytes`, `max_source_bytes`.
`query_text_bytes` учитывает текущие declared plain queries через тот же
replacement reserve; [query syntax](analyzer-query-syntax.md) не добавляет отдельной квоты.
`metadata_source_bytes` включает YAML и права роли, включая ресурс pending владельца.
Сумма текущих резервов не превышает установленный предел. Checker освобождает
независимо проверенное тело после syntax query, поэтому завершённый batch
обычно имеет нулевой `module_text_bytes`. Это не число всех проверенных байтов:
результаты файлов и их hash сохраняются отдельно.

В JSON metadata/module issues используют `analysis_source_budget_exceeded`.
Human output объясняет отказ на RU/EN и показывает текущий резерв и предел.
Неполная проверка возвращает exit 2. Settings hash по-прежнему относится
к диагностическим правилам; квота видна в отдельном поле ресурсов отчёта.
Поле ресурсов добавлено к schema 1 без изменения прежних значений.

## Ограничения

Квота не учитывает immutable composition, parsed heap, временные аллокации,
старые `Arc`, удержанные внешним потребителем, результаты запросов и memo Salsa.
Автоматического вытеснения чужих YAML-моделей нет. Это не общий бюджет памяти
или гарантия RSS. Дальнейшая работа должна отдельно ограничивать и измерять
удерживаемую память ядра и временные вычисления; EF-18 остаётся `IN_PROGRESS`.

Изменено неопубликованное Rust API: `InputRequest` получил необязательный
`source_budget`, `SessionOptions`/`BatchOptions` — общий предел,
`MetadataSnapshot` — исходный размер. Core контроллера может принять резерв
через `with_source_budget`; общий счётчик и расчёт оставшегося места принадлежат
сессии анализа. Проектное ядро не получает зависимости от анализатора.

## Проверки

Ниже — исходная приёмка YAML/BSL-квоты, до подключения прав. Текущие результаты
с ресурсами роли приведены в [приёмке роли](analyzer-roles.md).

Новый тест контроллера различает document limit и source quota для saved/overlay,
проверяет очистку и восстановление входа. Тест общей сессии заполняет квоту YAML
и BSL, отказывает соседнему модулю, очищает прежний canonical slot при большем
черновике, сохраняет stale update и восстанавливает модель после close.
Освобождение тела и повторное чтение YAML не накапливают резерв по ревизиям.
Process-тест проверяет одну общую квоту, machine code, оба языка и human warning.

Fmt/check/strict Clippy/test/Rustdoc прошли: 21 unit/файловой тест сессии,
девять process-тестов; minimal library — 21 тест. Основной набор приложения —
885 успешных тестов, 14 прежних ignored; minimal core — 161 и три ignored.
Project-cli/build-cli matrix также прошла. Новых зависимостей нет.

На C1 стандартная квота сохранила прежний результат checker: 1 975 проверенных
модулей, ноль syntax findings, явная неполнота моделей и exit 2. Текущий YAML
резерв составил 46 327 997 байт. При квоте 1 MiB удерживается 1 046 943 байта,
432 модуля проверены и 1 543 явно недоступны; syntax coverage неполная,
выход 2. JSON одинаков на обоих языках, исходники не изменены. Peak RSS около
528 MiB при стандартной квоте и 69 MiB при 1 MiB подтверждает, что эти метрики
имеют разный смысл. Полная семантика и клиентская приёмка 1С здесь не проверялись.
Замеры и gates — в [машинном отчёте](source-budget-results.json).
