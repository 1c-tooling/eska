# Канонические входы четырёх семейств метаданных

EF-18 расширяет проверенный вход Salsa до `CanonicalMetadata`: объект,
регистр, общий модуль и определяемый тип. Patch применяется только к отдельной
копии закреплённого ядра BSL; checkout reference остаётся неизменным.

Вход сопоставляется с главным `FileId` владельца. Resolver проверяет семейство,
имя и вид регистра. `None` означает недоступный вход: он не возвращает старую
модель и не обращается к XML. Source revision остаётся отслеживаемым входом.
Общий модуль доступен по имени и связи с BSL-файлом; определяемый тип возвращает
свой составной тип. Структурные индексы сохраняются, resolver соседнего семейства
не пересчитывается при адресной правке.

Прежний XML-вход сохранён, включая прямой путь общего модуля через его BSL-файл.
Новый resolver не добавляет к этому пути запросы и предупреждения.

```sh
python3 docs/research/eska-format/scripts/probe_canonical.py \
  --analyzer ../bsl-analyzer --family-inputs
```

[Результат](canonical-family-results.json) закрепляет версии и контрольные суммы
patch/consumer. Прошли сборка и strict Clippy consumer, strict Clippy изменённых
библиотек для всех targets, 179 unit-тестов `ide-db` и 30 `ide-host-core`.
Пять новых тестов проверяют семейства, несоответствие identity, отсутствие
fallback и адресную инвалидацию. Реальный consumer обновляет YAML в одном host
без XML-экспорта и без доступного Git/1С во время запуска.

Это готовность интерфейса ввода, а не полного адаптера YAML. Consumer пока
передаёт только имена справочников и прямых реквизитов с `Unknown` типами;
`metadata_complete=false`. Преобразование остальных свойств, конфигурации,
служебных объектов, ролей и форм, а также production host/check ещё не завершено.
