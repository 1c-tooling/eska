# Общая сессия метаданных

[`eska-analysis`](../../../tools/analysis-core/README.md) соединяет общий
контроллер saved/overlay, адаптер ESKA и локальное ядро BSL. Библиотеку используют
файловые тесты, read-only пример `project_session` и первый
[syntax checker](check-cli.md) и первый [transport метаданных IDE](analyzer-metadata.md).
Подключена [синхронизация документов](analyzer-documents.md), языковые операции
сервера ещё не подключены. Project core не получил
зависимостей от Salsa или анализатора.

`SourceReader` предоставляет проверенные идентичности и канонический корень
того же снимка состава, которым пользуется контроллер. При открытии регистрируются
устойчивые FileId и pending slot, без чтения других владельцев. Listing состава
и каноническая карта создаются один раз; обновление меняет только slot владельца.
Структурное изменение требует повторного открытия сессии.

Сохранённый файл и черновик проходят один parser и adapter. Invalid, missing,
cancelled и превышение локального лимита очищают текущую модель ядра. Старые
ревизии запросов и повторные версии документа отклоняются до изменения состояния.
Закрытие черновика перечитывает текущий диск; успешный предыдущий снимок не
восстанавливается из кеша. Координаты ошибки относятся к текущему YAML, его
fingerprint и ревизии владельца. Pending/unsupported не читают запасной XML.

Объекты, регистры и общие модули разрешаются реальными запросами ядра.
Определяемый тип проверяется `resolve_defined_type`; полный descriptor остаётся
в slot, поскольку ответ запроса содержит только underlying type.
Конфигурация пока предоставляет проверенный состав, без канонической модели.
Тест со счётчиками Salsa подтверждает: чужое обновление сохраняет индекс состава
и memo resolver соседнего объекта, нативный `parse_mdo_query` не запускается.

## Полнота и ограничения

`inputs.metadata_input_complete` сообщает о чтении всех объявленных YAML без
ошибок parser. `main_models_complete` дополнительно требует поддержанных главных
моделей. `descriptor_models_complete` учитывает все вложенные дескрипторы, которые
прочитал parser. Это не полнота BSL-анализа: ресурсы, предопределённые данные,
связи модулей и семантическая диагностика сюда не входят.

Пример сравнивает каждый kernel resolve с текущей моделью точным равенством,
отдельно считает unsupported/invalid и возвращает exit 2 при неполном покрытии.
Он не является публичной командой CI и не выдаёт неполный проект за проверенный.
Новые виды метаданных этим компонентом не добавлены; `AnyRef` C1 остаётся явным
ограничением адаптера объектов. Прежние native-пути reference не изменены.

Следующий компонент добавил [жизненный цикл BSL](bsl-session.md), диагностику,
completion и текущий YAML-снимок для дерева/свойств в этой же сессии. Общий
бюджет удерживаемой памяти, структурные правки и IDE transport ещё не реализованы.
Самостоятельный syntax checker добавляет deadline фазы анализа и освобождение
независимо проверенных тел; полная семантическая проверка пока не подключена.
Для выполняющихся запросов подключена [кооперативная отмена](query-cancellation.md).
Сессия пока сохраняет разобранные модели запрошенных YAML; локальный byte limit
не ограничивает RSS всего процесса. EF-18 остаётся `IN_PROGRESS`.

## Проверки

При приёмке первого компонента шесть файловых тестов проверили ленивое открытие, все подключённые семейства,
saved/overlay/close, текущие координаты adapter failure, stale/duplicate requests,
отмену, byte limit и адресную инвалидацию Salsa. Собственные fmt/check/strict
Clippy/test/Rustdoc и release-сборка примера прошли. Основное приложение прошло
полный набор: 883 теста, 14 прежних ignored; минимальная библиотека — 159 passed
и три прежних ignored. Изменённые reader API проверяются тестом основного core.

Все kernel resolve совпали с текущими моделями. Чтение YAML полное, модель
проекта неполная; каждый запуск ожидаемо завершился с exit 2.

| Корпус | YAML-владельцы | Разрешённые модели | Unsupported | Invalid | Время, с | Max RSS, MiB |
|---|---:|---:|---:|---:|---:|---:|
| C1 | 2 645 | 1 265 | 1 378 | 1 | 10,41 | 120,8 |
| C2 | 16 286 | 9 779 | 6 506 | 0 | 108,28 | 1 215,5 |
| C3 | 18 752 | 11 692 | 7 059 | 0 | 135,94 | 1 590,8 |

Замер выполнен release-примером, Max RSS получен через `/usr/bin/time`.
Он отражает удержание всех прочитанных YAML, а не типичный IDE-запрос к одному
объекту. Наличие данных по памяти не означает выполненный бюджет RSS.
Результаты read-only запусков на C1/C2/C3 и параметры замера записаны в
[машинном отчёте](shared-session-results.json). Исходники, принятые базы и рабочие
ИБ не изменяются. Runtime PATH пуст: пример не запускает платформу, Git или IDE.
Эти проверки описывают метаданные сессии; приёмка поведения в клиенте 1С ими
не утверждается.
