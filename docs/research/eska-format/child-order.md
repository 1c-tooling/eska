# Порядок существующих дочерних объектов

В EF-24 можно вручную переставлять существующие элементы `children` в семейном
или читаемом YAML. Общий protected selector переносит разрешённый порядок в
native `ChildObjects`; `eska-project prepare` и `eska-build build` используют
тот же selector. Новая команда или отдельный режим экспорта не нужны.

## Правила выбора

Состав каждой коллекции должен остаться прежним. Inline-элемент определяется
родным UUID, внешняя декларация — точными metadata kind и именем. Замена UUID,
дублирование, создание, удаление, переименование и перенос между владельцами
не считаются перестановкой и не получают разрешения через этот механизм.
Native class и форма хранения сохраняются в каждой позиции: нельзя перенести
форму в позицию реквизита или заменить inline-элемент внешней декларацией.

Проверяются принятые права владельца коллекции и каждого элемента, изменившего
позицию. Для внешней декларации UUID берётся из её принятого descriptor по
native path, включая вложенные формы и подсистемы. Рабочие значения `uuid`,
`kind`, имена каталогов и отображаемая поддержка не создают разрешений.
Freeze стационарного элемента допускает перестановку соседей, если его индекс
сохранился. Freeze перемещаемого элемента запрещает перестановку коллекции.
Если есть preserved child, порядок всей этой коллекции остаётся принятым:
неизвестная native семантика не выводится из окружающих известных объектов.

Разрешённые свойства выбираются по UUID до выбора порядка. Запрещённая
перестановка поэтому не теряет независимую разрешённую правку соседнего объекта.
При отказе восстановленный порядок получает одну диагностику с операцией
`{"kind":"reorder"}`. Для поддержки/freeze она содержит действительный UUID
запрещённого владельца или перемещаемого элемента. Другие запрещённые raw-правки
сохраняют свои диагностики.

Strict отказывает до публикации поколения. Явный `--allow-exclusions` возвращает
диагностики и результат с восстановленным порядком. Рабочие YAML, `source.json`,
accepted blobs, native evidence и pin не переписываются. Повторная подготовка
тех же входов использует проверенное готовое поколение.

## Чтение и происхождение

Saved/unsaved reader сохраняет порядок YAML в `All` и `Summary`. Несохранённый
корень может переставить прежние декларации; проверка его состава сравнивает
набор с multiplicity, точными именами и классами, а не порядок. Добавление или
переименование декларации по-прежнему получает `source_declaration_mismatch`.
Чтение рабочего текста само по себе не разрешает его экспорт.

Source map сохраняет принятые native bindings и состав. `uses_working_values`
отмечает также выбранный рабочий порядок. Диапазоны изменённых свойств
находятся по фактическому UUID в рабочем YAML после перестановки, а не по
старому индексу. Флаг не объявляет весь рабочий файл разрешённым.

Версии descriptor/reverse map/source map/rules, tool envelope и IDE protocol
не меняются. Экспериментальный `Operation` получил вариант `Reorder`; JSON
exclusions получил дополнительное значение `kind = "reorder"`. Имена и
параметры публичных команд сохранены. Создание/удаление/переименование остаются
следующей частью EF-24; CST-команда или UI для изменения порядка не добавлены.

## Проверки

Девять новых core tests, два integration tests и один CLI integration test
проверяют обе YAML-оболочки, повторное поколение, поддержку родителя/детей,
stationary/displaced freeze, смешанные свойства/порядок, класс позиции,
preserved child, смену состава/UUID, saved/unsaved корень и source locations.
CLI проверен на ru/en с одинаковым JSON, strict отказом до публикации и
восстановлением при явном разрешении exclusions.

Прошли 16 root gates: fmt/check/strict Clippy/default и all-features tests,
Rustdoc и minimal core/project-cli/build-cli boundaries. Основной набор —
455 unit + 554 integration; 24 opt-in tests пропущены обычным запуском.
All-features включает 17 project CLI и 9 build CLI tests. Прошли также
14 SDK gates (359 tests) и пять gates адаптера BSL (70 unit + 12 integration).
Standalone release project/build binaries собраны с `--locked`.

Реальная C1: четыре перестановки значений перечисления, реквизитов, форм и
корневых деклараций в трёх YAML совпали с независимым native контролем по
8 778 файлам/8 077 каталогам, exclusions — 0. Замороженный элемент сохранил
позицию; отдельный отрицательный сценарий подтвердил отказ при его перемещении
и точное восстановление порядка с сохранением остальных правок. Обе локали,
повторное поколение и самостоятельный release CLI без платформы/Git/оболочки
проверены; исходные рабочие/принятые/native байты и manifest не изменились.

Saved/unsaved проекции всех 3 595 descriptors/8 330 объектов C1 совпали с
независимым XML-контролем в `All` и `Summary`, включая новый порядок.
Обе CF собраны и повторно выгружены через ESKA на 1С 8.3.27.2325:
8 769 файлов/8 064 каталога равны, кроме 7 011 `configVersion`.
Проверены checksums artifact manifests, source map schema 2 и отдельный pin;
input/base/settings/исходный XML и версия конфигурации сохранены.
[Обезличенные результаты](child-order-results.json).
C2/C3, новые CFE/EPF/ERF, клиент, обновление рабочей ИБ и полный анализ BSL
этой проверкой не принимаются. EF-24 остаётся `IN_PROGRESS`.
