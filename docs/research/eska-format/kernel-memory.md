# Наблюдения памяти общей сессии

Проверено 2026-10-09. `AnalysisSession::kernel_memory()` предоставляет
существующую статистику закреплённого ядра BSL через ту же сессию YAML/BSL.
Платформа, XML, Git и IDE transport не участвуют. Production API сессии
экспериментальный; ни CLI-параметры, ни JSON checker не изменены.
С 2026-10-11 эти же оценки доступны через
[`eska/analysis/memory`](analyzer-kernel-memory.md); прежний замер ниже относится
к SDK и ограниченному рабочему набору.

Для каждой таблицы возвращаются имя реализации, число instances (`entries`),
`metadata_bytes`, `field_stack_bytes` и `heap_bytes: Option<usize>`.
Имена могут повторяться. Таблицы отсортированы по полным значениям: name,
entries, metadata_bytes, field_stack_bytes, heap_bytes. `None` означает
недоступную aggregate-оценку, `Some(0)` — нулевой вклад, в том числе у memo
с вытесненным значением. Счётчик entries включает такие memo; это не число
живых parse trees. Смешанный aggregate может не учитывать values без hook.
В отчёте отдельно показаны число null-оценок, число таких таблиц с entries>0
и сумма доступных heap estimates. Схема отчёта не менялась.
Снимок сопровождается текущим `SessionRevision`.

Чтение статистики не оценивает tracked queries, не читает файлы, не меняет
исходники, ревизию или [квоту входов](source-budget.md). Тест подтверждает пустые
parse tables до анализа и заполненную таблицу после реального syntax query.
После `trim_batch_caches()` текущие входы, ревизия и диагностика сохраняются.
Отдельно исправлено [освобождение reparse hints](kernel-parse-release.md)
недоступных модулей: они хранились вне Salsa и не учитывались этим отчётом.
В [пакетную очистку](kernel-source-sweep.md) включено также окно source-text
memos. Исторический замер 40 модулей ниже не превышает sweep cap 64;
новое сравнение использует 128 модулей каждого состава.

Размеры таблиц не дают общий memory budget. Один Arc может участвовать
в нескольких estimates; есть таблицы без hook и объекты вне Salsa:
composition, YAML-модели, parse snapshots, временные вычисления, allocator.
Сумма estimates не является RSS, точным heap или его гарантированной границей.
Имена таблиц отражают закреплённую реализацию ядра и не являются стабильными
идентификаторами будущего IDE protocol.

## Read-only C1

Пример `project_memory` загрузил все объявленные YAML, затем первые 40 текстовых
модулей из упорядоченного состава. Выполнен только профиль `syntax`.
Это ограниченный рабочий набор, а не проверка всех модулей C1.

| Состояние | Сумма heap estimates, bytes | Parse entries | Живые таблицы без hook |
|---|---:|---:|---:|
| Открытие состава | 2760227 | 0 | 1 |
| YAML загружены | 3928090 | 0 | 1 |
| 40 модулей проанализированы | 7838473 | 40 | 4 |
| Тексты модулей освобождены | 7366310 | 40 | 4 |
| Глубокий LRU trim | 7355110 | 40 | 4 |

Тексты занимали 472163 bytes текущей квоты; после release этот счётчик равен
нулю. YAML резерв сохранился — 46327997 bytes. При этом parse memo и вычисленные
строки оставались в ядре: release текста и LRU trim не означают полное
освобождение вычислений. Именно этот случай нужен дальнейшей политике памяти.

Пиковый RSS — 157320 KiB, время процесса — 7,87 s. Это один release-замер,
пиковый RSS не показывает RSS каждого промежуточного состояния.
После запросов без heap hook остаются `FeaturesInput` и interned arguments
трёх семейств диагностики. Доступные оценки нельзя использовать как точный
лимит процесса или обещание предотвращения OOM.

Проверены все 7829 файлов до и после запуска: байты одинаковы. `PATH` пустой.
Выход 2 отражает прежнюю неполноту моделей метаданных; она не исчезает при
успешном анализе выбранных 40 тел. Установленная платформа 1С не запускалась:
в этой части не меняются экспорт и сборка.

## Проверки и воспроизведение

В отдельном workspace прошли fmt/check/strict Clippy/Rustdoc, 22 unit/file tests
и 9 process tests checker; минимальный профиль также прошёл 22 теста и Clippy.

```bash
ESKA_TEST_ROOT="$(realpath ../eska-playground)" cargo test --manifest-path tools/analysis-core/Cargo.toml --all-features --locked
cargo run --manifest-path tools/analysis-core/Cargo.toml --release --locked --example project_memory -- /path/to/eska/source
```

Анонимизированные результаты и gates — в [машинном отчёте](kernel-memory-results.json).
