# Процессы, задачи и планы обмена в анализаторе

`metadata_object` и общая сессия анализа принимают `BusinessProcess`, `Task`
и `ExchangePlan` из текущего YAML. Это расширение прежней
[проекции объектов](object-adapter.md); экспериментальный ESKA protocol 0.1
и действующий IDE protocol 1.x не меняются.

## Граница модели

Используется существующий `CanonicalMetadata::Object`, без нового индекса,
XML-fallback или зависимостей. UUID, ownership, обычные реквизиты, порядок
табличных частей и типы колонок сохраняются тем же адаптером. Стандартные поля
выбираются по действительному виду объекта и настройкам из закреплённого
[каталога ядра](https://raw.githubusercontent.com/1c-tooling/bsl-analyzer/9021ba07471eee8a2614bed2105a2c8699f60780/crates/bsl-metadata/src/xml_parser/standard_attributes.rs).
Неявный стандартный реквизит без настоящего YAML-объявления не получает
выдуманный UUID или диапазон. Некоторые его типы остаются `Unknown` в соответствии
с reference; полнота семантики из готовности модели не следует.

`AddressingAttribute` задачи преобразуется в типизированный реквизит модели ядра,
как в закреплённом
[native reader](https://raw.githubusercontent.com/1c-tooling/bsl-analyzer/9021ba07471eee8a2614bed2105a2c8699f60780/crates/bsl-metadata/src/xml_parser/catalog.rs).
Исходник сохраняет отдельный kind и настоящий UUID. При definition общая сессия
подтверждает именно текущий дочерний объект задачи. Совпадающие обычный и адресный
реквизиты дают неоднозначность, а не переход к первому. Это правило не распространяет
адресные реквизиты на другие виды объектов или строки табличных частей.

Исправный descriptor с неподдержанным типом остаётся unavailable для канонической
модели. Отсутствующие обязательные типы и неверные UUID имеют исходные координаты.
Root definition, typed реквизиты, таблицы и колонки используют прежние запросы
и общий metadata locate. Saved/editor/close сохраняют одну ревизию и authority.

## Проверки

Пройдены 32 unit и шесть файловых тестов адаптера; 62 unit/file, 67 analyzer
process и девять checker process tests анализа, всего 138. Minimal profile — 50.
Все шесть adapter gates, 19 tool gates четырёх профилей и 15 root gates прошли,
включая fmt/check, строгие Clippy/Rustdoc, тесты и release builds.
Root: 893 passed / 14 прежних ignored; minimal 165/3, project-cli 181/3,
build-cli 200/3. Отдельные регрессии проверяют редакторское переименование
адресного реквизита и отказ при совпадении двух дочерних видов.

| Корпус | Процессы | Задачи | Планы обмена | Добавленные модели | Все семь поддержанных видов |
| --- | ---: | ---: | ---: | ---: | ---: |
| C1 | 0 | 0 | 1 | 1 | 232 |
| C2 | 9 | 1 | 26 | 36 | 2325 |
| C3 | 9 | 1 | 29 | 39 | 3034 |

Read-only пример `project_objects` сравнил все 76 новых моделей с независимыми
native parsers: различий и новых неподдержанных типов нет. Контроль прежних видов
сохранил известный неподдержанный `cfg:AnyRef` C1 и исключение сравнения синонимов
табличных частей: native reader ошибочно выбирает XML-отступы. Все остальные
поля готовых моделей совпали. Bytes 4/74/80 выбранных YAML/XML/control files
проверены до и после; экспорт XML и запись оригиналов не выполнялись.

На собственных частичных копиях с полным составом C1/C2/C3 прошли шесть stdio
сценариев в RU/EN. В каждом загружены все добавленные владельцы: 1/36/39.
Подтверждены 764 definition и 764 независимых locate, 292 отказа для неявных
стандартных полей и unavailable входов; всего 1056 definition requests.
Проверены текущие UUID/parent, hashes, UTF-16/byte ranges, non-BMP/BOM/CRLF,
editor authority после удаления файла, очистка целей при invalid YAML и close
отсутствующего файла. Восстановленный saved файл загружен явным `metadata/refresh`:
обычный read не перечитывает уже unavailable вход. Locale traces совпали.

Оригинальные bytes 5/40/43 выбранных файлов каждого сценария сохранены;
собственные payloads восстановлены и временные проекты удалены. PATH сервера
был пустым, native XML в его проекте отсутствовал. Остальные payloads намеренно
не копировались; semantic complete остаётся false. Peak RSS — 68924–257848 KiB,
время сценария — 0,15–4,58 s. Это локальные ограниченные замеры, не memory SLA.

Установленный `bsl-analyzer-app` 0.3.0 проверил 183 уникальных BSL-фрагмента:
ноль ParseError. Workspace MCP недоступен; использован CLI fallback. Проверка
ограничена синтаксисом и не подтверждает работу фабрик в платформе 1С.
CLI сообщил degraded platform help, поэтому описания API им не подтверждались.

Runtime graph прежний: 206 package names / 214 resolved versions. Release server —
49101024 bytes. [Машинный отчёт](analyzer-process-objects-results.json) содержит
gates и обезличенные результаты; существующие kernel patches не изменялись.

## Что остаётся

Планы видов характеристик, счетов и расчёта ещё не проецируются этим адаптером.
Form data, predefined values, query text, полнота inference/анализа, все IDE edits,
общий heap/RSS budget и Explorer ещё в работе. Настоящий VS Code client, OS watcher
и платформа 1С в этой части не запускались. EF-18 остаётся `IN_PROGRESS`.
