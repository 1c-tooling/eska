# Очистка принятого списка ссылок — EF-24, часть 16

Принятый непустой `reference_list` разрешено заменить на `Empty`. Это позволяет
убрать последнюю ссылку, в том числе вместе с зависимым структурным изменением.
Работают family schema 1 и readable schema 2, общий reader, protected preparation,
точечный editor API и самостоятельный `eska-project`.

## Значение и служебные bindings

В readable YAML меняется только именованное значение:

```yaml
Owners: {state: empty}
```

Существующий native slot с `references` можно оставить точно таким, как в
accepted base, либо заменить каноническим bare name. Оставленные prefixes
не записывают XML и не становятся второй редактируемой копией значения.
Protected selector сравнивает их с принятыми bindings: изменение prefix или
порядка служебной секции остаётся исключением. При `--allow-exclusions` выбирается
разрешённое `Empty`, а изменённые служебные данные не используются.

Для family schema 1 всё прежнее значение меняется на `{state: empty}`.
Оба варианта генерируют самозакрывающееся native свойство, например `<Owners/>`.
Пустой массив, отсутствие поля и `Nil` не подменяют это значение.

Профиль распространяется на уже типизированные списки: `DefaultRoles` у
Configuration, `Owners` у Catalog, `RegisterRecords` у Document/Sequence и
`Content` у Subsystem. Исходно preserved свойства не становятся редактируемыми.
Новый list из изначально пустого свойства не получает выдуманных bindings;
переход принятого list в `Nil` остаётся неподдержанным.

## Защита и происхождение

Права на свойство вычисляются по принятому UUID и native support/freeze.
Запрещённая очистка восстанавливает прежний список. Проверка ссылок выполняется
по окончательному выбранному составу, после восстановления запрещённых правок.

`prepare_property_edit` и preview по несохранённому тексту меняют только CST
значения, сохраняя соседние байты и EOL. Если очистка потеряет комментарий внутри
удаляемого значения, editor отказывает; автор может разрешить это вручную.
Native slot не переписывается. Source map адресует рабочий `Empty`, а reader
проецирует его непосредственно в прежнюю модель метаданных.

Схемы manifest/descriptor, публичные команды, JSON envelope и версия проекта
не меняются. Старые эксперименты не мигрируют автоматически.

## Проверки

Unit matrix проверяет пять owner profiles, сохранение native bindings и отказ
при `Nil`. Integration tests покрывают обе оболочки, raw YAML и точечный editor,
freeze, исключение служебных правок, saved/unsaved All/Summary, working locations,
канонический `Empty`, повторное поколение и неизменность входов. CLI test
проверяет реальные процессы и одинаковый JSON/exit code в ru/en.

Полные root gates: 479 unit + 561 integration, 24 opt-in пропущены обычным
запуском. Minimal project — 286 unit + 22 CLI tests, SDK — 359, adapter —
70 + 12. Fmt/check/strict Clippy, tests, Rustdoc и feature boundaries прошли.

Четыре очистки C1 в четырёх YAML сохранили все прежние native bindings.
Независимый XML-контроль совпал по 8 778 файлам/8 077 каталогам; все 3 595
descriptors/8 330 объектов совпали в saved/unsaved All/Summary. Обе версии
собраны в CF и повторно выгружены на 1С 8.3.27.2325: 8 769 файлов/8 064
каталога равны, кроме 7 011 `configVersion`. Checksums, inputs, settings,
manifest и версия проекта сохранены. [Результаты](reference-clear-results.json).

Отдельный native probe с очисткой `RegisterRecords` оставил регистр без единого
документа-регистратора и получил отказ платформы на import_sources. Положительная
приёмка использовала другой документ, у регистров которого остаются регистраторы.
Специфические ограничения состава регистраторов пока проверяет платформа при
сборке; typed reference index не подменяет эту проверку. Новые CFE/EPF/ERF,
клиент и изменение данных рабочей ИБ этой частью не принимаются.

EF-24 остаётся `IN_PROGRESS`: rename, прочие structural profiles, составные
домены и workspace migration ещё нужны.
