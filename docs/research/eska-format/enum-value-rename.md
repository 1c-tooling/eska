# Переименование значения перечисления — EF-24, часть 17

Принятый inline `EnumValue` допускает ручную правку `Name` в family/readable YAML
с прежними UUID, владельцем, class и native slots. Manifest, hashes и обратная
карта не редактируются. Общий protected selector используется существующими
`eska-project prepare` и `eska-build build`.

## Профиль и права

Нативный владелец — принятый корневой `Enum` данного descriptor; значение — его
прямой принятый inline child. Поддержан закрытый профиль `Name`, `Synonym`,
`Comment` без дополнительных namespaces/attributes, children или opaque секций.
Замена UUID или class рабочего узла не разрешает переименование старого значения.

Нужны `Reorder` владельца и `Rename` значения, рассчитанные по independently
pinned native policy и freeze. Freeze владельца/предка или самого значения
восстанавливает прежний Name; stationary frozen sibling этому не препятствует.
Права отдельного собственного значения не обходят locked namespace поставщика.
Разрешённые независимые свойства и порядок обрабатываются своими правилами.

Лексика имени совпадает с профилем создания: Unicode letter или `_` в начале,
затем letters/digits/`_`. Полные ограничения платформы по длине/семантике не
заявляются. Коллизии проверяются после выбора состава через `to_lowercase`.
Можно поменять имена местами, переименовать старое значение и создать новое
с освободившимся именем либо удалить прежнего носителя нового имени в той же
разрешённой операции. Проверка ссылок использует окончательный выбранный состав.

Экспериментальный `permission(EnumValue, Rename)` теперь разрешает необходимый
профиль операции, но не заменяет selector. `Property(Name)` остаётся запрещённым;
обычный точечный property editor не становится structural editor. Дополнительная
CST/CLI-команда переименования не добавлена. Другие классы требуют своих профилей.

Неприменённая правка Name принятого EnumValue диагностируется как `rename`,
а при отказе владельца указывает его UUID. Прежний JSON envelope и варианты
`Operation` сохраняются; классификация этой экспериментальной диагностики меняется.
Strict не публикует поколение. Явный `--allow-exclusions` восстанавливает имя,
сохраняя независимые разрешённые изменения и исходные авторские байты.

## Зависимости

Typed reference index проверяет имена по выбранным descriptors. Старая ссылка
на отсутствующий полный путь отказывает; разрешённая правка ссылки в том же
составе проходит, запрещённая правка восстанавливает прежнюю зависимость.

Общий guard для удаления и rename проверяет decoded preserved XML и выбранные
XML payloads. Удаление инвалидирует UUID и полный путь имени. Rename оставляет
UUID действительным и инвалидирует прежний `Enum.<owner>.EnumValue.<name>`.
Изменение только регистра символов сохраняет прежний namespace ключ по
`to_lowercase` и не инвалидирует такие ссылки.

Оставшееся упоминание старого полного пути отказывает с
`source_structural_reference_preserved`; непроверяемый XML — с
`source_structural_xml_unverified`. Поиск консервативен и может отклонить текстовое
упоминание или более длинную строку с прежним путём. Unknown inverse semantics
не угадывается. Запрещённый payload fix не скрывает принятую зависимость.
ConfigDumpInfo исключён как производный index; comments/PI не являются ссылками.

BSL/SDBL-обращения, вычисляемые ссылки и бинарные/non-XML resources этой проверкой
не принимаются. Их проверка относится к анализатору и отдельной runtime приёмке.
Автоматическое переписывание BSL и UI не входят в EF-24.

## Чтение и проверки

Saved/unsaved reader возвращает новое имя с прежним UUID в All/Summary.
Source map разрешает рабочие координаты Name по identity; прежние схемы,
native пути, source origins и transport сохранены.

Core tests проверяют оба формата, identity/class/profile, namespace/value freeze,
поставщик, коллизии и повторное имя в окончательном составе, независимый порядок,
typed/decoded references, выбранные XML bytes, reader, source locations и входы.
CLI tests проверяют реальные процессы, freeze/refusal и одинаковый JSON в ru/en.

Прошли 16 root/14 SDK/5 adapter gates и оба release build: 493 unit + 562
integration, 24 opt-in пропущены; minimal project — 300 unit + 24 CLI tests,
SDK — 359, adapter — 70 + 12. Добавлены 14 core, один supplier integration
и два CLI tests.

Три переименования C1 в одном YAML, включая английское/кириллическое имя и
смену только регистра, совпали с независимым native контролем по 8 778 файлам/
8 077 каталогам. UUID, bindings, manifest, settings и pin сохранены. Отдельный
frozen value отказал в обеих локалях; явное восстановление сохранило три
разрешённые правки. Все 3 595 descriptors/8 330 объектов совпали с контролем
в saved/unsaved All/Summary.

Существующая ссылка `FillValue` на прежнее полное имя другого значения C1
отказала в strict/exclusions и ru/en без публикации. Сохранение зависимости по
UUID проверено core-тестами; реальный UUID-reference сценарий этой частью не принят.
Контроль и ESKA собраны в CF и выгружены на 1С 8.3.27.2325: 8 769 файлов/
8 064 каталога равны кроме 7 011 configVersion, checksums/inputs/версия сохранены.
[Обезличенные результаты](enum-value-rename-results.json).

EF-24 остаётся `IN_PROGRESS`: другие structural profiles, составные домены
и workspace migration ещё нужны.
