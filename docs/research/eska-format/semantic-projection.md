# Одна модель метаданных для XML и YAML

`project_core::metadata_model` содержит существующие `MetadataObject`,
`ObjectId`, свойства, значения и project/node scopes. Pure XML parser и
predefined parser находятся в `project_core::metadata_parser`. Они доступны
без `legacy`, не открывают проект, не читают диск и не вызывают платформу,
Git или IDE runtime. Прежние XML-потребители используют эту же реализацию;
загрузка через `DesignerSource` остаётся в соответствующем resolver.

`SourceReader::read_metadata` и `parse_metadata` выдают те же
`ParsedDescriptor`/`ParsedObject`/`MetadataProperty`/`MetadataReference`.
Один YAML содержит отдельную проекцию каждого исходного native descriptor:
например, catalog и его form имеют общий source path, но свои native paths
и логических владельцев. Основной объект, inline hierarchy и внешние ссылки
сохраняют порядок деклараций. Перестановка nested descriptors не заменяет
вычисление родителя их порядком в массиве.

`ObjectId` сохраняет прежние правила: configuration collections не получают
префикс configuration, вложенные объекты наследуют логический ID владельца,
имена экранируются и нормализуются тем же способом. Родной UUID сохранён
отдельно; identity хранения ESKA не подменяется меняющимся при rename
`ObjectId`. Коллизии логических имён видны через общий `DuplicateIdentity`,
а не через случайно выбранный объект или новый идентификатор.

Typed свойства читаются непосредственно из `PropertyValue`. Empty и nil
имеют существующее семантическое представление пустого значения; nil сохраняет
явный xsi:nil qualifier. Для непрозрачных свойств используется тот же reader
`QName`, record, localized и unsupported values, что и у исходного XML.
Namespaces восстанавливаются одним envelope helper с правилами validation;
весь native descriptor или проект ради проекции не материализуется.

`PropertiesMode::Summary` не включает полный список свойств в результат,
но содержит объекты, синонимы и ссылки для дерева. `All` добавляет все
семантически доступные свойства. Strict source validation выполняется в обоих
режимах; Summary не предоставляет право собрать повреждённый источник.

Ranges в YAML-проекции относятся к исходному object/property/reference mapping,
а не к XML tag. Внутренний дефект opaque XML указывает на содержащий его YAML
property; точный offset внутри decoded XML string не выдумывается.
Все обнаруженные unsupported issues сохраняются, в том числе несколько внутри
одного property. `MetadataSnapshot.path`, `source_sha256` и `manifest_sha256`
определяют координаты, включая несохранённые правки.

Новых dependencies, публичных CLI/config/JSON и поведения XML-команд нет.
Экспериментальное библиотечное API стало доступно через `project_core`;
`ObjectId::renamed` и pure predefined parse доступны самостоятельным
потребителям без приложения. Это не утверждённый стабильный SDK.

## Проверки

Шесть новых обычных тестов сравнивают все семантические поля исходных XML
и YAML в режимах Summary/All, изменяя при сравнении только координаты.
Проверены вложенные родители, ссылки, пустое/nil, локализованные значения,
точные числа, неизвестные поля, rebound `QName`, несколько вложенных issues,
collisions и несохранённые значения с координатами YAML.

Полные fmt/check/strict Clippy/test/Rustdoc и diff check прошли в обеих
сборках: 300 unit и 525 integration для приложения; 114 unit для минимального
ядра. Обычный прогон пропускает 14 opt-in тестов, минимальный — три.
Проверка реальных корпусов запускается отдельно в release, с независимо
вычисленными родителями из исходных XML и без удержания всей разобранной модели.

Все шесть реальных проверок прошли: сравнивались все поля исходных XML и
YAML-проекции, кроме диапазонов, которые принадлежат разным исходникам.
Родители отдельно получены обходом деклараций оригинального XML, а не взяты
из проверяемой YAML-проекции. Для каждого режима проверен полный объявленный
состав, без чтения BSL/ресурсов или принятой базы.

Это проверка метаданных и координат, не BSL diagnostics или платформенная
приёмка. Время включает независимый XML-обход, обе проекции и сравнение;
его нельзя выдавать за время IDE-открытия или выигрыш формата.
Release, Linux, один процесс; 4 GiB address-space ceiling; OS cache не сбрасывался.
Параметры и JSON/вывод сохранены в собственном playground-каталоге задачи.
