# BSL и метаданные в одной сессии

`eska-analysis` использует одну базу ядра для текущих YAML и BSL. Новый
`SessionRevision` меняется при каждом принятом обновлении, включая неудачное
чтение. Stale requests и повторные версии черновика отклоняются до чтения или
изменения состояния. Это изменение неопубликованного экспериментального API:
публичные CLI/JSON-протоколы установленного комплекта не менялись.

## Текущий ввод

`SourceReader` получает тела модулей из manifest и привязывает их к объявленным
дескрипторам, включая формы и команды. Произвольный соседний каталог не становится
модулем конфигурации. Состав и FileId фиксируются при открытии; структурные
изменения требуют reopen. Чтение остаётся адресным, с лимитом байтов и отказом
для символьных ссылок в выбранном пути.

Saved/overlay/close сохраняют исходные UTF-8 байты, BOM и CRLF. Активный черновик
не заменяется фоновым обновлением диска. Close читает текущий диск; удаление,
неверная кодировка, отмена или превышение лимита очищают прежний текст ядра.
Бинарные защищённые тела остаются отдельным состоянием и не принимают текстовый
overlay. Устойчивый listing общих модулей проверяет текущую доступность тела,
а не его доступность в момент открытия.

`metadata` отдаёт тот же текущий YAML-снимок, который использует adapter.
Неподдержанная BSL-проекция не скрывает корректные свойства метаданных; invalid
не возвращает старый успешный снимок. `module_diagnostics` и
`module_completions` работают с короткоживущим handle той же базы. Результат
содержит clock сессии, SHA-256 исходных байтов и отдельные признаки полноты
метаданных и модулей. Принятый текст закреплён в базе: query не перечитывает
изменяемый диск вне ревизии.

## Ограничения

`SessionOptions.max_loaded_module_bytes` ограничивает сумму текущих текстов
BSL; по умолчанию 64 MiB. Замена переиспользует свою прежнюю квоту, неудачный
принятый ввод освобождает её. Отдельный документ имеет жёсткий предел 64 MiB;
запрос может его уменьшить. Эти лимиты не учитывают метаданные, parse trees,
memo Salsa или RSS процесса. Общий бюджет и eviction пока не реализованы.

Cancellation проверяется перед и после запроса ядра. Уже запущенное вычисление
этим флагом пока не прерывается; deadline не задан. YAML-проекция ограничена
подключёнными семействами и главными дескрипторами; готовые байты BSL не означают
полную семантическую проверку проекта. Сервер, LSP/metadata transport и отдельный
checker ещё не подключены. EF-18 остаётся `IN_PROGRESS`.

## Проверки

13 файловых тестов покрывают ленивый ввод, единый clock, stale/duplicate requests,
saved/editor/close и независимый batch, текущую недоступность, лимиты/освобождение
квоты, BOM/CRLF и оба языка диагностики. Completion реального ядра видит реквизит
из текущего YAML и его изменение в черновике; invalid не сохраняет прежний
реквизит. UTF-8 offset проверяется до completion. Отдельный тест отличает
unsupported BSL от пригодного для дерева YAML и проверяет оба признака полноты.

Fmt/check/strict Clippy/test/Rustdoc библиотеки, ядра и адаптера прошли:
13, 1046 и 36 тестов соответственно; у ядра четыре прежних ignored.
Основное приложение прошло полный набор: 884 passed, 14 прежних ignored;
минимальный core — 160 passed, три прежних ignored. Первый полный запуск получил
`Shelf(Locked)` в прежнем тесте переключения ветки; отдельный и повторный полный
запуски прошли без изменения VCS-кода. Причина единичного сбоя не установлена.

Read-only release-пример `project_module` загрузил 2645 YAML-владельцев C1 и один
текстовый общий модуль. Syntax-only диагностика saved/editor/close и отдельной
batch-сессии совпала по значениям и fingerprint: ошибок parser нет. Из 1876
модулей 1875 остались pending; неполное покрытие метаданных также сохранено.
Выход 2 сообщает эту неполноту. Время — 13,87 с; Max RSS — 264,5 MiB, измеренный
для двух перекрывающихся сессий с прочитанными метаданными. Runtime PATH пуст:
XML, платформа, Git и IDE при запросах не используются.

Workspace MCP анализатора недоступен. Дополнительно установленный
`bsl-analyzer-app` 0.2.86 проверил только тот же модуль в профиле `ParseError`:
один файл, ноль diagnostics/failed files, exit 0. Байты совпадают с нативным C1;
семантика метаданных этим ограниченным запуском не проверялась.
[Машинный отчёт](bsl-session-results.json) содержит обезличенные результаты.
Базы и исходники playground не изменены. Клиентская приёмка 1С этим компонентом
не проводилась.
