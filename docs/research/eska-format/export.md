# Обратный экспорт Designer XML, EF-04

Внутренний `project::source_format::export_designer` создаёт полный native снимок
для приёмки формата. Этот writer не вычисляет разрешения поставщика; публичная
сборка подключается к защищённому снимку после EF-05/EF-06.

Reader проверяет `source.json`, YAML каждого объявленного владельца и соответствие
native пути/UUID. По текущим `ChildObjects` повторно проверяются весь состав,
kind/Name, все inline UUID и отсутствие лишних descriptors. Физические файлы вне
manifest и неизвестные дополнительные директории дают отказ, а не пропадают.
Новые структурные операции не входят в первое покрытие.

Все descriptors сериализуются до создания назначения. XML сохраняет native
UUID, generated IDs, смысловой порядок, дополнительные attributes, точные строки
и локализованные значения. Empty, nil и отсутствие не объединяются. Состояние
`text` требует непустую строку: XML не сохраняет отдельный пустой text node;
для пустого значения используется `empty`. YAML/schema проверяют это заранее.

Непрозрачные фрагменты сохраняют внутренние XML-байты. Если binding ранее
наследовался от немоделируемой оболочки `Properties`/`ChildObjects`, он добавляется
на корень фрагмента, включая `xmlns=""`. QName-значения получают прежний контекст.
Дублирующиеся own declarations не создаются. BSL, формы, бинарные ресурсы,
служебные и необъявленные файлы копируются побайтово. Empty directories
восстанавливаются из native manifest.

Допустимые лексические отличия metadata XML: каноническая UTF-8 declaration,
отступы/переносы между native узлами, форма empty tag, эквивалентное XML escaping,
расположение namespace declarations и порядок дополнительных attributes.
BOM/EOL генерации задаются наблюдённым XML-профилем; переносы внутри значений
не заменяются глобально. Изменение значения, identity, порядка и QName-смысла
не считается оформлением. Generated XML проходит ограниченный envelope и
XML-parser check до записи.

Результат не содержит служебного export marker внутри XML-дерева. Сначала
строится полный ожидаемый список paths/lengths/SHA-256/directories. Для нового
назначения весь снимок записывается и перепроверяется вместе с исходниками.
Для существующего назначения допускается только полное совпадение: операция
ничего не записывает и сохраняет mtime. Отличающийся каталог отклоняется без
изменений. Обновляемые поколения и последняя успешная сборка относятся к EF-06.
Удаление собственных производных результатов не влияет на повторный экспорт;
отдельный cache writer не требуется.

Fixtures проверяют полный файловый цикл и повторный импорт, ordered references,
вложенные части, nil/empty, default namespace reset, opaque bytes, ресурсы,
mtime, сохранность отличающегося назначения и отказ при незаявленных файлах.

Реальная C1: все 8 778 native файлов восстановлены; полные модели всех 3 595
активных descriptors совпали с оригиналом без различий. Это более строгая
проверка, чем сравнение одной семантической проекции: opaque XML и namespace
tables также вошли в сравнение. Все остальные файлы совпали побайтово.
Повторный экспорт сохранил mtime всех 8 778 файлов.
Opt-in тест `project::source_format::real_playground_export` принимает
`ESKA_TEST_ROOT`, `ESKA_FORMAT_INPUT`, `ESKA_FORMAT_ORIGINAL`,
`ESKA_FORMAT_OUTPUT`; все пути должны находиться в соседнем playground.
Native CF и повторная выгрузка платформой пока не проверены.
