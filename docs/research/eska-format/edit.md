# Точечные правки YAML: EF-07

Внутреннее ядро `prepare_property_edit` готовит изменение одного существующего
типизированного свойства. `SourceEditPlan` предоставляет относительный путь,
проверенный текст и признак отсутствия изменений; `publish` отдельно сохраняет
результат. Saved CLI ещё не подключён. [IDE-сервер](analyzer-property-plans.md)
уже возвращает versioned plans для открытого YAML; он не публикует файлы.
`prepare_property_edit_text`/`SourcePropertyEdit` используют тот же editor над
caller-owned text с проверкой текущей версии/hash в общей сессии. Preview
не предоставляет publish; saved writer и его повторный preflight сохраняются.

[Editor управляемых форм EF-12](managed-form-edit.md) использует тот же saved
writer с операцией `Resource` по принятому metadata UUID. Его отдельные
`FormEdit`/`FormEditPreview` адресуют existing properties/layout в едином form.yaml.
Прежние metadata-property API и IDE protocol сохраняют свой контракт.

Владелец, путь native descriptor и UUID берутся из независимо закреплённой
принятой базы. Рабочий документ должен сохранить состав частей и ancestry
выбранного объекта: UUID, вид и `Name`. Рабочий YAML не меняет права.
Разрешения проверяются для конкретной операции и части, поэтому редактируемый
реквизит внутри объекта с запретом поставщика остаётся редактируемым.
Дополнительная заморозка ESKA распространяется на вложенные части.

Редактор находит значение через CST `yaml-edit 0.3.2` и заменяет только его
поддерево. Весь документ не сериализуется повторно. Незатронутые байты сохраняются;
кавычки выбранного scalar сохраняются, если ими можно выразить новое значение.
После замены строгий reader проверяет весь документ и сравнивает модель с
ожидаемой единственной правкой. Потеря комментария или изменение другого значения
вызывает отказ до записи. При одинаковом значении сохраняется исходное написание,
файл не перезаписывается и его время изменения остаётся прежним.

Поддержаны замена текста, [boolean/integer/enum](typed-scalars.md), переходы
скаляра/`empty`/`nil` в блочной записи и замена
текстов существующих языков `Synonym` без изменения их состава и порядка.
Одинарные/двойные кавычки, plain scalar, проверенные литералы и замена текста
в flow mapping покрыты тестами. Удаление поля `value` сохраняет связанные
комментарии отдельными строками, вместо удаления CST entry вместе с комментариями.

`Name`, создание/удаление свойства, rename/move, перестановка native частей,
изменение состава языков и неподдержанные переходы возвращают явный отказ.
Удаление `value` из flow mapping, смешанные LF/CRLF внутри изменяемого поддерева
и записи, которые библиотека не может изменить без потери комментариев или смысла,
также отклоняются. Остальной документ сохраняет своё исходное оформление.
YAML с BOM запрещён профилем EF-02; редактор не удаляет BOM молча.
Нативная политика BOM/EOL для XML и отдельного BSL от этого не меняется.

Сохранение использует существующий writer XML-редактора: проверку пути и прав,
точное сравнение исходных байтов, временный файл в том же каталоге, `sync_all`
и замену после повторной проверки. Перед сохранением проверяется та же ссылка
на принятую базу и её содержимое. Обнаруженное внешнее изменение, повреждение
базы, read-only или symlink вызывает отказ. Сравнение перед rename не является
OS-level compare-and-swap против постороннего процесса в последнем окне записи.

Три unit-проверки CST и десять integration-проверок покрывают оформление,
no-op, переходы состояний, языки, права, конфликты, BOM, небезопасные пути,
повреждение базы и обратный экспорт. В сценарии одной правки вложенного descriptor
и одного BSL изменяются ровно два ожидаемых native файла. Это файловая проверка;
сборка реальной конфигурации платформой выполняется отдельно в EF-08.
