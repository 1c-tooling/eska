# Локальное расширение ядра BSL

[`tools/bsl-kernel`](../../../tools/bsl-kernel/README.md) хранит отдельный
workspace трёх изменённых библиотек закреплённого bsl-analyzer. Канонический
ввод из [предыдущего proof](canonical-families.md) теперь находится в исходниках
репозитория. Его используют тесты `ide-db`; адаптер ESKA уже зависит от локальной
модели `bsl-metadata`. Project core сохраняет независимость от ядра BSL.
Самостоятельные analyzer/check и общий runtime host ещё не реализованы.

## Что изменено

`CanonicalMetadataInput` хранит значение и source revision в отслеживаемом
входе Salsa. Поддержаны объекты, регистры, общие модули и определяемые типы;
устойчивый FileId связывает slot с главным descriptor. Несовместимые имя/вид,
pending и unavailable не возвращают прежнюю модель и не читают XML. Изменение
значения одного объекта не перестраивает индекс состава и не переисполняет
resolver соседнего объекта. Сохранён прежний XML-путь для незарегистрированных
канонических входов.

В `RegisterPeriodicity`, нативный XML-reader и адаптер добавлены `Quarter`/`Year`.
Сохраняются сериализуемое значение, поле `Период` и таблицы `СрезПервых`/
`СрезПоследних`. В `hir-ty` расширен exhaustive match стандартных ключей фильтра.
Отдельный тест проверяет сериализацию периодичности: существующий serializer
ядра намеренно исключает вычисленные типы полей, поэтому весь `Register` не
выдаётся за обратимый JSON-снимок.

Локальный workspace заменяет только три пакета. Остальные библиотеки и исходная
ветка Salsa закреплены на точных Git-ревизиях; главный Cargo manifest, его lock,
версия приложения и публикация не изменены. Исходные лицензии/NOTICE сохранены.
В [provenance](../../../tools/bsl-kernel/upstream-provenance.json) записаны
контрольные суммы оригиналов до правок. При строгой сборке Rustdoc исправлены
унаследованные ссылки на приватные/неквалифицированные элементы.

## Проверки

[Машинный результат](kernel-integration-results.json) включает отдельные
fmt/check/strict Clippy/test/Rustdoc обоих workspace, release-сборку примера и
полный набор проверок основного приложения. Все gates завершились с exit 0.

- Ядро: 267 тестов `bsl-metadata`, 600 `hir-ty`, 179 `ide-db`; четыре прежних
  теста загрузчика реальных конфигураций остаются ignored.
- Адаптер: 30 unit и шесть файловых тестов; failed/ignored отсутствуют.
- Основное приложение: 353 unit и 529 integration; 14 прежних ручных проверок
  остаются ignored. Минимальный project core: 159 passed, три прежних ignored.

В одном импортированном BSL-fixture удалена табуляция на пустой строке для
`diff --check`; BOM и LF сохранены. MCP workspace недоступен, поэтому установленный
`bsl-analyzer-app 0.2.86` проверил затронутый файл через CLI с загруженными
метаданными. Четыре прежних замечания модельного fixture совпали с оригиналом;
новых диагностик и failed files нет. Общих настроек `bsl-analyzer.toml` здесь нет.
Тесты ядра повторены после этой правки.

Повторное read-only сравнение всех главных дескрипторов регистров C1/C2/C3
выполнено release-примером `project_registers` с пустым PATH. Native reader
использует локальное исправление периодичности; остальные поля сравниваются
точным равенством моделей.

| Корпус | Совпавшие модели | Поля | Неподдержанные | Exit |
|---|---:|---:|---:|---:|
| C1 | 228 | 2 030 | 0 | 0 |
| C2 | 1 464 | 16 606 | 0 | 0 |
| C3 | 1 963 | 23 680 | 0 | 0 |

Эти числа описывают покрытие регистров, а не всего проекта. XML не экспортируется,
платформа, Git и IDE runtime не запускаются; исходники конфигураций не меняются.
Результаты прежнего [audit](register-adapter-results.json) сохранены отдельно.
Время нового примера нельзя сопоставлять с прежней dev-сборкой как ускорение IDE.

## Оставшиеся границы EF-18

Нет полного преобразования всех семейств и предопределённых ресурсов. У
[адаптера объектов](object-adapter.md) по-прежнему один явно неподдержанный
`TypeSet=cfg:AnyRef` в C1. Отсутствуют общий runtime host с жизненным циклом BSL,
структурными изменениями проекта, согласованной полнотой диагностики, общими
бюджетами/отменой, сервером IDE и пакетным checker. Контроллер saved/overlay,
адаптер и входы Salsa проверены как библиотеки; полный цикл анализа конфигурации
и подключение Explorer не приняты. Статус EF-18 остаётся `IN_PROGRESS`.
