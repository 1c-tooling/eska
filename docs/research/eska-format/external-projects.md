# Приёмка внешних проектов ESKA — EF-14

Профили EPF/ERF приняты для Designer XML 2.20 на 1С 8.3.27.2325,
Linux/Distrobox. [Модель внешних корней](external-roots.md), адаптер версии T84
и protected build прошли собственные независимые циклы. Вместе с
[приёмкой CFE](extensions.md) это завершает EF-14.
[Машинный результат](external-project-results.json) содержит проверки и ограничения.

## Независимые сборки

Нативный контроль создавался из исходного Designer XML, без экспорта из ESKA.
В обоих проектах явно изменены комментарий корня и номер версии. В ERF условие
СКД изменено с `Код >= "02"` на `Код >= "03"`; в ESKA редактировался отдельный
`.sdbl`. Артефакты собраны `eska-build` и повторно выгружены `eska new --from`
в новые каталоги. Одинаковое имя артефакта исключает различие физических aliases.

| Профиль | Содержимое | Версия | Повторная выгрузка |
|---|---|---|---|
| EPF | Настоящая обработка из playground, две формы, три модуля | `1.0.1` | Все 8 файлов совпали побайтно |
| ERF | Непустая СКД и экспортный модуль | `1.3.1` | Все 4 файла совпали побайтно |
| ERF, исходно без ObjectModule | Та же непустая СКД, явное создание модуля | `01.02.004.0001` | Все 4 файла совпали побайтно |

Отчёт использует настоящую выгруженную схему СКД с выборкой из справочника.
Его отдельный ExternalReport root собран и выгружен платформой; исходное физическое
имя с Unicode и точкой отличается от metadata Name. Это подтверждает сохранение
identity и native bindings на непустом внешнем объекте. Полная интеграция БСП
этим примером не проверена.

Обработка зависит от CommonPicture основной конфигурации. Сборка исходного
native контроля без контекста отказала на чтении формы. Обе успешные сборки
использовали явный `--base-configuration` с исходным CF из playground. Для ERF
передан отдельный CF с нужными метаданными. Эти исходные базы не изменялись.
Manifest каждой сборки подтвердил SHA-256 артефакта и номер из `Версия()`.
Карта исходников и исходный pin ESKA сохранились при миграции/bump.

## Выполнение в клиенте

В собственной ИБ подготовлены строки `01`, `02`, `03`. Скомпилированные ERF
созданы через `ВнешниеОтчеты.Создать`; их сохранённые схемы выполнены штатными
компоновщиком макета, процессором СКД и выводом в коллекцию значений.
Все четыре экземпляра из независимых пар вернули только `03`.

Экспортная `Версия()` вернула `1.3.1` для пары с готовым модулем и
`01.02.004.0001` для пары с явно созданным модулем. В первой паре также выполнена
`СведенияОВнешнейОбработке()`: номер регистрации совпал с экспортной функцией.

Отдельный EPF проверил вставку функции до инициализации, включая альтернативную
ветку препроцессора. В клиенте функция и регистрация вернули `1.2.3`, а значение
переменной подтвердило выполненную инициализацию. Код инициализации не удалялся
и не перемещался. Собственная ИБ загружена/обновлена через установленный `ibcmd`:
отдельная операция apply пока отсутствует в ESKA.

## Защита и статические проверки

Для настоящих EPF/ERF отдельно принята база с freeze корня. На обоих языках bump
отказал с `source_edit_frozen`, строгая сборка — с `source_changes_excluded` до
поиска runner. С `--allow-exclusions` платформа упаковала принятый модуль;
повторная выгрузка подтвердила его bytes и версию. Рабочая правка сохранилась.
Core/CLI тесты также проверяют optional slot, stale preview, появление файла
после preview, потерю обязательного модуля, неверный pin и неизменность карт.
Чтение и migration preview трёх проектов вручную проверены RU/EN: JSON совпал.

Workspace MCP недоступен. Использован `bsl-analyzer-app` 0.3.2 с адресной проверкой
изменённых файлов; каждый результат завершён, `failed_files = 0`. Нативные API
сверены через reference MCP. В настоящем модуле обработки сохранились исходные
диагностики, включая два Critical и отсутствие полного контекста основной базы.
После исправления места вставки Blocker не добавляется; новая рекомендация —
`CodeOutOfRegion` уровня Hint. Это не полная семантическая приёмка обработки.

Все 18 Rust gates успешны: обязательные fmt/check/strict Clippy/test, all-features
tests, Rustdoc, minimal core, соответствующие проверки SDK и BSL adapter.

Анализ дополнительных профилей остаётся EF-18; общий new/init и повторный импорт
в существующий проект — EF-20/EF-25. Поведение всей обработки и применимость CFE
в клиенте, Windows/macOS и весь MVP этой приёмкой не подтверждены.
