# Импорт Designer XML, EF-03

Реализован внутренний `project::source_format::import_designer`. Он читает обычную
конфигурацию XML 2.20 и создаёт новый каталог. Команда публичного CLI появится
после защищённого экспорта; существующий `eska.toml` пока принимает Designer XML.

`configuration.yaml` содержит корневой descriptor. `<Collection>/<Name>/object.yaml`
содержит основной descriptor и `nested` — отдельно хранившиеся native описания
форм, шаблонов, команд и вложенных подсистем. Их native пути заданы явно.
Реквизиты, табличные части и прочие inline части остаются в основном descriptor.
[Схема владельца](object-source.schema.json) использует
[схему descriptor](descriptor.schema.json), без второй схемы метаданных.

Состав берётся из `ChildObjects`, начиная с `Configuration.xml`. Файл должен
существовать, иметь объявленные kind и `Name`; native UUID проверяется среди всех
активных основных и inline объектов. Необъявленные XML не разбираются как активные
метаданные. Они сохраняются побайтово вместе с BSL, ресурсами и служебными файлами,
на прежних относительных путях.

`source.json` фиксирует версии схемы/правил и профиль, исходную ревизию,
все native директории и файлы. Для файла сохраняются путь, длина и SHA-256;
`role.kind = descriptor` указывает YAML владельца и native UUID, `preserved`
означает восстановление из отдельного файла. Порядок состава определяется YAML,
а не порядком этого файлового списка. `input_revision` относится к исходному
XML-снимку, не к последующим рабочим правкам. Индекс IDE остаётся производным.

Все проверки состава выполняются до создания результата. Каталог назначения
должен отсутствовать и находиться вне входного дерева. Символические ссылки,
специальные/non-UTF-8 пути, traversal, непереносимые имена и коллизии регистра
отклоняются, в том числе между созданным YAML и ресурсами. Полный входной снимок
перепроверяется после копирования; `source.json` записывается последним.
Обычная ошибка записи удаляет только новый каталог. Прерывание процесса может
оставить неполный каталог без ready manifest; обновление существующего каталога
не реализовано.

Typed-набор остаётся ограниченным `Name`, `Comment`, `Version`, `Synonym`.
Прочие свойства и `InternalInfo` сохраняются исходными XML-фрагментами с контекстом
QName, включая сброс default namespace. Комментарии внутри modeled секций
сохраняются. PI, значимый mixed text, дополнительные attributes секций и
немоделируемое содержимое envelope отклоняются. Вложенная ссылка внутри inline
части требует отдельного правила расположения и сейчас отклоняется.
Текстовый документ ограничен 64 MiB; YAML сверх этого лимита не создаётся.
BSL и двоичные ресурсы копируются потоково без этого ограничения.

Проверки на обезличенном корпусе: повторяемость, полный файловый состав,
владение nested descriptors, BOM/CRLF BSL, точные значения и UUID, namespace reset,
ошибки профиля/декларации, missing descriptor, path/UUID/case collisions, symlink,
сохранность существующего назначения и входа.

На реальной C1 учтены 8 778 файлов и 368 712 972 исходных байта. Преобразованы
3 595 активных descriptors в 2 645 YAML владельцев. Все исходные SHA-256 совпали
с инвентаризацией EF-01. Повторный импорт и чтение всех созданных YAML выполняются
отдельным opt-in тестом `project::source_format::real_playground_import` с
`ESKA_TEST_ROOT`, `ESKA_FORMAT_INPUT`, `ESKA_FORMAT_OUTPUT`: input и новый output
должны находиться в соседнем playground.

Первый результат занимает 403 476 716 байт: на 9,43% больше XML-исходников,
включая manifest и отдельные неизменённые ресурсы. Это предварительное измерение
debug-импорта, без accepted baseline, XML export, кешей и Git. Оптимизация и
решение о полезности формата принимаются по полной матрице EF-09.
Обратная выгрузка и native сборка этим этапом не подтверждаются.
