# Подписи платформы 1С

Каталог содержит русские и английские подписи свойств Designer XML для профилей
**8.3.27** и **8.5.1**. Подписи в IDE сопровождают исходные XML-имена; ключи,
значения, порядок, namespace и диапазоны исходника сохраняются.

## Ресурсы

- `locales/{ru-RU,en-US}/main.ftl` — интерфейс CLI, сообщения и диагностика ESKA.
- `locales/{ru-RU,en-US}/platform-8.3.27.ftl` — базовый словарь: 416 подписей
  свойств/вложенных полей и 81 ранее существовавшая подпись дерева.
- `locales/{ru-RU,en-US}/platform-8.5.1.ftl` — 16 дополнительных подписей.
- [platform-catalog.tsv](../locales/platform-catalog.tsv) — 432 идентичности
  подписей: Fluent key, XML namespace, имя, контекст владельца, версия каталога.
- [platform-coverage.tsv](../locales/platform-coverage.tsv) — соответствие
  свойств модели экспорта словарю: 2 639 вхождений, 328 разных XML-имён.
- [platform-sources.json](../locales/platform-sources.json) — версии и SHA-256
  исходных пакетов EDT. Сами пакеты в репозитории не хранятся.

Переводы хранятся только в FTL. TSV содержит идентификаторы для аудита и тестов.
Ключи `tree-*` сохранены при переносе из `main.ftl`; wire-контракт дерева не меняется.

## Источники и проверка

Использована установленная **1C:EDT (Lite) 2025.2**, активные bundles из
`configuration/org.eclipse.equinox.simpleconfigurator/bundles.info`:

- `metadata` — модель метаданных и наследование;
- `md.export.xml` — порядок экспортируемых свойств, XML-имена и ограничения версий;
- `md.ui`, `md.ui.extension`, `mcore.ui` — пары `FeatureNames*.properties`;
- профили `platform_v8.3.27` и `platform_v8.5.1`.

`MetadataObjectFeatureOrderProvider` задаёт список свойств;
`MetadataFeatureNameProvider` — их XML-имена;
`MetadataObjectWriter.isFeatureSupportedByVersion` — доступность полей.
Подпись выбиралась по конкретному классу, его предкам и классу объявления поля.
Для составных значений дополнительно проверены стандартные реквизиты,
характеристики, ограничения типов и предопределённые элементы.
Имена вложенных элементов могут переопределяться специализированными XML writers;
поэтому прямое преобразование имени поля EMF в PascalCase недостаточно.

У каждого сообщения FTL указан источник. Структурные XML-поля без отдельной
подписи в палитре EDT отмечены `Reviewed Designer XML structural field`.
Исправлены очевидные опечатки (`presentataion`, «Использоват», «Истроия») и
раскрыты сокращения отдельных подписей. Контекстные значения сохранены:
например, `Type` у элемента стиля — «Вид», у реквизита — «Тип»;
`RegisterRecords` у последовательности — «Движения, влияющие на последовательность».

Сопоставление с 3 659 дескрипторами имеющихся тестовых конфигурации и расширения
в playground дало 317 XML-имён с namespace: все получили подписи. Чтение было
без изменения этих проектов. Это проверка покрытия выборки, а не доказательство
полноты всех будущих структур XML. Неизвестный namespace или новое поле выводится
под исходным именем. Enum-значения, пользовательские имена объектов и содержимое
внешних форм/макетов этот словарь не переводит.

Модель EDT содержит также классы за пределами текущего дерева ESKA; наличие
их подписей не добавляет поддержку этих классов. Из исходного списка исключено
неподдерживаемое деревом ESKA свойство устаревшего `Interface.Switchable`, для
которого в EDT нет пары подписей. Остальные три поля без собственной пары
используют существующие общие подписи (`Content`, `IncludeHelpInContents`,
`ChoiceDataGetModeOnInputByString`).

## Семантика версий

`since = 8.3.27` означает «входит в базовый каталог», а не «впервые появилось
в 8.3.27». Для 8.5.1 модель экспорта добавляет 18 полей с учётом контекста;
16 требуют новых ключей: `Color` уже известен у другого типа, а
`AuxiliaryVariantForm` встречается у отчёта и внешнего отчёта.

Оба FTL загружаются вместе. Сейчас в доступных источниках используется общая
палитра подписей EDT для двух профилей: отдельного подтверждённого переименования
одного свойства между этими версиями не установлено. Runtime распознаёт
проверенное объединение имён и не угадывает версию платформы по `version` XML
или по режиму совместимости. Это позволяет показывать подписи и при незаданной
версии сборки проекта.

Для следующей версии сначала извлекается и сравнивается её профиль. Новые поля
добавляются в отдельный FTL; изменившееся значение существующей подписи потребует
явного выбора версии в presentation layer. Произвольные версии `8.3.27+`
автоматически поддержанными не объявляются. Платформа 8.5.1 не запускалась;
источник её словаря — установленный профиль EDT.

## Повторное извлечение

[extract_edt.py](../tools/platform-catalog/extract_edt.py) и
[Inspect.java](../tools/platform-catalog/Inspect.java) — только инструменты
исследования установленного EDT. Для сборки и работы ESKA Java, EDT и платформа
1С не нужны. Внешние зависимости приложения не добавлены.

```sh
python3 tools/platform-catalog/extract_edt.py \
  --edt "$EDT_INSTALLATION" \
  --java "$EDT_JAVA" \
  --container 1c-ubuntu-env \
  --output ../eska-playground/platform-catalog-review
```

Переменные указывают на установку EDT и Java внутри контейнера. Каталог вывода
должен быть новым; существующие результаты не перезаписываются. Без Distrobox
параметр `--container` опускается. Проверенный инструмент рассчитан на Linux,
Java 25 и указанные в манифесте пакеты EDT.

Инструмент извлекает JSON модели, оригинальные ресурсы подписей и контрольные
суммы. У поля `property` отмечено включение в список свойств экспортера;
прочие поля — кандидаты для проверки вложенных значений. Он не перегенерирует
проверенный FTL автоматически: изменения XML writers и контекстных подписей
нужно сверять перед обновлением словаря. Новые пары добавляются в обе локали,
а их идентичности — в TSV. Тесты проверяют равенство ключей локалей, загрузку
Fluent без конфликтов, разрешение каталога и покрытия, namespace и контекст.
