# Проверка лицензий зависимостей

Дата: 2026-09-07. Снимок: `eska 0.5.0`, commit `5da6c35`, текущий `Cargo.lock`.

SHA-256 Cargo.lock: `e49cd9a5a2cca9d3cff679fabfeb584340d449522d61fd84a425a4946d444177`.

## Вывод

По проверенным декларациям и текстам лицензий **оснований менять Apache-2.0
для собственного кода `eska` не обнаружено**. `Cargo.toml` и корневой `LICENSE`
согласованы. При этом Apache-2.0 проекта не заменяет лицензии включённых библиотек.

Есть две зависимости под MPL-2.0: `option-ext 0.2.0` и `uluru 3.1.0`.
Их можно объединять с кодом Apache-2.0 в одном исполняемом файле: Mozilla прямо
описывает такой случай в [MPL FAQ, Q8, Q11 и Q13](https://www.mozilla.org/en-US/MPL/2.0/FAQ/).
При распространении бинарника нужно сообщать, где доступны исходники этих
компонентов под MPL, включая внесённые в них изменения, если они есть.
Основание: [MPL-2.0, разделы 3.1–3.3](https://www.mozilla.org/en-US/MPL/2.0/).

**Совместимость лицензий подтверждена в указанных границах; полнота оформления
произвольной бинарной поставки не подтверждена.** В репозитории на момент проверки
нет комплекта текстов лицензий и уведомлений для всех включаемых third-party
компонентов. Этот отчёт не заменяет такой комплект. Перед распространением готовых
бинарников его нужно подготовить для фактической сборки.

## Что проверено

- `Cargo.toml`, `Cargo.lock`, корневой `LICENSE` и результат
  `cargo metadata --locked --offline --format-version 1`.
- Все 275 внешних пакетов разрешённого графа: 11 прямых и 264 транзитивных,
  включая зависимости сборки и платформенные варианты. У всех заполнено `license`.
  Это не означает, что все 275 пакетов попадают в каждый исполняемый файл.
- Цепочки MPL-зависимостей через `cargo tree -i`, их локальные файлы лицензий.
- Особые декларации и тексты у `aws-lc-sys`, `ring`, `encoding_rs`,
  `curl-sys` с вложенным `curl/COPYING`, `libz-sys` с `src/zlib/LICENSE`.
- Условия Apache-2.0, MPL-2.0, Unicode-3.0, curl и CDLA-Permissive-2.0
  по источникам правообладателей или SPDX.

Это проверка закреплённых версий, а не последних версий crates.io. Полный аудит
каждого исходного файла 275 пакетов, системных библиотек и готовых релизных
архивов не выполнялся. Состав нативных компонентов зависит от ОС, features и
настроек сборки; например, `curl-sys` может выбрать системную libcurl.

обоих компонентов сохраняются. Нельзя свести составную лицензию к первому слову.

## Что включать при распространении бинарника

1. Копию [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)
   для `eska`; для зависимостей — тексты выбранных лицензий, обязательные
   copyright notices и применимые NOTICE. Требования Apache описаны в разделе 4.
2. Уведомление об MPL-компонентах и способ получить их точные исходники под MPL.
   Исходные пакеты соответствуют записям `option-ext 0.2.0` и `uluru 3.1.0`
   в Cargo.lock; доступны из registry crates.io через `cargo vendor --locked`.
   Изменённые MPL-файлы также должны быть доступны получателям.
3. Уведомления нативных компонентов, фактически вошедших в бинарник.
   Одного поля `license` Rust-обёртки для этого недостаточно. Например,
   [libcurl требует сохранить copyright и permission notice](https://curl.se/docs/copyright.html).
4. Для включённых Unicode-данных и данных корневых сертификатов — соответствующие
   тексты условий: [Unicode-3.0](https://spdx.org/licenses/Unicode-3.0.html) и
   [CDLA-Permissive-2.0](https://cdla.dev/permissive-2-0/).

Установка зависимостей пользователем из registry и передача заранее собранного
исполняемого файла — разные сценарии распространения. Наличие Cargo.lock полезно
для воспроизводимости, но само по себе не заменяет notices в бинарной поставке.
Лицензирование внешней платформы 1С этим анализом не покрывается: она не входит
в Cargo-граф и устанавливается отдельно.

## Повторение проверки

```bash
cargo metadata --locked --offline --format-version 1
cargo tree --locked --offline --target all
cargo tree --locked --offline -i option-ext
cargo tree --locked --offline -i uluru
```

Если зависимости ещё не загружены, сначала выполните `cargo fetch --locked`.
После изменения Cargo.lock, features, нативной сборки или состава поставки
результаты следует обновить.
