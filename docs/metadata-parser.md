# Чтение Designer XML по запросу

`project::metadata_parser::parse` разбирает один UTF-8 descriptor в принадлежащие
модели значения. `load` получает его через manifest-backed `DesignerSource`,
проверяет наличие запрошенного ObjectId и читает только файл владельца.
Несуществующий inline-элемент возвращает `ObjectNotFound`, отсутствующий файл —
`MissingDescriptor`; ошибка XML содержит путь этого descriptor.

`PropertiesMode::Summary` возвращает identity, UUID, синонимы, дочерние IDs и
ссылки `ChildObjects`. `All` дополнительно возвращает свойства с namespace URI,
атрибутами-qualifiers, текстом или упорядоченными вложенными полями. Повторённые
поля сохраняются. Неизвестные имена свойств не отбрасываются. Скалярные значения
не преобразуются автоматически в числа/булевы значения; QName внутри текста
остаётся текстом, а не разрешённой ссылкой на тип.

Ссылка на форму/команду/макет или верхнеуровневый объект не вызывает чтение его
XML. Для конфигурации/расширения верхнеуровневый ObjectId сохраняет прежний вид
без префикса конфигурации; `MetadataReference.owner` связывает его с корнем.
Для внешнего отчёта/обработки дочерние IDs включают корень. Отдельный вложенный
descriptor разбирается с parent, который предоставляет resolver.

Ошибочный inline-объект, неизвестный тип/namespace и повторённый ObjectId дают
локальную диагностику с диапазоном XML; корректные соседи остаются доступны.
Смешанное содержимое свойства и некорректная структура синонима помечаются
`Unsupported`. Summary проверяет структуру объектов и синонимы; полная проверка
форм значений остальных свойств выполняется только в All. Это не проверка
семантики или допустимости свойств платформой 1С.

Диапазоны — byte offsets исходного UTF-8, включая BOM и исходные CRLF. Их можно
применять только к той же версии файла. Преобразование в UTF-16 позиции и
контроль версии файла относятся к source API. В возвращённой модели нет XML DOM
и копии всего исходного текста. Payload форм/макетов и BSL остаются отдельными
sources; parser их не читает.

Пределы: 64 MiB на файл, миллион XML-узлов, **64 уровня элементов**.
Потоковый предварительный проход `quick-xml 0.42.0` ограничивает вложенность
до рекурсивного tokenizer `roxmltree 0.21.1`; оба работают с одним входным
буфером. Это уточнение [решения T63](xml-parser-decision.md): проверка глубины
после DOM оказалась слишком поздней для debug-сборки со стандартным стеком
тестового потока. Граница 64 и превышение проверены без увеличения стека.
DTD не разрешён. Новые ограничения применяются к открытию DesignerSource и
новому parser; старый CLI object model не переписан этой задачей.

Проверки T64: реальные формы источников четырёх типов на небольших fixtures,
тождество IDs прежней модели, inline source lookup, локальная ошибка дочернего
файла, namespace/BOM/CRLF, свойства и диапазоны, неизвестные фрагменты и лимиты.
Общая identity-оболочка проверена для всех 65 типов; полнота специальных свойств
и допустимых коллекций каждого типа этим не утверждается — схемы входят в T65.

Ручная проверка большого стенда 2026-09-17: открытие корня 109 мс, общий проход
с разбором 12 выбранных объектов 181 мс (Linux, debug, один запуск). Это smoke,
не p95 и не измерение UI. Пользовательские XML/BSL не изменялись, платформа и
сборка конфигурации не запускались. Повторяемые замеры модели/индекса — T68.
