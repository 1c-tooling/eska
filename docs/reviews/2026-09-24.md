# Ревью eska: 2026-09-24

Исходное состояние: `a06e7ef`, ветка `feat/ide`, чистая рабочая копия.
Обзор структуры охватывает 147 Rust-файлов в `src` (40 556 строк) и
16 530 строк автоматических тестов. Глубокая проверка сосредоточена на
сравнении изменений, поисковом индексе, границах слоёв и сохранении контрактов.
Это обзор всех подсистем с адресными исправлениями, а не формальное доказательство
корректности каждой строки или аудит всех сторонних зависимостей.

## Архитектура после рефакторинга

`cli/commands/diff.rs` содержит выбор проекта, сравнения и представления.
Human-группировка, raw-колонки, JSON DTO и диагностика неполного semantic-анализа
находятся в отдельных внутренних модулях. Файл сократился с 1 957 примерно до
460 строк; тесты представлений вынесены отдельно.

`project/semantic.rs` координирует snapshots и генерацию событий. `changes.rs`
владеет нормализацией путей и ownership summary, `model.rs` — событиями и
ошибками, `descriptor.rs` — структурой XML, `routines.rs` — разбором BSL.
Основной файл сократился с 1 539 до 526 строк. Изменение внутренних путей не
потребовало менять потребителей `project::semantic`.

Новых зависимостей, постоянных индексов и runtime-механизмов нет. CLI arguments,
JSON schemas, raw-колонки, порядок групп и locale-independent идентификаторы
сохранены. Исправление XML меняет только результат обнаружения ранее пропущенных
или ложных событий. Пакетная очистка сохраняет набор результатов, поколения,
очистку ошибок и соседние ветви с похожими именами.

## Проверки и ограничения

Базовый прогон вне sandbox: 181 unit + 358 integration passed, пять ignored.
В sandbox шесть тестов падали из-за недоступного локального HTTP и особенностей
видимости Git-каталогов; повтор без этих ограничений прошёл до изменений.

Финальные `cargo fmt --check`, `cargo check`,
`cargo clippy --all-targets --all-features -- -D warnings` и
`RUSTDOCFLAGS='-D warnings' cargo doc --no-deps` прошли.
`ESKA_TEST_ROOT="$(realpath ../eska-playground)" cargo test`: **183 unit и
360 integration passed**, 0 failed; 1 unit и 5 integration ignored.
Один из ignored-тестов — новый benchmark, запущенный отдельно до/после.
Проверены whitespace diff, JSON измерений, Markdown fences и 185 локальных ссылок
шести затронутых документов.
Проверка cleanup regression повторена пять раз; benchmark выполнен по три раза
до и после оптимизации. В измерение включён только `index_search_step(1)` после
`changed_paths`, а не полный цикл обновления. Все создаваемые fixtures принадлежат
тестам и находятся в соседнем `eska-playground`.

Производительность массового редактирования без удаления ветвей отдельно не
измерялась: при переиндексации уже известного descriptor остаётся
`records.retain` по всему поисковому индексу. Также semantic revision comparison
повторно получает tree diff для каждого выбранного проекта. Это кандидаты на
следующие измерения, а не подтверждённые этим замером задержки. Постоянные
дополнительные индексы ради этих предположений не добавлены.

Windows/macOS, Extension Host и настоящий Конфигуратор в этом ревью не запускались.
Прежние открытые пункты приёмки T55/T57/T81 и поддержки остаются открытыми.
Крупные build/tool и object_model модули сохраняют свои текущие границы; размер
файла сам по себе не использован как основание для дополнительной перестройки.

Разделение по файлам опирается на обычные модули и ограниченную видимость,
описанные в [актуальной Rust Book](https://doc.rust-lang.org/stable/book/ch07-05-separating-modules-into-different-files.html).
Значение `maintenance.auto` сверено с [документацией Git](https://git-scm.com/docs/git-config#Documentation/git-config.txt-maintenanceauto).
