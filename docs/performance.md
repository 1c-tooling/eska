# Замеры рефакторинга diff и semantic analysis

Замеры выполнены 2026-09-08 на Linux, Rust 1.98.1. Исходное состояние —
`aa8e956`. Это локальные синтетические проверки, а не SLA или оценка ускорения
на произвольной конфигурации.

## Чтение Git-снимков

Сравнение исходного CLI и `94de352`, обе сборки `cargo build` (debug).
В собственном временном каталоге соседнего `eska-playground` создана конфигурация
с 1000 общих модулей: по одному XML-дескриптору и BSL-файлу на модуль.
После начального commit изменены Comment каждого дескриптора и тело процедуры
каждого модуля. Выполнены `diff --format json` и
`diff --semantic --format json`: один прогрев, пять измерений, порядок бинарников
чередовался. В таблице медианы wall-clock времени всей команды.

| Команда | До | После | Снижение времени |
|---|---:|---:|---:|
| `diff --format json` | 1,2769 с | 1,1667 с | 8,6% |
| `diff --semantic --format json` | 3,8831 с | 3,5909 с | 7,5% |

JSON совпал побайтово между реализациями и между `ru-RU` / `en-US`.

## Выделения памяти в semantic analysis

Для сравнения использован отдельный Rust harness, собранный с `rustc -O`:
он вызывает исходные и новые функции с `std::hint::black_box`, сравнивает
результаты и измеряет пять серий. XML разобран заранее, поэтому время parser
roxmltree не входит в результат.

| Операция и вход | До, медиана серии | После | Снижение времени |
|---|---:|---:|---:|
| XML-сигнатура: 80 уровней, 1000 элементов; 200 вызовов | 31,65 мс | 12,37 мс | 60,9% |
| BSL: 1000 процедур по 30 строк тела, CRLF; 50 вызовов | 86,38 мс | 70,23 мс | 18,7% |

XML теперь дописывается в один буфер. BSL parser читает строки итератором,
без копии всего файла для замены CRLF и без промежуточных массивов строк.
Объём выделенной памяти отдельно не измерялся.

Итоговый CLI дополнительно сравнен с исходным на 100 изменённых модулях:
human/raw/JSON, RU/EN, обычный и semantic diff совпали побайтово; при
перенаправлении с `NO_COLOR` escape-последовательностей нет.

Полное обнаружение ObjectModel в workspace semantic diff сохранено.
Эти замеры не оценивают production release-сборку, полный обход реальной
конфигурации или стоимость вызовов платформы 1С.
